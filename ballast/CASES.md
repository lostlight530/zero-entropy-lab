# 控制案例

## B-01 重复执行

- 输入: 同一任务、初始状态与允许范围.
- 变化: 连续执行两次.
- 检查: 第二次是否保持等价结果且无重复副作用.

## B-02 中断恢复

- 输入: 具有读取、处理、验证和写入阶段的任务.
- 变化: 在不同阶段模拟中断.
- 检查: 恢复位置、已有状态和最终产物是否正确.

## B-03 过期基线

- 输入: 已读取的基线与随后变化的真实状态.
- 变化: 在写入前更新基线.
- 检查: 是否重新同步、重新计算或安全停止.

## B-04 假成功

- 输入: 返回成功但缺少关键产物的受控命令.
- 变化: 分别启用和移除后置验证.
- 检查: 是否阻止不完整结果被报告为成功.

## B-05 临时污染

- 输入: 旧缓存、未完成文件和重复记录.
- 变化: 在干净与污染环境中执行同一任务.
- 检查: 是否识别污染并保持最终结果一致.

## B-06 自洽但过期

- 输入: 从旧事实源生成且内部摘要自洽的多文件结果.
- 变化: 在读取与发布之间推进事实源代际, 再从中断点恢复.
- 检查: 内部校验与绑定当前事实源的校验是否产生不同判断, 重新同步后的重放是否零写入.

## B-07 结果未知重试

- 输入: 非幂等操作、稳定请求键与可查询收据.
- 变化: 副作用已提交但确认丢失, 再分别盲重试、仅按键去重和绑定意图恢复.
- 检查: 是否重复副作用, 同输入是否零写入, 同键不同意图是否拒绝.
- 强反例: 只有一个副作用且命中请求键, 但返回结果对应旧意图.

## B-08 共享依赖共同失效

- 输入: 多个执行者共享同一外部依赖, 任务具有可保存检查点与独立后置条件.
- 变化: 连续注入两次共同不可用, 第一次聚合恢复后保留一个上下文不可用.
- 检查: 独立重试是否放大调用, 聚合状态是否误导完成判断, 复发时已验证任务是否零调用重放.
- 强反例: 聚合状态显示恢复且产物数量齐全, 但一个执行上下文产物为空.

## B-09 半开探针与故障域

- 输入: 两个执行上下文共享依赖, 但恢复时间不同.
- 变化: 全局熔断器用一个成功探针关闭, 再与按上下文保持独立状态的路径比较.
- 检查: 半开调用数量、未恢复上下文状态、占位产物、最终语义与完成后重放.
- 强反例: 全局状态关闭且产物键数量齐全, 但未被探测的上下文仍返回空产物.

## B-10 过期租约提交

- 输入: 两个执行者、可过期探针租约、单调所有权令牌与条件写入端.
- 变化: 第一持有者在探针后中断, 租约过期后第二持有者接管并提交, 第一持有者随后恢复.
- 检查: 并发竞争是否只有一个获胜者, 旧令牌提交是否被副作用接受端拒绝, 当前结果重放是否零写入.
- 强反例: 第一持有者曾合法获得租约且探针成功, 但恢复提交时当前所有者已经变化.

## B-11 共享解析共同失效

- 输入: 原始结构化文本、规范化产物、共享默认解析路径与保留原始成员序列的验证路径.
- 变化: 注入重复字段并与唯一字段控制输入比较.
- 检查: 生产器和共享验证器是否同时丢失冲突证据, 原始输入验证器是否拒绝歧义, 控制结果重放是否零写入.
- 强反例: 规范化产物结构与语义字段齐全且共享验证通过, 但原始输入包含互相冲突的同名字段.

## B-12 去重保留窗口过期

- 输入: 已提交但确认丢失的非幂等操作、有限保留的请求键、持久关联标识与当前意图.
- 变化: 在去重记录过期后迟到恢复, 比较直接重放、只按关联标识跳过和绑定原请求及意图的权威结果核对.
- 检查: 过期请求键是否再次产生副作用, 同标识不同意图是否被拒绝, 已确认当前结果的重放是否零写入.
- 强反例: 查询得到一个关联标识相同的资源并跳过重试, 但该资源由另一请求和不同意图创建.

## B-13 副作用与去重收据双写

- 输入: 非幂等副作用、稳定请求标识、当前意图与持久去重收据.
- 变化: 分别在副作用后收据前、收据后副作用前和单一原子状态提交前注入中断.
- 检查: 恢复是否重复创建或错误跳过, 最终资源与收据是否一一对应, 同输入重放是否零写入.
- 强反例: 收据格式正确且意图匹配, 恢复器返回缓存成功, 但权威资源不存在.

## B-14 超时重试后的迟到提交

- 输入: 同一任务的旧输入、新事实源代际、客户端截止与可重试执行路径.
- 变化: 第一尝试超时后第二尝试提交当前结果, 再让第一尝试迟到提交, 比较无条件写入、只发取消信号和提交代际围栏.
- 检查: 当前结果是否被旧结果覆盖, 取消是否真正阻止副作用, 旧尝试是否被拒绝, 同输入重放是否零写入.
- 强反例: 客户端已经收到取消信号且第二尝试成功, 但未在提交点核对状态的第一尝试仍覆盖当前结果.

## B-15 条件写入响应丢失后的远端回读

- 输入: 带强校验标识的远端对象、稳定操作意图与可能丢失的写入响应.
- 变化: 比较冲突后盲覆盖、首次写入已生效但响应丢失、首次写入未生效且其他写入已推进状态.
- 检查: 旧前置条件是否阻止覆盖, 回读能否区分已生效与真实冲突, 已确认结果重放是否零写入.
- 强反例: 使用旧校验标识的重试被拒绝, 但远端当前对象已经包含首次请求的完整意图.

## B-16 缓存读取中的写入代际验证

- 输入: 已推进到新代际的权威对象、仍保存旧代际的公开缓存与预期写入意图.
- 变化: 比较普通缓存读取、请求侧绕缓存指令被忽略、绑定代际的权威读取和同载荷不同代际.
- 检查: 验证是否识别读取层级, 是否绑定预期代际与意图, 相同载荷是否掩盖旧状态.
- 强反例: 旧代际与当前代际载荷相同, 内容验证返回成功, 但意图和代际仍指向旧写入.

## B-17 集合变化中的跨页快照完整性

- 输入: 排序集合、页大小、继续位置、可变排序键与读取开始时的身份基线.
- 变化: 第一页后分别插入前置项目、让未读项目跨过游标, 再与绑定初始快照的路径比较.
- 检查: 数量是否掩盖等量重复与遗漏, 普通游标是否遗漏排序键移动项目, 快照重放是否保持身份序列.
- 强反例: 聚合元素数量与基线相同且分页命令全部成功, 但结果含一个重复身份并遗漏另一个身份.

## B-18 批量部分成功与选择性恢复

- 输入: 三个唯一意图、批量传输状态、逐项结果与权威副作用日志.
- 变化: 首次批量调用让 A、C 成功而 B 失败, 比较只看整体状态、整批重试与只重试失败项.
- 检查: 整体成功是否掩盖缺失项, 整批重试是否重复已成功副作用, 选择性恢复与完成后重放是否保持每项恰好一次.
- 强反例: 批量响应为 HTTP 200 且返回条目数与输入相同, 但 B 的单项状态失败且权威日志缺少 B.

## B-19 验证后替换与发布字节绑定

- 输入: 可变候选路径、有效 JSON 字节、预期摘要、必需身份与最终发布路径.
- 变化: 独立验证通过后原子替换候选路径内容, 比较按路径重新打开、摘要绑定拒绝和恢复后原子发布.
- 检查: 验证成功是否对应最终发布字节, 替换状态是否在写入前被拒绝, 恢复与完成后重放是否保持零重复写入.
- 强反例: 初始验证和发布命令都退出 0, 最终文件存在且 JSON 状态为 complete, 但摘要已经变化并缺少必需身份 A.

## B-20 异步接受与终态产物分裂

- 输入: 稳定操作标识、意图摘要、异步状态资源和最终产物.
- 变化: 分别在接受后处理前、Succeeded 写入后产物提交前中断, 再恢复同一操作并重放.
- 检查: 202 和终态是否被误报为完成, 状态与产物是否绑定同一操作和意图, 完成后重放是否零入队零写入.
- 强反例: 状态为 Succeeded 且操作标识和意图摘要正确, 但最终产物不存在.

## B-21 迟到生产入口与代际围栏

- 输入: 已读取的旧 generation、已经推进的当前 generation、稳定操作身份、意图摘要与完成记录.
- 变化: 当前操作生效后让旧任务从中断恢复, 再让旧任务和当前已完成任务分别重新经过生产入口.
- 检查: 旧 generation 是否在提交前被拒绝, 当前完成记录是否仍绑定同一意图与结果代际, 有效完成重放是否零新增写入.
- 强反例: 迟到任务首次和重放都返回 `applied` 且产物可解析, 但覆盖当前值并复制同一副作用.

## B-22 幂等身份与意图错配

- 输入: 已有完成记录的幂等身份、原意图和参数已经变化的新意图.
- 变化: 响应丢失后恢复时错误复用旧身份, 再比较仅身份去重、身份加意图摘要和新身份执行.
- 检查: 同身份不同意图是否显式冲突, 新意图是否真正完成, 新身份完成后的同输入重放是否零新增写入.
- 强反例: 返回 `already_complete` 且新增写入为 0, 但新目标根本没有实现.

## B-23 基准漂移后的目标判定

- 输入: 旧任务读取的 generation、当前较新状态与原任务目标后置条件.
- 变化: 原任务响应未知后由其他操作推进当前状态, 再让迟到任务重放; 另构造较新 generation 已经满足原目标的状态.
- 检查: 旧写权限是否先被关闭, 当前目标是否独立重新判断, 已满足目标是否能够零写入返回完成.
- 强反例: 单纯 generation conflict 会把当前状态已经满足原目标的情况统一误判为失败.

## B-24 后置条件读取竞态

- 输入: 当前目标值、revision 与需要返回的完成声明.
- 变化: 在读取目标与完成判定之间推进 revision, 并与判定返回后才发生合法变化的路径比较.
- 检查: 完成证据是否绑定被验证 revision 与判定时点, 两种事件顺序是否能够独立区分.
- 强反例: 相同最终 revision 与 value 既可能来自判定前漂移, 也可能来自判定后合法变化, 只看最终状态无法判断声明是否有效.

## B-25 所有权交接传播窗口

- 输入: 旧 holder、新 holder、单调 generation、sink 已见最大 generation 与当前权威所有权.
- 变化: 所有权已经交接, 但新 holder 尚未向 sink 发送第一条请求时让旧 generation 迟到提交.
- 检查: sink-local 最大已见 generation 是否遗漏新所有权, 提交边界的权威 holder/generation 是否拒绝旧副作用, 最终值正确时是否仍能发现历史 stale write.
- 强反例: 旧 generation 先被 sink 接受, 新 holder 随后修正最终值, 导致最终状态正确但副作用计数多一次.

## B-26 退避跨越任务有效期

- 输入: `Retry-After`、transport retry deadline、任务 `valid_until` 与稳定 intent.
- 变化: 服务恢复等待时间跨过任务自身有效期, 但仍早于 transport deadline.
- 检查: 每次生产重试前是否重新核对任务有效期, at-most-once 是否只限制重复次数而没有续期任务语义.
- 强反例: 服务已恢复、等待已满足、transport deadline 未到且请求只执行一次, 但任务已经过期, 技术成功仍是语义错误副作用.

## B-27 任务取消与仍有效凭据

- 输入: RUNNING 任务、ACTIVE credential、静态校验、动态 introspection 与任务级授权入口.
- 变化: 先把任务切换为 CANCELLED 而保持 credential ACTIVE, 再单独测试 credential 后续撤销.
- 检查: credential 自身有效时是否仍核对当前任务状态, introspection 是否只证明 token 状态, 已完成 intent 重放是否零新增写入.
- 强反例: introspection 返回 ACTIVE、请求成功且只执行一次, 但 CANCELLED 任务仍产生副作用.

## B-28 批准恢复中的动作与相关状态陈旧化

- 输入: 已批准的具体 action、call identity、相关权威状态投影与无关 metadata.
- 变化: 批准后分别改变 action 参数、相关权威状态和仅无关 metadata, 再让旧批准重新进入原生产入口.
- 检查: 工具级批准是否跨 action 误用, action-bound 批准是否遗漏相关状态变化, state-bound 批准是否只在真实依赖变化时失效, 完成后重放是否零新增写入.
- 强反例: call identity 与 action 字节完全不变, 但相关权威状态已经改变, 仅绑定 action 的旧批准仍产生副作用.

## B-29 迟到恢复中的未知副作用结果

- 输入: 任务 identity、相关状态 generation、completion 记录与可查询的 effect identity.
- 变化: 在 effect 已提交但 completion 尚未持久化时中断, 随后让同一任务重新经过生产入口; 另只改变无关 metadata 作为过度围栏反例.
- 检查: 相关状态变化是否关闭旧执行权限, completion 缺失时是否先核对 effect evidence, unknown-result replay 是否产生第二次副作用, 无关变化是否被整体 revision 误拒绝.
- 强反例: effect 已真实发生但 completion 记录缺失, 仅按任务完成状态恢复会再次执行; 正常 completed replay 却仍表现为零新增写入.

## B-30 恢复接管后的旧副作用未知

- 输入: unknown-outcome 任务、可过期 ownership claim、递增 epoch 与可查询 prior-effect evidence
- 变化: 旧 holder 在 effect 后 completion 前中断, claim 过期后新 holder 合法接管
- 检查: 新 epoch 是否只解决当前所有权, takeover 后是否独立核验旧 effect, completed replay 是否掩盖 crash-window
- 强反例: 新 holder 合法获得 epoch 2 且 current permission 有效, 仍因未查旧 effect 产生第二次副作用

## B-31 receipt 查询错误与缺失折叠

- 输入: 已存在 prior effect 与 receipt、暂时不可用的 authoritative query、可选 stale negative cache
- 变化: 比较 error-as-miss, negative-cache fallback 与显式 hit, miss, unknown 三态
- 检查: query error 是否产生新 effect, 查询恢复后是否从真实 hit 或 miss 继续, safe stop 是否永久遗漏必要操作
- 强反例: prior effect 已存在时 query error 被折叠为 miss 或旧负缓存后产生第二次 effect, 而 no-prior 场景恢复后真实 miss 仍能执行必要 effect

## B-32 滞后读取造成的 receipt 假缺失

- 输入: primary 已提交 receipt、滞后 replica、pre-attempt watermark 与可验证读取 freshness
- 变化: 比较 eventual miss, pre-attempt watermark, global freshness 与覆盖当前提交的读取
- 检查: successful miss 是否足够新鲜, watermark 是否覆盖 attempt 自身提交, global revision 是否因无关更新过度围栏
- 强反例: replica revision 已满足 pre-attempt watermark 但仍早于 receipt commit, miss 后产生第二次 effect

## B-33 receipt 保留期短于恢复窗口

- 输入: 有限 receipt retention、task valid_until、exact action 与 target identity、可查询 remote effect evidence
- 变化: receipt 在合法恢复前过期, 比较直接 replay, horizon-bound retention, broad marker 与 exact identity fallback
- 检查: expired miss 是否被误当 never-executed, retention 是否覆盖合法恢复窗口, fallback 是否保持完整 effect identity
- 强反例: receipt authoritative miss 后直接重试产生第二次 effect, broad task marker 又在无关 action 与 target 历史中产生零写入假完成

## B-34 当前资源删除与历史副作用缺失

- 输入: 已发生 effect、completion 缺失、live resource 删除、delete marker、version history 与独立 receipt
- 变化: 比较 live-only, marker, exact history identity 与 independent receipt, 再清理历史版本
- 检查: current absence 是否被误当 historical absence, marker 是否绑定完整 identity, history pruning 后 miss 是否回到 unknown
- 强反例: live absent 后直接 replay 产生第二次 effect, 同名无关 delete marker 形成假完成, exact history 被清理后 history miss 再次重复

## 扩展规则
新案例必须来自真实失败机制并包含可复验条件. 单纯改写已有问题不构成新案例.
