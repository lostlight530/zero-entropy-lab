## 重复信号

### 1. 当前执行权限与既往副作用证据必须分开

08-11 至 08-14 主要回答“现在还能不能执行”

- 当前 owner 是否仍匹配
- 任务是否仍在业务有效期
- 任务是否仍 RUNNING
- 当前批准是否仍绑定相同 action 与相关权威状态

08-15 至 08-17 进一步回答“上一次未知尝试是否已经产生副作用”

- completion 缺失不能证明 effect 未发生
- receipt 存在不能证明它属于当前 target incarnation
- receipt 格式正确也不能证明 effect 已经真实提交
- effect 已发生但 receipt 缺失时直接重放会重复执行

两个问题不能互相替代

旧 receipt 失配只说明不能据此跳过, 不自动授予再次执行权限

当前执行权限仍有效也不说明此前 effect 一定没有发生

### 2. effect identity 的绑定范围正在变得更具体

08-15 已稳定要求恢复前查询 authoritative effect identity 或等价权威证据

08-16 首次观察到 effect identity 如果只绑定 key 与 action, 在同名目标重建后仍会把历史实体与当前实体混同

08-17 再次说明 identity 正确仍不等于 provenance 正确, receipt 必须与真实 effect 具有可核验对应关系, 能共享事务时优先同一原子可见边界

当前可复用框架可以拆成三层

- action identity: 证明副作用语义没有漂移
- target incarnation identity: 证明副作用属于同一个真实承载实体
- effect provenance: 证明 receipt 与真实 effect 的发生关系可核验

其中 target incarnation 只有 08-16 一个独立窗口, 当前仍是观察边界, 不能提前升级 METHOD 或新建 CASE

### 3. 最终状态与 completed replay 都可能过于乐观

08-11 最终 value 正确仍掩盖一次 stale side effect

08-15 completed replay 安全仍漏掉 effect 已发生但 completion 未持久化的窗口

08-16 同一实体 unknown outcome 能安全恢复, 但同名新实体会触发错误跳过

08-17 三条路径 completed replay 都安全, 但 receipt-first 与 effect-first crash-window 仍分别失败

因此恢复验证至少同时覆盖

- 正常完成后重放
- effect 已发生但 completion 缺失
- receipt 或 effect 单边可见
- 身份复用或实体 reincarnation
- 后续合法写入把最终值修正正确的场景

### 4. 更强围栏不等于更宽围栏

08-14 与 08-15 都给出无关 metadata 变化的强反例

只绑定全局 revision 虽然可以拒绝更多旧状态, 但会把与授权和副作用语义无关的变化也误判为冲突

相关状态投影只有在依赖字段完整时才优于整体 revision

无法证明投影完整时仍应使用更强围栏或安全停止

## 恢复与重放

- 08-11 当前 holder 的已完成意图重新经过提交入口后保持零新增写入
- 08-12 已完成 intent 重放保持零新增写入, 但过期未完成任务必须在入口停止
- 08-13 已完成 intent 重放保持零新增写入, CANCELLED 任务不能依赖 ACTIVE credential 继续执行
- 08-14 state-bound approval 在完成后重放保持零新增写入, action 或相关状态变化则安全停止
- 08-15 projection-effect 在 unknown-result replay 中通过 effect evidence 保持单次写入并恢复 completion
- 08-16 同一 target incarnation 的 unknown outcome 在三条路径都保持单次写入, 但旧 receipt 不能跨新 incarnation 复用
- 08-17 completed replay 在三条路径都保持单次 effect, 但只有 crash-window 注入暴露 ghost receipt 与重复 effect

本周期进一步确认“重放零写入”只有在当前权限、意图、目标实体与 prior effect evidence 同时仍匹配时才是有效完成证据
