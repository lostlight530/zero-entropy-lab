## 重复信号

### 1. 当前执行许可

08-18 证明新 holder 合法接管只回答谁现在可以尝试提交

08-21 的 task expiry 反例进一步说明业务有效期可以独立关闭新的 effect

因此第一问始终是 `现在是否仍允许执行`

### 2. 历史 effect occurrence

08-17 至 08-22 逐步收紧 historical evidence

- provenance 不能被 receipt/effect 双写顺序破坏
- ownership epoch 不能替代 prior-effect 查询
- query error 不能变成 miss
- successful miss 需要足够 freshness
- fresh miss 还需要 retention coverage
- current absence 不能替代 historical occurrence absence

因此第二问是 `此前未知尝试到底发生了什么`

### 3. 当前 completion postcondition

08-23 证明 exact receipt 可以真实证明 effect 曾经发生, 但如果 effect 后续被 compensation 或其他合法状态变化反转, historical occurrence 不再自动等于 current completion

compensation ledger 只有在能够证明覆盖所有会使完成语义失效的 reversal path 时才足够

当完成定义要求 persistent state 当前仍成立时, completion 恢复还需要 current authoritative postcondition

因此第三问是 `当前任务要求的完成条件现在是否仍成立`

### 4. 七日闭环

本周期可以写成三个彼此不可替代的合同

`recovery decision = current execution permission + historical effect evidence + current completion postcondition`

该表达是七日派生模型

其中 prior-effect evidence validity 已达到 METHOD 与 NOTES 门槛

current completion 与 historical occurrence 的进一步分离目前只有 08-23 一个新独立实验, 继续保持观察, 不升级为新 NOTES 发现

## 事实分层

### 已验证事实

- 08-17 至 08-23 七个日期都有主题唯一的每日研究记录
- 08-19 至 08-22 四个实验已经通过不同 failure position 支撑 negative prior-effect evidence 的现有发现
- 08-23 exact receipt 在真实 effect 后提交, 但 compensation 或 ledger 外合法 reversal 后 receipt-only 仍能得到 completed 1 与 current value `clean`
- 08-23 receipt-postcondition 在两类 reversal 后都重新确认 current permission 并恢复目标 current state
- 08-23 completed replay 三条路径都保持历史 effect 1, 因而不能替代 reversal-after-effect crash-window
- 本周期 AI 特殊专题使用 Google、OpenAI 与 Anthropic 官方公开材料, 并与七个日报逐项建立问题映射

### 基于证据的推断

- unknown-outcome recovery 至少需要独立回答 current permission、historical occurrence 与 current completion 三个问题
- prior-effect negative result 的现有 validity contract 继续成立
- 对要求当前状态持续成立的可逆 effect, truthful historical receipt 只证明 occurrence, 不能单独恢复 current completion
- compensation ledger 可以提高 reversal visibility, 但 ledger coverage 无法证明完整时仍需要 current authoritative postcondition
- 模型外 identity、sandbox、egress 与 deterministic gateway 能形成 hard execution boundary, 但不自动替代上述三类应用级恢复证据

### 未验证事项

- 尚未证明三合同模型可以直接外推到任意不可逆副作用、消息投递或第三方 API
- 尚未证明 current authoritative postcondition 在多资源、跨区域或 eventually consistent 系统中能够由一次读取完整表达
- 尚未验证 compensation 与 forward effect 并发交错、重复补偿或嵌套 Saga
- 尚未验证真实 Agent platform 的 durable resume 是否携带可核验 task generation、approval binding 与 effect evidence
- 尚未证明任何单一厂商架构已经完整实现 Ballast 的 recovery contract
