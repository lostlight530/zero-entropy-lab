## 重复信号

### 1. Freshness 与 atomicity 是不同合同

08-24 证明读成功仍可能 stale

08-25 证明即使读在当时正确, commit 前仍可失效

因此 observation freshness 不能替代受保护 decision boundary

### 2. Coherent state 与 complete identity set 是不同合同

08-26 证明固定 A/B 各自读正确仍可能构成从未存在的组合

08-27 至 08-29 进一步证明即使比较边界原子, logical name 或 local revision 也不能跨 incarnation 自动解释为同一个目标

因此 snapshot coherence 不能替代 task-semantic identity binding

### 3. Complete observed set 与 complete current set 是不同合同

08-29 对固定 A/B 的每个 UID+revision 都能形成完整 compare set

08-30 证明当 task semantics 由动态 selector 定义时, C 可以在最后观察后加入集合, 旧 A/B compare 仍全部成功

因此 dynamic selector 的 relevant set 还必须绑定 membership 或 predicate witness

### 4. 更宽 global fence 不是默认最优

08-24、08-25、08-26 与 08-30 都存在无关 global state 推进造成额外等待或 conflict 的反例

稳定方向不是无限扩大 whole-store revision, 而是完整但尽可能相关地表达 task dependency

### 5. 七日稳定链

当前 current completion evidence 可收束为

`task semantics -> current relevant membership and identity set -> coherent snapshot or freshness -> predicate-complete atomic protected completion`

这仍属于既有长期发现 `生产路径成功证据不能替代当前后置条件` 的深化, 不需要复制第四个发现标题

## 恢复与重放

- 08-24 freshness strong paths 在 stale positive 后重新建立 current state
- 08-25 compare-and-complete 在 read 后 reversal 时冲突, recovery effect 前重新确认 permission
- 08-26 pair compare 在 earlier observation 失效时冲突并恢复完整 pair
- 08-27 incarnation-bound path 在 concrete target 被替换时 safe stop / replan
- 08-28 contract-aware compare 在具体实体任务中拒绝 revision reuse, selector-bound 反例按任务语义完成

它们不能替代 stale read、read-to-commit、fractured view、reincarnation、compare under-binding 或 dynamic membership 窗口

## 审计缺口

- 七日新机制仍主要来自标准库受控状态机, 尚无真实 Kubernetes、PostgreSQL、etcd 或跨服务 completion store 端到端故障注入

### 基于证据的推断

- current completion evidence 的 relevant set 对 dynamic selector task 必须覆盖 membership/predicate identity, 不能只覆盖首次观察成员
- atomicity、freshness、snapshot coherence、identity completeness 与 predicate completeness 是相关但不能互相替代的条件
- whole-store global revision 可以作为更保守 fallback, 但 relevant witness 完整时可减少无关 conflict

### 未验证事项

- 完全独立实现的 verifier 是否会发现共享建模假设错误
