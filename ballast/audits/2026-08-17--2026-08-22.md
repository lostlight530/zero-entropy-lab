## 审计方法

1. 逐日复核 unknown-outcome crash-window, production-entry replay, effect 数, event order, 独立 verifier 与强反例
2. 把 current execution permission 与 prior-effect evidence 分开, 不让 ownership, valid_until 或 approval 代替历史 effect 证明
3. 对 prior-effect negative evidence 分别攻击 query classification, read freshness, retention 与 resource lifecycle

5. 检查 broad marker, tombstone, stale cache, replica miss 与 current absence 是否被错误升级为完成或 never-executed
6. 复核当前官方实现语义只用于约束实验模型, 不把外部文档当作 Ballast 受控结果

## 重复信号

### 1. 当前执行权限与历史 effect 证明是两个独立合同

08-18 中新 holder 合法获得新 epoch 仍不能证明旧 holder 没有 effect

08-21 中 valid_until 过期能够阻止新的 effect, 但 valid_until 之前 permission valid 仍不能证明旧 effect 不存在

因此 permission gate 回答 `现在还能不能执行`, prior-effect evidence 回答 `此前是否已经执行`

### 2. negative evidence 需要证明可判定性

08-19 至 08-22 共同说明 miss 或 absent 的文字结果本身不够

要把 negative prior-effect result 提升为可重试依据, 至少需要同时约束

- exact effect identity
- evidence provenance
- read freshness
- retention 或 lifecycle coverage

query error, stale read, expired record 与 pruned history 都可能让 executed history 看起来像 miss

### 3. 更宽或更强的围栏也可能错误

08-20 的 global freshness 因无关 revision 产生额外等待

08-21 的 task marker fallback 与 08-22 的 delete marker 又因为 identity 过宽产生 effect 0, completed 1 的假完成

因此强路径不是无差别扩大 revision 或 marker 范围, 而是把证据精确绑定真实依赖

## 事实分层

### 已验证事实

- 08-19 至 08-22 四个不同日期分别通过 query outage, stale read, retention expiry 与 resource lifecycle 删除制造 negative prior-effect evidence 失真
- 四个实验都有 normal baseline, unknown-outcome crash-window, completed replay 与决定性强反例
- 四个实验均保存 effect count 与 event order, 不只检查最终 completed
- 每个实验 producer 均重复运行三次并得到稳定轨迹摘要
- 每个实验都有独立 Python verifier 与 awk 第二验证实现
- 当前官方存储与幂等文档继续支持一致性, retention 和历史版本生命周期这些实验前提

### 基于证据的推断

- negative prior-effect result 只有在 identity, provenance, freshness 与 retention/lifecycle 同时足够时才有资格支持新的非幂等 effect
- 任何维度无法证明时, `unknown` 比 `never-executed` 更符合当前证据
- current permission 与 prior-effect evidence 必须独立满足, 任一单独成立都不足以授权 unknown-outcome replay
- broad marker 与 whole-store freshness 都可能牺牲正确性或可用性, relevant evidence boundary 更精确

### 未验证事项

- 尚未证明该发现可直接外推到任意支付, 消息, 云对象或第三方工具 API
- 尚未证明真实线性化读取足以同时解决 receipt provenance, effect/receipt atomicity 与 target incarnation
- 尚未验证无限 retention 的成本和隐私约束, 本审计不主张永久保存所有历史
- 尚未验证无法查询历史 effect 的外部系统应采用何种补偿协议
