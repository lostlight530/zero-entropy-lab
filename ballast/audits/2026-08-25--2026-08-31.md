## 重复信号

### 1. Freshness 不能替代 protected boundary

08-25 证明最后一次读取即使在当时正确, 之后 target 仍可变化

因此 completion 依赖的 observation 需要与 protected commit 绑定

### 2. Coherent snapshot 不能替代 identity completeness

08-26 证明多个资源各自读取正确仍可能拼出不存在的共同状态

08-27 至 08-29 证明 logical name 与 local revision 不能跨 incarnation 证明 concrete target identity

### 3. Complete observed set 不能替代 current membership

08-30 证明新成员加入 dynamic selector 后, frozen A/B compare 全部成功仍可假完成

08-31 进一步证明即使最终 count 不变, 甚至 logical name set 不变, member replacement 仍可让旧 membership proof 失效

因此 dynamic membership evidence 必须区分 current member identity, 不能只看数量或名字

### 4. Relevant witness 比 whole-store fence 更精确

08-25、08-26、08-30 与 08-31 都显示 whole-store global revision 会对无关状态变化产生额外 conflict

如果相关依赖能够完整证明, task-scoped identity/freshness witness 可以减少无关 over-fencing

### 5. 月末稳定链

8 月后半段 current completion evidence 收束为

`task semantics -> current relevant membership and identity set -> coherent snapshot or freshness -> predicate-complete atomic protected completion`

08-31 只增强其中 membership and identity set 的证明要求, 不新增语义重复的长期发现

### 已验证事实

- 08-25 至 08-31 连续七个日报均存在独立受控实验与强反例

- 08-31 global revision 对 selector 外 metadata 变化产生额外 conflict, UID-set witness 不冲突
- 08-31 三次 trace SHA-256 一致, Python verifier 3/3 PASS, awk verifier 3/3 PASS, py_compile PASS
- audit 自身不增加实验数量或长期结论数量

### 基于证据的推断

- dynamic selector membership proof 需要 identity-bearing witness, count equality 不足
- logical name set equality 不能跨 delete/recreate 证明历史 membership 等价
- membership identity、per-member freshness 与 protected completion boundary 是相关但不可互相替代的合同
- whole-store revision 是保守 fallback, task-scoped witness 完整时可以减少无关 conflict

### 未验证事项

- 尚未证明真实 collection/predicate witness 能完整覆盖 Ballast 的 membership semantics
- 尚未验证分页、高 churn、跨服务与 multi-region 组合行为
- 尚未证明完全独立 verifier 不会发现共享建模错误
