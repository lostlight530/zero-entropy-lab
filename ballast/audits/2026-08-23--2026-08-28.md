## 重复信号

### 1. Freshness 只解决 observation 时点

08-24 证明 successful read 仍可能来自滞后 replica

08-25 进一步证明即使最后一次普通 read 在读取时完全正确, 读取后到 completion commit 之间仍可以发生 reversal

因此 fresh evidence 与 atomic decision boundary 是两个不同条件

### 2. 多个 fresh read 不自动形成 coherent state

08-26 中 A 与 B 的每个单项读取都是真实 authoritative observation

但读取发生在不同状态转换两侧时, 可以合成一个从未在任何 authoritative 时点存在的 `A satisfied + B satisfied`

普通 double-read 也能被 oscillating state 交错欺骗

因此 multi-resource completion 需要共同 snapshot identity, 或在 completion commit 时原子复核所有 earlier relevant observation

### 3. Revision 只能在它的 identity domain 内解释

08-27 中旧 B1 与新 B2 可以具有相同 logical name、value 与 local revision

仅 value 或 value+revision 因而无法证明当前目标还是旧任务绑定的实体

对 concrete-incarnation task, identity evidence 需要覆盖不可混淆 incarnation

但 selector-bound task 的反例又说明 UID 不能机械成为所有任务的完成条件

### 4. Atomicity 不等于 predicate completeness

08-28 的 revision-only compare 本身是原子的

问题不是缺少 CAS, 而是 CAS 没有比较任务真正依赖的 target identity

因此 atomic compare 只能保护实际 compare set

compare set 必须从 task semantics 推导, 而不是从基础设施方便提供哪些 revision 字段倒推任务语义

### 5. 五日稳定链

本轮 current completion evidence 可以进一步收束为

`task semantics -> relevant identity set -> coherent snapshot or freshness -> atomic compare-and-protected-commit`

这不是新发现标题

它是既有 `生产路径成功证据不能替代当前后置条件` 发现和 `Current completion evidence 有效性` 方法的五日深化

## 恢复与重放

- 08-23 receipt-postcondition 在合法 reversal 后重新读取 current state, 必要 effect 前重新确认 current permission

- 08-25 target/global compare 在 final read 后 reversal 时拒绝 stale completion, 冲突后重新读 state 并在 effect 前重新确认 permission
- 08-26 pair compare 在 earlier A observation 已失效时识别 conflict, atomic pair snapshot 不把跨时 read 合成为共同完成
- 08-27 incarnation-bound 在同名重建时 safe stop / replan, 不把旧任务副作用执行到新实体

所有 completed replay 只能证明已经持久化 completion 后的重放行为

## 事实分层

### 已验证事实

- 08-24 至 08-28 五个日期都有主题唯一的每日研究记录并保持观察状态
- 08-24 保存 stale positive postcondition 的 effect count、event order 与双验证结果
- 08-25 保存 final read 后 reversal 的 TOCTOU, 普通 reread 仍假完成而 atomic relevant compare 拒绝旧声明
- 08-26 保存 authoritative 分离读取组成 fractured view 的反例, pair compare 能识别 earlier observation 失效
- 08-27 保存 same-name recreate + local revision reuse 的 identity alias, incarnation-bound 路径安全停止
- 08-28 保存 revision-only atomic compare 在 incarnation replacement 后仍成功的 under-binding 反例, contract-aware compare 按 concrete 或 selector task 语义区分
- 本周期两个 special 均明确不计作实验

### 基于证据的推断

- current completion correctness 同时依赖语义、身份、状态视图与提交时点, 任一维度缺失都可能形成 technically successful false completion
- atomicity 与 semantic completeness 是两个正交条件, 原子 CAS 不能自动修复 compare predicate 漏掉的业务依赖
- multi-resource current evidence 需要 coherent snapshot 或对全部 relevant earlier observation 的原子复核
- concrete-incarnation 与 selector-bound task 需要不同 identity contract, compare set 应从 task semantics 推导
- `task semantics -> relevant identity set -> coherent snapshot or freshness -> atomic compare-and-protected-commit` 是本周期最稳定的 current completion 方法收束
