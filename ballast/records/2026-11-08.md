## 研究问题

父级 orchestration 已进入 `TERMINATED` 或 `CANCELLED` 后, 能否据此认定 delegated child execution 和已发出的 effect request 均停止, 并证明任务没有产生副作用

若不能, no-effect cancellation proof 需要哪些 exact identity、child quiescence、in-flight closure、sink fence、attempt boundary、receipt freshness 与 retention 证据

## 来源依据

- [AWS Step Functions Parallel workflow state](https://docs.aws.amazon.com/step-functions/latest/dg/state-parallel.html), 2026-11-08 核验, branch failure 会停止分支, 但已调用 Lambda 与 task-token activity worker 不会自动停止, worker 需通过 heartbeat 发现停止并自行退出
- [AWS Step Functions service integration patterns](https://docs.aws.amazon.com/step-functions/latest/dg/connect-to-resource.html), 2026-11-08 核验, `.sync` job cancellation 是 best-effort, IAM permission 缺失或临时服务故障可能导致取消失败; Request Response 只等待 HTTP response, 不等待 job 完成
- [Microsoft DurableTaskClient.TerminateInstanceAsync](https://learn.microsoft.com/en-us/dotnet/api/microsoft.durabletask.client.durabletaskclient.terminateinstanceasync?view=durabletask-dotnet-1.x), 2026-11-08 核验, API 返回表示 terminate message 已入队, task hub worker 后续更新 runtime status; in-flight activity 与 sub-orchestration 继续运行, 结果被丢弃
- [Microsoft Durable Task instance management](https://learn.microsoft.com/en-us/azure/durable-task/common/durable-task-instance-management?tabs=csharp), 2026-11-08 核验, termination transition 异步排队, parent termination 不向 activity functions 和 sub-orchestrations 传播

AWS 与 Microsoft 是独立 publisher, 页面只证明各自产品合同, 不证明所有 workflow engine、真实 sink 或本地模型采用相同语义

## 可证伪假设

H1: `parent terminal -> CANCELLED_NO_EFFECT` 会在 child 仍运行、request 仍在途、effect 已提交或 membership 不完整时错误给出无副作用结论

H2: `CANCELLED_NO_EFFECT` 必须满足完整 child identity、quiescence、in-flight closure、attempt close 与每个 exact effect identity 的 retention-covered authoritative MISS; sink fence 只约束其生效后的 commit boundary, 不能抹去此前发生的 effect

H3: cancellation 与 authorization revocation 是不同事件; late effect 必须按 effect-time grant 分类, 不得由 cancellation 自动推导历史越权或授权有效

## 强反例

1. Parent tick 12 已 `TERMINATED`, child-A 仍运行并于 tick 14 提交 effect-A, weak path 错判 `CANCELLED_NO_EFFECT`, reference 判为 `OCCURRED_RECONCILE`
2. 若 issuer 在 tick 13 明确撤销 delegate grant, tick 14 的同一 effect 判为 `UNAUTHORIZED_OCCURRENCE`; cancellation 不等于 revocation
3. 两个成员都提交 effect, 但只有 child-B grant 被撤销, 必须逐成员检查, 不能因先遇到合法成员而提前返回
4. Worker 已 quiescent 但 request 仍在途, 没有 sink fence 时不能仅凭 MISS 证明无迟到提交
5. Fence tick 13 生效但 effect tick 11 已提交, fence 不会消除历史 occurrence
6. `{A,B}` 被 `{A,C}` 等量替换、重复 A 或增加 C 时, count 相等不代表 identity completeness
7. Sink effect 与 exact receipt MISS 冲突必须 `EVIDENCE_CONFLICT`; query error、旧 watermark 或 retention 缺口不得升级为 authoritative MISS

## 暂时结论

`PARTIAL / EVIDENCE_INSUFFICIENT`

AWS 与 Microsoft 合同支持有限判断: cancellation/termination 不必然终止已启动的 child activity、Lambda invocation 或集成 job, parent terminal 不能单独证明 effect sink 静止

本地模型显示 no-effect cancellation 需要 child identity completeness、quiescence、in-flight closure、attempt boundary 和 exact retention-covered MISS; sink fence 必须覆盖完整 effect-set, fence 前 occurrence 仍需独立核验

本轮无真实 runtime、sink、issuer 或独立 receipt authority 证据, 不晋升 CASE、METHOD、NOTES, 不形成长期发现

## AGI-scale action-integrity relevance
