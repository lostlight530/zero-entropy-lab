## 研究摘要

This Daily extends the 2026-10-02 deletion boundary into controller provenance and external-resource verification.

The question is not whether Kubernetes can represent finalization. It is whether finalizer removal, control-object absence, or a controller cleanup claim can be promoted into proof that the external effect set is actually clean.

Kubernetes documents finalizers as a control-plane coordination mechanism. Crossplane documents the intended managed-resource contract in which an external resource is deleted before its finalizer is removed. Crossplane troubleshooting also documents the counter-boundary: manually removing a finalizer can delete the Kubernetes object without necessarily deleting the external resource.

No real external non-idempotent effect is executed or blindly retried.

## 研究问题

Can finalizer release, Kubernetes object absence, or controller-reported cleanup prove current external cleanup completion without an independently fresh witness over the exact external target and required effect set.

## 来源依据

Checked 2026-10-03 against current public documentation.

[Kubernetes Finalizers](https://kubernetes.io/docs/concepts/overview/working-with-objects/finalizers/) defines finalizers as keys that hold object deletion until controllers satisfy their cleanup requirements. The API protocol itself does not independently inspect arbitrary external systems.

[Crossplane Managed Resources](https://docs.crossplane.io/latest/managed-resources/managed-resources/) documents the intended managed-resource lifecycle: a provider begins deleting the external resource, keeps the managed resource through a finalizer, and removes the finalizer after the external resource is fully deleted. It also documents management policy combinations where external deletion is intentionally not permitted.

[Crossplane Troubleshooting](https://docs.crossplane.io/latest/guides/troubleshoot-crossplane/) states that manually removing a stuck finalizer allows the Kubernetes object to disappear but does not necessarily delete the external managed resource, and recommends checking the provider for lingering resources.

These sources constrain protocol and product semantics. They do not prove this bounded fixture, a specific provider implementation, or a live cluster result.

## 可证伪假设

H4 exact external target identity plus policy-aware, membership-complete and fresh independent external evidence rejects the modeled false completions.

## 强反例

## 路径比较

control-object-absence is cheap but collapses control-plane lifecycle into external completion and exposes five false-complete cases.

finalizer-release adds lifecycle information but still collapses provenance and external postcondition, also exposing five false-complete cases.

controller-contract distinguishes normal controller removal, manual bypass and policy semantics. It removes some false completion but still relies on controller semantics and misses provider-side contract breach, stale external evidence and incomplete external membership.

independent-external-witness is strongest in this bounded study because it binds the exact external target/effect set, deletion authority, evidence freshness and membership completeness while retaining historical occurrence and authorization guards.

The stronger path costs an additional authoritative external observation and may return evidence-insufficient rather than optimistic success when freshness or membership proof is unavailable.

## 暂时结论

Finalizer release is not an independent external cleanup receipt.

Kubernetes object absence is not external effect-set absence.

A controller's intended finalizer contract is useful evidence, but controller provenance is not verifier semantic independence.

For tasks whose semantics require external cleanup, valid current completion should be bound to a sufficiently fresh authoritative external witness over the exact target or required effect set.

H4 is supported only inside this bounded model. It is not a live Kubernetes, Crossplane, or cloud-provider result.

## AGI-scale action-integrity relevance

Long-running agents increasingly delete resources through control planes, operators, provider bridges and delegated controllers.

A harness that treats control-plane object disappearance or controller success as global completion can close a task while external resources, charges, credentials or dependent effects remain.

The action-integrity boundary therefore needs to state which authority proves control-plane lifecycle, which authority proves external effect state, whether the required effect-set membership is complete, and whether the verifier is independent of the controller that claimed cleanup.
