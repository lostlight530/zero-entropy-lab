## 研究问题

producer 与 verifier 已经使用不同代码实现时, 如果它们仍共享同一份漏字段授权 schema, 实现差异是否足以构成语义独立验证

关键窗口为 `APPROVE action+uid+policy+credential_scope -> credential_scope revoked -> producer compares action+uid+policy -> EFFECT -> verifier A and verifier B independently implement the same incomplete three-field contract`

本轮把 2026-09-05 的 omitted dependency 从 environment 改为 credential scope, 同时让两个 shared-schema verifier 使用不同算法, 检查共同失效是否来自共享语义合同而非代码复用

## 来源依据

查询日期为 2026-09-06

- [NIST SP 800-162 Guide to Attribute Based Access Control](https://www.nist.gov/publications/guide-attribute-based-access-control-abac-definition-and-considerations) 将授权建模为 subject、object、requested operation 与可选 environment attributes 对 policy 的联合求值, 并要求属性管理考虑 validation、integrity、provenance 与 change history. 本轮只采用有限命题: 授权可以依赖多个权威属性, 漏掉真实依赖的局部 projection 不能证明当前授权仍成立
- [NASA IV&V Overview](https://www.nasa.gov/ivv-overview/) 说明 IV&V 的 technical independence 要求验证人员独立于开发者评估开发过程和产物, 并由独立方选择分析对象与技术问题. 本轮只采用有限命题: verification independence 不仅是代码文件分离, 还要求对被验证假设具有独立评估能力

两个来源来自不同权威体系. 外部资料不证明本轮 effect 数量、PASS 结果或 Ballast 夹具的通用性

## 可证伪假设

- H1: producer 与 verifier 使用不同实现算法后, 即使共享同一 authorization field schema, 一致 PASS 也可以证明任务有效完成
- H2: action、UID 与 policy 足以代表当前 approval applicability, credential scope 变化不会改变授权
- H3: 两个不同实现但共享漏字段 schema 的 verifier 可以同时接受同一个 unauthorized effect
- H4: 从 raw authority state 独立重建 action、UID、policy、credential scope 的 verifier 能识别上述共同失效
- H5: dependency-complete projection 拒绝 credential scope 与 policy 两类相关变化, 但不因无关 metadata 单独停止
- H6: whole-global revision 保守阻止相关变化, 但会 over-fence 无关 metadata
- H7: completed replay 不能替代 omitted-dependency production replay

H1 的反证条件是 verifier A 与 verifier B 实现方式不同, 但 credential scope 被撤销后两者仍同时接受 incomplete producer 的 effect

H2 的反证条件是 action、UID、policy 全部保持批准值, 仅 credential scope 从 `mark:write` 变为 `read:only`, incomplete path 仍产生 unauthorized effect

H4 的反证条件是 raw verifier 读取完整 authority fields 后仍无法区分该 effect 与 normal authorized effect

## 控制条件

- approval contract 固定为 action=`mark`, uid=`uid-A1`, policy=`standard`, credential_scope=`mark:write`
- 初始 authority note=`n0`, revision=10
- credential-scope-revoked 只把 credential scope 改为 `read:only`, revision 推进到 11
- policy-restricted 只把 policy 改为 `restricted`, revision 推进到 11
- irrelevant-metadata 只把 note 改为 `n1`, global revision 同样推进到 11
- incomplete-projection 比较 action、UID、policy, 明确省略 credential scope
- complete-projection 比较 action、UID、policy、credential scope
- global-revision 比较 whole-global revision
- verifier A 使用显式布尔条件实现三字段 incomplete schema
- verifier B 使用独立的 key-value set equality 实现同一三字段 incomplete schema
- raw verifier 不导入 producer 或两个 shared-schema verifier, 从 raw action、UID、policy、credential scope 重建 authorization truth
- completed replay 从已持久化 completion 重新进入 production entry
- 夹具只使用 Python 标准库与系统 awk

## 实验设计

1. 三条 production path 运行 normal baseline
2. 只撤销 credential scope, 攻击 shared incomplete schema
3. 只改变 policy, 作为 included dependency 控制
4. 只改变无关 note metadata, 检查 global over-fencing
5. completed replay 检查新增 effect 为 0
6. producer 保存 raw authority fields、projection match、effect、unauthorized、ops 与 event_order
7. producer 完整运行三次并比较 TSV SHA-256
8. verifier A 用显式条件实现 incomplete schema
9. verifier B 用 set-of-pairs 合同比较实现相同 incomplete schema
10. raw verifier 从完整 authority fields 重建 approval applicability
11. awk 独立复核 scope revoked 与 irrelevant metadata 两个关键边界
12. producer 与三个 verifier 执行 `py_compile`

## 独立验证

verifier A 与 verifier B 不共享实现代码

- verifier A 使用显式 `action == mark and uid == uid-A1 and policy == standard` 条件
- verifier B 独立构造 `action`、`uid`、`policy` 的 key-value set 并比较批准集合

两者都故意共享同一漏掉 credential scope 的语义 schema, 因而三次分别返回 `EXPLICIT_SCHEMA_PASS 15` 与 `SET_SCHEMA_PASS 15`

这两个 PASS 是共同失效观测, 不是有效完成证据

raw verifier 不读取 producer 的 projection_match 作为授权真值, 而从 raw action、UID、policy、credential scope 重建完整 approval contract

raw verifier 三次均返回 `RAW_AUTHORITY_PASS 15`, 并确认 credential-scope-revoked / incomplete-projection 为 projection_match=1、effect=1、unauthorized=1

awk 三次均返回 `AWK_PASS`

producer、verifier A、verifier B、raw verifier 均通过 `py_compile`

所有验证仍共享 scenario vocabulary、TSV 字段约定与同一系统运行环境, 不构成完全外部 IV&V

## 强反例

第一强反例攻击 implementation diversity

verifier A 与 verifier B 的代码路径和比较算法不同, 但二者都从相同错误合同中省略 credential scope. scope 从 `mark:write` 变为 `read:only` 后, 两个 verifier 仍同时接受 incomplete producer 的 effect

第二强反例攻击三字段授权 schema

credential scope 是批准合同中的真实字段, 但 action、UID、policy 全部保持原值. incomplete projection 因字段集合欠完整而产生 1 次 unauthorized effect

反方向强反例只改变 note metadata

complete projection 的真实 authorization dependencies 全部未变并继续执行, global revision 却因为无关变化安全停止, 说明更宽 fence 不是更精确的独立性修复

policy-restricted 控制中 incomplete projection 正确拒绝 effect, 证明 weak path 并非无条件执行, 失败定位在 omitted credential scope

## 路径比较

- incomplete-projection 字段少且操作数低, 但 credential scope 漏字段时产生 stale unauthorized effect
- verifier A 与 verifier B 实现不同却共享错误 schema, 增加代码多样性没有增加该依赖维度的语义覆盖
- raw verifier 从完整 authority fields 重建合同, 能阻止把共同失效报告为有效完成, 但不能撤销已发生 effect
- complete-projection 在 effect 前拒绝 credential scope 与 policy drift, 并允许 irrelevant metadata
- global-revision 在相关变化中保守停止, 但 irrelevant metadata 下额外停止
- 本轮质量改进来自 dependency coverage 与 semantic independence, 不是 verifier 数量或操作数

## 暂时结论

证据状态为观察

本轮支持: implementation diversity 不等于 semantic independence. 两个 verifier 即使使用不同代码与不同比较算法, 只要继承同一漏字段授权 schema, 仍可共同接受同一个 stale unauthorized effect

与 2026-09-05 的 omitted environment 实验相比, 本轮改用 credential scope 并增加第二种 verifier 实现, 同一 common-mode omission 现象在实质不同输入字段与验证实现下再次出现. 这构成跨日重复信号, 但今日单元本身仍保持观察状态, 不进入 NOTES

raw authority reconstruction 仍是验证 common-mode omission 的必要独立证据路径之一, 但事后验证不能替代 effect 前 dependency-complete protected authorization boundary

现行 METHOD 已要求保留原始事实源、披露共享假设并保守覆盖 relevant projection dependencies, 本轮不修改 METHOD

## 事实分层

### 已验证事实

- credential scope 被撤销而 action、UID、policy 保持不变时, incomplete projection 产生 1 次 unauthorized effect
- verifier A 与 verifier B 使用不同实现算法, 但共享漏字段 schema 后均接受该 effect
- raw verifier 从完整 authority fields 能识别上述共同失效
- complete projection 阻止 credential scope 与 policy 两类相关变化
- irrelevant metadata 中 complete projection 正常执行, global revision 额外停止
- completed replay 三条路径零新增 effect
- producer 三次 trace SHA 一致, 两个 shared-schema verifier 3/3 PASS, raw verifier 3/3 PASS, awk 3/3 PASS, 四个 Python 文件 py_compile PASS

### 基于证据的推断

- code-path independence 与 semantic dependency independence 是不同性质的验证约束
- 多个 verifier 如果共享同一错误 contract schema, verifier 数量和实现多样性都不能证明 dependency set 完整
- raw authority reconstruction 能提高 shared-spec omission 的发现能力, 但 effect 前授权边界仍必须自己完整

### 未验证事项

- 尚未在真实 ABAC、HITL 或 policy engine 复现 credential scope omission
- 尚未让 verifier 读取真正独立的 authority representation
- 尚未测试不同实现共享同一错误自然语言规范的发现率
