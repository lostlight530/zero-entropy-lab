# Ballast 日记录 2026-07-25

类型: 每日专题
主题: 共享依赖复发时的上下文门控恢复

## 研究问题

多个 Agent 同时依赖一个发生复发故障的外部服务时, 各自重试或只信任聚合恢复状态是否会形成重试放大和共同假成功, 上下文门控恢复能否安全完成并保持重放幂等.

本专题于 2026-07-26 执行并补录, 对应缺失的 2026-07-25 研究窗口.

## 来源依据

查询日期为 2026-07-26.

- [OpenAI 广泛服务事件特殊专题](../special/2026-07-25-openai-wide-service-events.md) 只说明本实验的问题来源, 不作为实验结果或机制解释.
- [AWS Timeouts, retries, and backoff with jitter](https://d1.awsstatic.com/builderslibrary/pdfs/timeouts-retries-and-backoff-with-jitter.pdf) 说明重试会放大依赖负载, 失败相关时相同重试时刻会再次形成拥塞, 应限制重试并在观察到依赖健康时才恢复.
- [Microsoft Retry Storm antipattern](https://learn.microsoft.com/en-us/azure/architecture/antipatterns/retry-storm/) 更新于 2025-08-11, 说明频繁客户端重试可能阻碍服务恢复, 建议限制次数与持续时间、退避并使用熔断.
现实事件事实、时间线和表达边界只保存在独立特殊专题中. 本日报仅使用 AWS 与 Microsoft 的工程资料约束受控实验设计.

## 可证伪假设

路径 A 让三个执行者在共享依赖不可用时各自立即重试三次, 并把捕获异常后的占位产物标记为完成. 预计依赖调用被放大, 文件数量检查通过而语义验证失败.

路径 B 只在聚合状态显示恢复后同时放行三个执行者. 预计两个上下文完成, 一个受控上下文仍不可用, 聚合状态加文件数量仍产生假成功.

路径 C 首次共享失败后打开一次熔断状态, 保存任务检查点且不写完成产物. 聚合恢复后逐上下文执行并验证, 尚未恢复的任务继续暂停. 第二次事件期间已完成任务先验证结果并零调用重放, 新任务等待第二次恢复.

如果路径 A 未增加调用或错误产物未通过浅层检查, 路径 B 能识别上下文差异, 或路径 C 留下无效完成产物、丢失检查点、复发时重新调用已完成任务或最终验证失败, 对应假设被推翻.

## 控制条件

- 三个基础任务分别代表 API、ChatGPT 与 Codex 执行上下文, 输入和预期结果固定.
- 两次事件阶段均令三个受控上下文不可用.
- 第一次聚合恢复阶段令 API 与 ChatGPT 可用, Codex 仍不可用, 这是根据聚合状态边界设计的强反例, 不是对真实事件中某个 Codex 用户的事实陈述.
- 第一次上下文恢复后三个基础任务均可用.
- 第二次事件开始时三个基础任务已经独立验证, 同时加入一个未完成 API 新任务.
- 生产器与验证器使用不同 Python 文件和进程, 验证器只读取最终输出与当前任务合同.
- 所有样本使用 ballast 内固定前缀, 实验前不得存在, 结束后逐文件清理.

## 实验设计

1. 路径 A 在第一次事件中让三个任务各自立即调用三次, 失败后写入状态为 complete 的空结果, 比较文件数量与独立语义验证.
2. 路径 B 在聚合恢复信号后同时运行三个任务, 对仍不可用的上下文捕获错误并写入完成占位, 比较聚合状态、文件数量与语义验证.
3. 路径 C 首次失败后打开共享熔断状态并为三个任务写入等待检查点, 不生成完成输出.
4. 聚合恢复阶段逐上下文调用, 只发布并清除通过任务的检查点, 未恢复任务保持等待.
5. 上下文恢复后完成剩余任务并验证三个基础任务.
6. 第二次事件发生时先验证三个已完成任务, 确认重放零依赖调用与零写入, 新任务只保存检查点.
7. 第二次恢复后完成新任务, 验证四个任务并再次零调用重放, 最后清理全部受控文件.

## 原始观测

正式轨迹为 第一次共同失败 → 路径分叉 → 聚合恢复 → 上下文恢复 → 第一次完整验证 → 第二次共同失败 → 已完成任务零调用重放与新任务暂停 → 第二次恢复 → 最终验证.

- 路径 A 依赖调用 9 次, 写入 3 个完成产物. 文件数量检查为真, 独立验证以三个 result_invalid 拒绝, 退出状态为 1.
- 路径 A 因只看文件存在而在重放时依赖调用 0 次、写入 0 次, 但错误完成状态被持续保留.
- 路径 B 在聚合恢复后依赖调用 3 次并写入 3 个完成产物. 文件数量检查为真.
- 路径 B 的 API 与 ChatGPT 结果有效, Codex 结果为空. 独立验证以 result_invalid:codex-task 拒绝, 退出状态为 1.
- 路径 C 第一次失败后打开熔断状态, 初始三个任务均保存等待检查点.
- 聚合恢复阶段先完成 2 个任务, 1 个任务继续等待. 上下文恢复后剩余任务完成, 三任务验证通过.
- 第二次事件期间, 已完成三任务重放的依赖调用与写入均为 0. 新任务保存等待检查点.
- 第二次恢复后第四个任务完成, 最终四任务验证通过, 检查点剩余 0.
- 路径 C 依赖调用 7 次、完成产物写入 4 次、检查点状态写入 8 次. 最终重放依赖调用与写入均为 0.
- 四项机制断言全部为真, 有效完成为真, 受控状态完成清理.
- 三次验证后的有效耗时分别为 504.583、531.189 与 360.596 毫秒.

实验没有调用 OpenAI 生产服务, 不把受控故障时序当作真实事件内部机制.

## 独立验证

verify_shared_outage.py 在独立 Python 进程中回读任务输出, 检查任务集合、完成状态、执行上下文、当前输入摘要和预期处理结果. 文件数量检查与独立语义验证分开运行.

验证器不读取生产函数的成功状态、熔断变量或检查点判断. 独立性限制是两者共享 JSON 模式、SHA-256 和 processed 结果合同, 并运行在同一文件系统.

特殊专题不能验证本地实验断言, 本地实验也不能解释现实事件根因, 两条证据链分别维护.

## 强反例

路径 B 同时满足聚合状态显示恢复、三个完成文件存在和两个任务结果正确, 但 Codex 受控上下文仍不可用且空结果被标记为完成. 独立语义验证将整体拒绝.

这个状态推翻了供应商聚合状态恢复加预期产物数量齐全就足以证明多个 Agent 全部恢复的解释.

路径 A 的错误完成产物在第二次检查时没有新增调用或写入, 表面上满足重放零副作用, 但错误状态被稳定重放. 这进一步说明幂等错误不等于有效完成.

## 路径比较

- 路径 A 调用 9 次仍得到 3 个无效结果, 重试最多且质量失败.
- 路径 B 只调用 3 次, 操作最少但整体结果不完整, 不能把低调用数记为速度改进.
- 路径 C 调用 7 次完成跨两次事件的 4 个有效任务, 额外检查点写入换取可恢复状态和任务级验证.
- 路径 C 在第二次事件中没有重新调用已验证的三个任务, 新任务保持等待, 避免把复发事件扩散到已完成工作.
- 三条路径没有分别测量墙钟时间, 因此不声明哪条路径绝对更快. 有效耗时只记录整体验证闭环.

## 暂时结论

状态为观察.

在本次受控多 Agent 实验中, 独立立即重试放大了共享依赖调用, 聚合恢复信号不能替代每个任务上下文的最终验证. 共享熔断、等待检查点、逐上下文恢复和结果级验证共同阻止了占位完成与复发时重复调用.

该机制只出现一次, 不升级为候选或长期结论.

## 复验条件

在另一时间窗口改变执行者数量、故障持续时间和恢复顺序, 加入限额响应、超时与部分流式结果. 比较固定间隔、指数退避加抖动、共享重试预算与分区熔断.

使用不同实现验证器并让状态来源与实际调用结果冲突. 验证检查点损坏、恢复信号撤回和第三次复发时是否安全停止.

## 事实分层

### 已验证事实

受控实验中盲重试放大调用, 聚合恢复路径产生一个无效完成结果, 上下文门控路径完成四个有效任务并在复发时零调用重放已完成任务.

### 基于证据的推断

多个 Agent 同时依赖同一外部服务时, 故障相关性会削弱各自独立重试的价值. 聚合服务状态适合作为恢复线索, 不适合作为单个任务完成证明. 已验证产物优先于复发时重新调用依赖.

### 未验证事项

真实外部依赖中的客户端重试行为、并发竞争、限额响应与远端副作用均未验证. 本实验未调用生产服务.

## 指标

- 有效完成: 路径 C 为是, 路径 A 与路径 B 为否.
- 重放一致与幂等通过: 路径 C 为是. 路径 A 只是稳定保留错误, 不计为有效幂等.
- 中断恢复: 路径 C 跨两次事件完成.
- 假成功: 路径 A 1 个整体状态, 路径 B 1 个整体状态, 均被独立验证拦截.
- 依赖调用: 路径 A 9 次, 路径 B 3 次, 路径 C 7 次.
- 完成产物写入: 路径 A 3 次, 路径 B 3 次, 路径 C 4 次.
- 检查点状态写入: 路径 C 8 次.
- 第二次事件期间已完成任务重放: 依赖调用 0, 写入 0.
- 无效操作: 正式协议内 0.
- 人工介入: 0.
- 验证后的有效耗时: 504.583、531.189 与 360.596 毫秒.
