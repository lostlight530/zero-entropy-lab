# Ballast 日记录 2026-08-01

类型: 每日专题
主题: 条件写入响应丢失后的远端回读

## 研究问题

云端对象写入的响应丢失后, 使用旧校验标识重试被拒绝时, 仅看失败状态、盲覆盖和回读当前对象能否区分首次写入已生效与其他写入已经推进状态.

## 来源依据

查询日期为 2026-08-01.

- [RFC 9110 HTTP Semantics](https://www.rfc-editor.org/rfc/rfc9110.html) 规定 `If-Match` 以强实体标签约束状态变更, 用于阻止并发参与者造成丢失更新. 规范同时说明先前响应可能丢失, 已经生效的等价变更可以返回成功.
- [GitHub REST API endpoints for Git references](https://docs.github.com/en/rest/git/refs) 说明引用更新在 `force` 省略或为假时只接受快进更新, 避免覆盖已有工作, 冲突与成功具有不同响应状态.

RFC 给出通用条件请求语义, GitHub 文档给出云端引用更新实例. 两者支持用当前标识限制覆盖, 但不保证任意供应商都提供等价的幂等结果查询.

## 可证伪假设

- H1: 旧前置条件被拒绝足以证明任务失败, 无需读取远端当前状态.
- H2: 前置条件只阻止覆盖, 不能单独区分首次写入已生效与其他写入冲突. 使用稳定操作意图回读远端当前内容可以区分两者.

如果两个场景在回读后仍无法区分, 或回读路径错误覆盖其他写入, H2 被推翻.

## 控制条件

- 三条路径从修订 1 的同一对象开始, 使用相同任务标识和客户端意图.
- 写入端只维护当前对象、单调修订与接受记录.
- 条件写入要求当前修订等于客户端读取的修订 1.
- 独立验证器只读取最终状态和单独提供的当前意图, 不读取客户端成功判断、异常或生产器预期.
- 实验使用 Python 标准库和系统临时目录, 文本显式使用 UTF-8.

## 实验设计

1. 盲覆盖路径: 客户端读取修订 1 后, 外部写入推进到修订 2, 客户端忽略旧前置条件并覆盖到修订 3.
2. 已生效响应丢失路径: 首次条件写入成功推进到修订 2, 响应丢失, 同一旧前置条件重试被拒绝, 随后回读当前对象.
3. 冲突推进路径: 首次请求没有生效, 外部写入推进到修订 2, 客户端旧前置条件重试被拒绝, 随后回读当前对象.
4. 对已生效路径执行同输入重放, 检查额外写入.

故障注入分别位于并发写入后、首次写入响应返回前与首次写入生效前.

## 原始观测

| 路径 | 首次客户端写入 | 旧条件重试 | 最终修订 | 最终意图 | 结果写入 | 任务级判断 |
| --- | --- | --- | ---: | --- | ---: | --- |
| 盲覆盖 | 未执行 | 无条件接受 | 3 | client | 2 | 拒绝, 当前外部意图被覆盖 |
| 已生效但响应丢失 | 接受 | 前置条件拒绝 | 2 | client | 1 | 回读后有效完成 |
| 其他写入推进 | 未生效 | 前置条件拒绝 | 2 | external-current | 1 | 冲突并安全停止 |

已生效路径如果只看最后响应会报告失败. 回读确认任务标识、稳定意图、载荷与最新接受修订一致, 同输入重放写入为 0.

## 独立验证

独立 Python 进程从最终状态重新读取任务标识、意图、载荷、当前修订和接受记录中的最大修订.

验证器不读取客户端异常、条件写入返回值、重试次数或生产器成功布尔值. 它仍与生产路径共享 JSON 字段合同、任务标识和稳定意图定义.

## 强反例

首次写入已经把完整客户端意图提交为修订 2, 但响应在客户端收到前丢失. 使用修订 1 重试被拒绝, 最后一次命令状态是失败, 而远端当前对象已经满足目标.

另一路径也返回相同的前置条件拒绝, 但远端对象属于外部意图. 因此前置条件失败既不能单独证明有效完成, 也不能单独证明任务失败.

## 路径比较

| 路径 | 阻止丢失更新 | 区分已生效与冲突 | 有效完成 | 重放写入 | 结果质量 |
| --- | --- | --- | --- | ---: | --- |
| 盲覆盖 | 否 | 否 | 否 | 未执行 | 覆盖当前外部结果 |
| 只看前置条件失败 | 是 | 否 | 否 | 未执行 | 把已完成误报为失败 |
| 条件写入加远端回读 | 是 | 是 | 是 | 0 | 已生效确认, 冲突停止 |

回读路径增加一次读取和内容验证, 但避免一次错误覆盖与一次假失败. 单次受控耗时不用于推断真实网络速度.

## 暂时结论

状态为观察.

本次受控实验中, 强前置条件阻止旧客户端覆盖当前对象, 但条件失败不能区分首次写入已生效与其他写入冲突. 绑定稳定操作意图的远端回读恢复前者的有效成功, 并让后者安全停止.

该观察扩展现有未知结果重试和当前状态绑定证据, 但只在单机模型中出现一次, 不升级为候选或长期发现.

## 复验条件

使用真实对象存储、Git 引用或支持实体标签的 HTTP 服务复验, 注入响应丢失、并发写入、延迟读和权限变化. 测试内容相同但操作身份不同、弱实体标签、复制延迟和引用非快进冲突.

构造首次请求部分生效、回读暂时不可见或当前内容相同但副作用历史不同的反例, 检查稳定意图是否足以证明完成.

## 事实分层

### 已验证事实

- 盲覆盖路径在外部写入后接受客户端写入, 最终覆盖当前外部意图, 独立验证拒绝.
- 已生效与冲突路径的旧前置条件重试都被拒绝, 两者最后操作状态相同.
- 远端回读接受已生效客户端意图, 拒绝外部冲突意图.
- 已确认路径同输入重放写入为 0, 实验临时目录完成清理.

### 基于证据的推断

- 云端提交需要把防覆盖和完成判定分成两个条件, 前置条件保护写入边界, 当前内容回读判断任务结果.
- 对响应丢失的操作, 失败状态更适合作为查询当前状态的触发器, 不适合作为最终任务结论.

### 未验证事项

- 真实云服务的延迟读、弱实体标签、跨区域复制与权限故障.
- 相同最终内容是否足以证明不可逆副作用只发生一次.
- GitHub 连接器写入与引用更新在真实响应丢失时的可观察行为.

## 指标

- 有效完成: 条件写入加回读路径为是, 盲覆盖和只看失败状态为否.
- 重放一致与幂等通过: 已生效回读路径为是, 同输入重放写入 0.
- 中断恢复: 首次写入响应丢失后由远端回读恢复判断.
- 假成功: 盲覆盖路径 1 次, 最终内容存在但覆盖当前意图.
- 假失败: 只看前置条件失败路径 1 次, 远端目标已经实现.
- 无效操作: 盲覆盖路径 1 次错误写入, 安全路径 0 次额外写入.
- 重试次数: 已生效与冲突路径各 1 次.
- 人工介入: 正式机制实验内 0.
- 结果质量差异: 盲覆盖破坏当前外部结果, 只看状态遗漏有效完成, 回读路径区分完成与冲突.
- 验证后的有效耗时: 301.833 毫秒.
