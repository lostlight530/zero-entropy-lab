## 研究问题

副作用前重新读取 current execution permission 是否足以证明 effect 发生时仍有权限

攻击窗口为 `PERMISSION_RECHECK -> authority change -> EFFECT`, 并比较 whole global revision 与 relevant authority projection 两种受保护边界

## 来源依据

查询日期为 2026-09-02

- [etcd API](https://etcd.io/docs/v3.7/learning/api/) 说明 transaction 是原子 If/Then/Else, comparison 可以检查 value、version、create revision 或 mod revision, 多个 comparison 原子决定 success 或 failure block. 适用边界是 etcd transaction semantics
- [Kubernetes API Concepts](https://kubernetes.io/docs/reference/using-api/api-concepts/) 说明 resourceVersion 提供资源版本与 freshness 语义. 适用边界是 Kubernetes API concurrency and visibility semantics

两个独立官方来源共同支持有限前提: 单次读取只证明读取时点事实, 后续动作继续依赖该事实时需要版本或条件继续绑定到受保护动作边界

## 可证伪假设

- H1: effect 前普通 permission recheck 足以授权后续 effect
- H2: whole global revision compare 能拒绝相关授权变化, 但可能被无关 metadata 过度围栏
- H3: 完整 relevant authority projection 与 effect 原子 compare 可以拒绝真实授权变化并容忍无关 metadata
- H4: completed replay 不能替代 permission change 窗口

- entry-cache 最便宜但权限最陈旧

- projection-compare-effect 在本轮显式依赖集内拒绝 cancel/handoff 且容忍无关 metadata, 安全性依赖 projection 完整性
