## 研究摘要

本轮直接攻击 2026-09-18 delegated-authority observation 的下一层边界.

问题不是把 delegation history 绑定得越多越安全, 而是区分 current access-control dependency 与 historical delegation trail.

受控实验比较四条路径:

- subject-only
- current actor + audience
- current actor + audience + current token active
- full-chain-active, 额外要求 nested prior actors 当前仍满足本地假设

实验同时保留 prior-effect HIT 与 UNKNOWN 的零新增 effect 边界.

## 研究问题

在 nested OAuth delegation token 中, protected resource 是否应该把 nested prior actors 的当前状态继续当作 new-effect access-control gate, 还是只使用 top-level claims, current actor 与 authorization server 提供的 current token state.

进一步问题是, 忽略 current token active state 是否会 under-fence, 而把 prior-actor history 直接升级成 current gate 是否会 over-fence.

## 来源依据

查询日期 2026-09-19.

- RFC 8693 https://www.rfc-editor.org/rfc/rfc8693.html 定义 JWT `act` actor claim. Nested `act` 可以表达 delegation history, outermost `act` 是 current actor, 更深层 prior actors 是历史 trail. RFC 明确要求 token consumer 在 access-control policy 中只考虑 top-level claims 与 current actor, nested prior actors 仅作 informational history.
- RFC 7662 https://www.rfc-editor.org/rfc/rfc7662.html 定义 token introspection. `active` 表示授权服务器当前认为 token 是否可用, authorization server 必须执行适用的 expiry, revocation, signature 与 resource-server applicability 检查.
- RFC 7009 https://www.rfc-editor.org/rfc/rfc7009.html 定义 OAuth token revocation, revocation 可以使 token 以及适用时同一 authorization grant 下的其他 token 或 grant 失效.

外部 RFC 只支持协议语义, 不证明本地 fixture PASS, 不证明真实 authorization server 会如何把某个 prior-actor lifecycle change 投影为 token revocation.

## 可证伪假设

- H1 subject-only 足以决定 delegated new effect.
- H2 current actor + audience 足以决定 delegated new effect, token current active state不构成独立 dependency.
- H3 current actor + audience + current token active 能在本轮 modeled consumer boundary 内拒绝 current actor drift, wrong audience 与 inactive token.
- H4 在 H3 之上额外把 nested prior-actor current state作为 access-control gate只会增加安全性, 不会产生 false rejection.
- H5 prior HIT 即使 current token inactive 仍只做 historical reconciliation, 不产生新的 effect.
- H6 prior UNKNOWN 即使 current token active 仍保持 safe stop, 不把 permission valid 当成 historical non-occurrence.

## 强反例

### Under-fencing counterexample

token-inactive 场景中:

- subject正确
- current actor正确
- audience正确
- current token active=false

actor-aud 仍产生 new-effect.

actor-aud-active 正确拒绝.

这推翻 H2, 说明 current actor 与 audience都正确仍不能替代 current token authority state.

### Over-fencing counterexample

prior-actor-inactive-but-token-active 与 prior-chain-unknown-but-token-active 中:

- top-level subject正确
- current actor正确
- audience正确
- current token active=true
- nested prior actor分别为 inactive 或 unknown

full-chain-active 两次 permission-reject.

actor-aud-active 两次 new-effect.

在本轮 RFC 8693 consumer-side contract 下, prior actors是 informational delegation history, 不直接参加 resource-side access control. 因而 full-chain-active 在两个场景中形成 over-fencing false rejection.

## 路径比较

subject-only 最便宜, 但对 actor substitution, wrong audience 与 inactive token全部 false accept.

actor-aud 修复 actor substitution 与 wrong audience, 但 inactive token仍 false accept.

actor-aud-active 在本轮 8 个场景中与 modeled normative consumer decision 8/8 一致.

full-chain-active 没有新增 false accept, 但把 prior delegation history错误升级成 current gate后产生 2 个 false rejection.

因此 stronger predicate 不等于 better predicate. dependency completeness要求包含真实 current authorization dependency, 也要求不要把 informational history机械提升为 current authority.

HIT 与 UNKNOWN 四条路径均保持 new_effect=0, current permission predicate没有覆盖 historical reconciliation decision.

## 暂时结论

状态为观察.

H1, H2, H4 被推翻.

H3, H5, H6 在本地 modeled boundary 内得到支持.

本轮最重要的增量是双向约束:

- current token authority不能省略, 否则 under-fence
- nested prior-actor history不能在 resource consumer侧被机械升级成 current access-control gate, 否则 over-fence

如果 prior actor失效应使当前授权失效, 更符合本轮协议边界的路径是由 authorization server把该依赖投影到 current token state, 再由 consumer读取 current authoritative state.

这不证明所有 OAuth deployment 都采用相同 revocation cascade policy.

## AGI-scale action-integrity relevance

长期自主 Agent 的 delegation chain可能包含 planner, approver, executor, sub-agent 与 tool/resource.

完整审计 trail 与 current execution authority 都重要, 但它们不是同一个 predicate.

把所有历史参与者当前状态都绑进 leaf action gate会造成不必要拒绝, 而只看最终 subject又会漏掉真正的 current actor 与 current credential state.

AGI-scale action integrity因此需要同时控制 under-fencing 与 over-fencing, 不能把更多字段自动视为更安全.

### 基于证据的推断

- delegated action的 current permission必须绑定 current actor和 current token authority, 不能只绑定最终 subject.
- nested delegation history提供审计与 provenance价值, 但 history存在不等于每个 prior actor current state都应成为 leaf resource的 current gate.
- authorization dependency完整性既要避免漏字段 under-fencing, 也要避免把非授权字段升级为 gate造成 over-fencing.
