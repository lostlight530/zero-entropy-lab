## 研究问题

当 effect 可能已提交、completion 未持久化且 authoritative receipt 暂时返回 `UNKNOWN` 时, 使用稳定 idempotency token 重放能否同时证明副作用没有重复并证明 effect 在中断前已经发生

核心攻击不是 final-state duplication 本身, 而是两个不同历史是否会在 token 去重后收敛到同一个最终资源与 effect count, 使只看最终状态的 verifier 无法区分 pre-interruption occurrence 与 replay-time creation

## 可证伪假设

- H1: authoritative receipt 为 UNKNOWN 时, 把 UNKNOWN 视为 MISS 并在 current permission 有效时重试是安全恢复
- H2: 增加固定查询预算后把连续 UNKNOWN 降级为 MISS, 可以在不损失结果质量的前提下降低等待
- H3: stable idempotency token 可以阻止 duplicate effect, 因而 token replay 的最终成功足以证明 prior effect occurrence 已经解析
- H4: persistent reconciliation 保持 UNKNOWN, 直到获得 authoritative HIT 或 authoritative MISS, 能区分 pre-interruption hit 与 replay-time creation
- H5: current permission 无效时仍可继续只读 historical reconciliation, 但任何 sink replay attempt 都必须被当前权限门阻止
- H6: completed replay 从 production entry 重入时保持零新增 effect 与零 sink call

H1 的反证条件是 late-hit-valid 中 historical effect 已存在, UNKNOWN-as-MISS 又执行一次 effect, effect_total 从 1 增长到 2

H3 的反证条件是 initial-hit 与 initial-miss 两个不同历史经过 token replay 后得到相同 `effect_total=1` 与相同 result identity, 但 verifier 仅凭 sink 最终状态无法判断 effect 是中断前存在还是 replay 时创建

H4 的反证条件是 persistent path 在 receipt 最终变为 HIT 或 MISS 后仍不能恢复对应历史分类

## 控制条件

- effect identity 固定为 `op-77`
- late-hit-valid 初始 effect_total=1, completion 缺失, receipt 顺序为 `UNKNOWN,UNKNOWN,HIT`, current permission 有效
- late-hit-cancelled 初始 effect_total=1, receipt 顺序为 `UNKNOWN,HIT`, current permission 无效
- late-miss-valid 初始 effect_total=0, receipt 顺序为 `UNKNOWN,MISS`, current permission 有效
- late-miss-cancelled 初始 effect_total=0, receipt 顺序为 `UNKNOWN,MISS`, current permission 无效
- persistent-unknown-valid 初始 effect_total=1, 三次 receipt 都为 `UNKNOWN`
- completed-replay 已有 completion, 重新进入 production entry
- unknown-as-miss 第一轮 UNKNOWN 直接假定 MISS
- budget-as-miss 最多查询两轮, 连续 UNKNOWN 后假定 MISS
- token-replay 在 UNKNOWN + current permission valid 时用相同 `op-77` 进入幂等 sink, sink 已存在则返回原 identity, 不存在则创建一次
- persistent-reconcile 每次 production entry 只推进 authoritative receipt reconciliation, UNKNOWN 时不执行新 effect, HIT 时恢复历史 occurrence, MISS + permission valid 时才进入 protected effect boundary
- fixture 只使用 Python 标准库与系统 awk

## 强反例

第一强反例攻击 UNKNOWN-as-MISS

late-hit-valid 中 authoritative receipt 暂时 UNKNOWN 但 historical effect 已存在, unknown-as-miss 和 budget-as-miss 都在 current permission valid 后执行新 effect, effect_total 变为 2

第二强反例攻击 idempotency token 等于历史完成证明

late-hit-valid 与 late-miss-valid 的 token replay 都得到 effect_total=1 和 result=`token-result-op-77`, 前者 effect 在中断前已经存在, 后者 effect 是 replay 时才创建. 只看最终 sink state 的 verifier 无法区分这两个事件历史

第三强反例攻击固定 retry budget 可以把 unknown 变成 miss

late-hit-valid 的第二次 query 仍为 UNKNOWN, budget-as-miss 随后重试造成 duplicate, 而第三次 authoritative query 实际会返回 HIT

反方向强反例为 late-miss-valid

persistent reconciliation 等到 authoritative MISS 后, current permission 仍有效, 此时执行一次必要 effect 并完成, 证明保持 UNKNOWN 不是永久禁止恢复

## 路径比较

- unknown-as-miss 查询最少, 但 late HIT 时直接产生 duplicate effect, 结果质量失败
- budget-as-miss 多一次 query 仍会在迟到 HIT 前错误降级, 操作更多但没有增加正确性
- token-replay 在显式幂等 sink 合同下保持 effect_total=1, 比 persistent HIT 路径更早获得稳定最终资源, 但 sink final state 单独不能证明 effect 的 pre-interruption occurrence
- persistent-reconcile 需要更多 production entries 与 authoritative queries, 但在 HIT/MISS 可获得时恢复历史分类, 在持续 UNKNOWN 时宁可保持 reconciliation 也不猜测 absence
- current permission invalid 时 token path 和 persistent path 都没有新 sink effect, 但 persistent path 可以在之后只读查询得到历史 HIT
- 本轮不把 Python 微秒级运行时间外推为真实系统性能, 用 query_count、entries、sink_calls 与最终证据质量比较有效成本

## 暂时结论

证据状态为观察

本轮支持把 duplicate suppression 与 historical occurrence proof 分成两个证明义务

stable idempotency token 可以在明确 sink 合同下防止同一 effect identity 重放产生重复外部结果, 但最终返回相同 identity 不能单独证明 effect 是中断前已发生还是 replay 时创建

因此, 当任务完成语义依赖历史发生时点或要求解析 unknown outcome 时, idempotent final state 不能替代 authoritative receipt timeline、remote occurrence evidence 或等价时序证据

UNKNOWN 也不能因查询次数、timeout 或本地 retry budget 自动降级为 authoritative miss

## 事实分层

### 已验证事实

- late-hit-valid 中 unknown-as-miss 与 budget-as-miss 都新增一次 duplicate effect
- token-replay 在 initial-hit 与 initial-miss 两个历史中最终都保持 effect_total=1 和相同 result identity
- token-replay 的两个历史虽然 final state 相同, 但 initial_effect 分别为 1 与 0, 本地 sink result 本身不包含 pre-interruption occurrence proof
- persistent-reconcile 在 late HIT 后恢复 HIT 且零新增 effect, 在 late MISS + permission valid 后只执行一次必要 effect
- persistent UNKNOWN 三轮后仍保持 UNKNOWN 且零新增 effect
- current permission invalid 时没有任何新 sink call, historical query 仍可继续到 HIT 或 MISS
- completed replay 四条路径均零新增 effect与零 sink call
- producer 与 verifier 通过 `py_compile`, Python verifier 3/3 PASS, awk PASS, 三次 trace SHA-256 一致

### 基于证据的推断

- idempotency token 的 duplicate suppression 与 prior-effect temporal reconciliation 是不同证明义务
- 最终资源 identity 一致不能在两个历史可能收敛时替代 event order 或 authoritative occurrence evidence
- local retry budget 不能把 UNKNOWN 自动提升为 authoritative miss
- current execution permission 只决定是否允许新的 sink attempt, 不决定历史 effect 是否发生
