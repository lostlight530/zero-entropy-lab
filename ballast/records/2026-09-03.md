## 研究问题

当非幂等 effect 已可能提交但 completion 尚未持久化, 随后任务在恢复前又被取消或发生 ownership handoff 时, 恢复器能否只因为 current permission 已失效就直接停止

本轮把两个问题严格分开: 上一次 unknown outcome 是否已经产生 effect, 以及当前是否仍允许新的 effect

关键窗口为 `EFFECT committed -> completion missing -> interruption -> current permission invalid -> production entry replay`

## 来源依据

查询日期为 2026-09-03

- [RFC 9110 HTTP Semantics](https://www.rfc-editor.org/rfc/rfc9110.html) 说明幂等方法可以在通信失败且响应未知时自动重试, 非幂等方法不应自动重试, 除非客户端能够证明请求语义实际幂等或检测原请求未被应用. 适用边界是 HTTP retry semantics, 不直接证明 Ballast 夹具结果
- [Amazon EBS StartSnapshot idempotency](https://docs.aws.amazon.com/ebs/latest/userguide/ebs-direct-api-idempotency.html) 说明相同 client token 与相同参数的成功请求重试返回原结果且不产生额外 effect, token 相同但参数改变会冲突. 适用边界是 Amazon EBS API idempotency contract

两个独立权威来源共同支持有限前提: 响应或 completion 缺失不能单独证明原 effect 未发生, 重试安全需要稳定 effect identity、幂等语义或能够判定原请求是否已应用的权威证据

外部资料不证明本轮 permission、effect_count、reconciliation 或 completion 结果

## 可证伪假设

- H1: current permission 已失效时可以立即 safe stop, 无需继续解析 prior unknown outcome
- H2: completion 缺失可以作为 effect 未发生的充分证据并直接重试
- H3: prior-effect occurrence 与 current permission 是两个独立恢复轴, 即使 current permission 无效也应先得到 prior effect 的 hit、authoritative miss 或 unknown 分类
- H4: prior effect 为 authoritative miss 且 current permission 有效时, 才允许进入新的 protected effect boundary
- H5: prior effect 为 hit 时, current permission 无效只能阻止新的 effect, 不能把历史 occurrence 改写成未发生
- H6: completed replay 不能替代 `effect committed -> completion missing -> permission conflict -> replay` 窗口

H1 的反证条件是 effect 已真实提交且 receipt 可权威查询, permission-first path 因 current permission=0 在查询前停止, 最终 prior_reconciled=0

H2 的反证条件是 prior effect 已发生时 blind retry 使 effect_total 从 1 增加到 2

H3 的反证条件是 two-axis path 在 current permission 无效时无法同时确认 historical effect 与零新增 effect

## 控制条件

- effect identity 固定为 `op-42`
- unknown-hit 场景中 historical effect 已提交一次, completion 未持久化
- unknown-miss 场景中 historical effect 没有提交, completion 同样缺失
- current permission 由 intent、owner、valid_until、task status、credential capability 与 approval binding 联合表示
- unknown-hit-cancelled 在恢复前把 current task status 变为无效
- unknown-hit-handoff 在恢复前改变 current owner generation
- normal-miss-valid 保持 prior effect authoritative miss 与 current permission 有效
- completed-replay 从已持久化 completion 重新进入同一 production entry
- `blind-retry` 不查询 prior effect evidence
- `permission-first-stop` 先查 current permission, permission 无效时在 prior-effect query 前停止
- `receipt-first` 先解析 prior effect occurrence, 再检查 current permission
- `two-axis-recovery` 无论 current permission 是否有效都分别建立 authoritative prior-effect classification 与 current permission, 仅在 authoritative miss + permission valid 时进入 protected effect boundary
- 夹具只使用 Python 标准库与系统 awk

## 路径比较

- blind-retry 操作少, 但 unknown-hit-valid 产生重复副作用
- permission-first-stop 在 current permission 无效时能阻止新 effect, 但提前退出导致 unknown prior-effect evidence 未解析
- receipt-first 能解析历史 occurrence, 但如果需要新 effect 仍必须继续使用 current protected permission boundary, 不能把历史 query 替代当前授权
- two-axis-recovery 明确分离 prior-effect classification 与 current permission, 只有 authoritative miss + permission valid 才进入 protected effect
- 本轮质量差异来自恢复事实完整性与副作用正确性, 不是来自操作数最少

## 暂时结论

证据状态为观察

本轮支持将 unknown-outcome recovery 与 current permission 视为两个不可互相替代的轴

current permission invalid 可以阻止任何新的 effect, 但不能证明旧 effect 没有发生, 也不能自动消除解析 historical occurrence 的义务

completion 缺失同样不能证明 effect 未发生; 非幂等或外部副作用恢复前仍需要 authoritative effect identity、receipt、remote resource identity 或等价证据

完整受控恢复路径为 `authoritative prior-effect classification -> current permission -> if miss and valid then protected effect -> completion or reconciled safe stop`

### 基于证据的推断

- prior-effect occurrence 与 current permission 是独立恢复事实
- permission invalid 不会把 historical effect hit 变成 miss
- completion missing 不会把 prior effect unknown 自动变成 authoritative miss
- 当前权限只决定是否允许新的 effect, historical reconciliation 需要独立的权威 effect evidence
