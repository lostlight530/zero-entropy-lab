# Ballast 日记录 2026-08-08

类型: 每日专题
主题: 幂等身份复用中的意图错配

## 研究问题

任务已经产生副作用但响应丢失后, 恢复路径如果把同一个幂等身份复用于参数已经变化的新意图, 仅按身份去重与同时绑定身份和意图摘要的生产入口, 哪一种能避免把必要的新操作错误判为已完成

## 来源依据

查询日期为 2026-08-08

- [Amazon EC2 API idempotency](https://docs.aws.amazon.com/ec2/latest/devguide/ec2-api-idempotency.html) 访问于 2026-08-08, AWS 说明相同 client token 用于相同请求可实现幂等重试, 但同 token 携带不同参数时会出现 `IdempotentParameterMismatch` 或等价拒绝语义, 支持把幂等身份约束在同一请求意图内
- [Google AIP-155 Request identification](https://google.aip.dev/155) 创建于 2019-05-06, 状态为 Approved, 说明 request ID 用于识别同一请求并提供重复提交无额外效果的幂等保证, 支持 request ID 表示特定请求而不是可跨意图复用的永久任务身份
- [Stripe Idempotent requests](https://docs.stripe.com/api/idempotent_requests) 访问于 2026-08-08, Stripe 保存首次使用 idempotency key 的结果, 后续相同 key 会返回相同结果, 同时比较传入参数并在参数不同时报错以防止误用

AWS, Google 与 Stripe 来自三个独立组织, 都支持幂等身份用于同一请求的安全重放, 其中 AWS 与 Stripe 明确把不同参数复用相同身份视为冲突或错误, 但这些文档不证明所有任务系统都保存完整参数摘要, 也不证明幂等记录与业务副作用具有同一原子边界

## 可证伪假设

- H1: 只要同一个幂等身份已经有完成记录, 后续恢复调用直接返回 `already_complete` 且新增写入为 0, 就可以认为重放安全
- H2: 完成记录必须同时绑定幂等身份与规范化意图摘要, 同身份但不同意图应返回冲突而不是已完成, 新意图必须使用新的身份后再执行

如果只按身份去重在意图变化后仍能完成新目标, 或意图绑定路径无法识别错配且无法让新身份完成目标, H2 被推翻

## 控制条件

- 初始状态为 generation 1, value 10
- 基线请求使用 token `task-42`, 参数为 `value=20, mode=normal`
- 故障注入为基线请求副作用已经生效但响应被视为丢失, 调用方进入恢复
- 恢复时任务重新计算出新意图 `value=30, mode=recomputed`, 但错误复用 token `task-42`
- 正确恢复路径为新意图改用 token `task-43`
- 意图摘要由独立验证进程从控制夹具按键排序后的 UTF-8 JSON 重新计算 SHA-256
- 正式实验使用 Python 标准库和系统临时目录, 所有文本显式使用 UTF-8, 临时目录由运行时在每次实验结束时清理

## 实验设计

1. 初始化弱路径与强路径两份独立状态
2. 两条路径都让基线 `task-42` 通过各自生产入口写入 value 20
3. 注入响应丢失, 不把生产入口返回值作为恢复事实
4. 构造参数变化但复用 `task-42` 的恢复调用, 两条路径都重新经过原生产入口
5. 弱路径只按 token 查询完成记录, 命中后直接返回旧结果
6. 强路径重新计算当前参数摘要并与完成记录中的原意图摘要比较
7. 强路径发现错配后返回 `intent_conflict`, 随后使用新 token `task-43` 执行 value 30
8. 让 `task-43` 再次经过同一强生产入口以验证真实完成后的同输入重放
9. 独立 Python 进程从控制夹具与原始观测重新计算意图摘要, 检查最终内容, 结构, 身份集合与写入计数
10. 在同一控制条件下完整运行三次, 比较结果质量, 操作数量和验证后有效耗时

## 原始观测

| 路径 | 基线首次 | 错配恢复 | 新身份首次 | 新身份重放 | 最终代际 | 最终值 | 副作用写入 |
| --- | --- | --- | --- | --- | ---: | ---: | ---: |
| 仅身份去重 | applied | already_complete | 未执行 | 未执行 | 2 | 20 | 1 |
| 身份加意图摘要 | applied | intent_conflict | applied | already_complete | 3 | 30 | 2 |

弱路径在错配恢复中新增写入为 0, 返回旧完成结果, 但新目标 value 30 没有实现, 最终仍为 value 20

强路径在错配恢复中新增写入为 0, 但明确返回 `intent_conflict`, 没有把旧完成记录解释为新意图已经完成, 使用新 token 后 value 30 成功写入, 随后的同输入重放新增写入为 0

五项独立机制检查在三次完整运行中均为真, 独立验证进程每次返回码为 0, 验证后有效耗时分别为 3815.213 毫秒, 3276.553 毫秒和 3733.547 毫秒, 系统临时目录均已清理

独立验证重新计算出的摘要为

- 基线意图: `f0ffed545fe7e57a5230525535fef4e12b2e45c406e52128334e11f1bdd717a8`
- 变化后意图: `36c710d20b25dd9030f8f557ff7b1e22a96ce0cd665826ef66fffd5409b1b4d0`
- 新身份意图: `36c710d20b25dd9030f8f557ff7b1e22a96ce0cd665826ef66fffd5409b1b4d0`

后两者参数相同所以摘要相同, 差异只在幂等身份, 这使实验能区分意图内容与请求身份

## 独立验证

验证器作为独立 Python 进程运行, 不导入弱路径或强路径的生产入口函数, 不读取生产入口内部断言或成功布尔值

验证器直接读取控制夹具和原始观测, 重新计算三个请求的 SHA-256 意图摘要, 并分别检查

- 基线与变化后意图摘要确实不同
- 弱路径错配恢复返回 `already_complete`, 新增写入为 0, 但最终 value 不等于新目标
- 强路径错配恢复返回 `intent_conflict`, 新增写入为 0, 状态仍保持基线结果
- 新 token 首次调用实际写入一次并达到 value 30
- 新 token 再次经过同一生产入口返回 `already_complete`, 新增写入为 0, 最终副作用身份集合只有 `task-42` 与 `task-43`

验证器仍与生产路径共享 Python 运行时, JSON 语义, SHA-256 定义和同一文件系统, 未覆盖真实远端服务的参数规范化差异, TTL, 并发请求, 网络分区与不可逆副作用

## 强反例

弱路径在恢复时满足三个很容易被误判为成功的表面条件

- 完成记录存在
- 生产入口返回 `already_complete`
- 新增写入为 0

但恢复调用的参数已经从 value 20 变化为 value 30, 弱路径仍返回旧结果并保持 value 20

因此零副作用重放本身不能证明任务完成, 如果幂等身份没有绑定当前意图, 去重机制可以从防止重复写入退化为错误跳过必要操作

## 路径比较

| 路径 | 身份去重 | 意图绑定 | 错配结果 | 新目标是否实现 | 重放新增写入 |
| --- | --- | --- | --- | --- | ---: |
| 仅按 token 返回旧结果 | 是 | 否 | already_complete | 否 | 0 |
| 同 token 不同意图冲突 | 是 | 是 | intent_conflict | 不直接执行 | 0 |
| 新意图使用新 token | 是 | 是 | applied | 是 | 1 |
| 新 token 完成后同输入重放 | 是 | 是 | already_complete | 是 | 0 |

强路径增加一次规范化意图摘要比较和冲突分支, 操作数量并未比弱路径更少, 但避免把需要执行的新意图静默判为完成

本次单机毫秒级耗时只用于记录受控实验成本, 不用于推断真实 API 性能

## 暂时结论

状态为观察

本次受控实验中, 只按幂等身份查询完成记录可以做到零重复写入, 但当恢复调用的意图已经变化时会错误跳过必要操作, 形成一种没有重复副作用却仍然未完成目标的假成功

把完成记录绑定到规范化意图摘要后, 同身份不同意图会显式冲突, 新意图使用新身份后可以完成, 随后的真实同输入生产入口重放保持零新增写入

该结果补充 2026-08-07 对操作身份与意图摘要绑定的观察, 但今天仍是一个受控研究单元, 三次同条件重复不计为三个独立实验, 不提升为候选或发现

## 复验条件

使用真实支持 idempotency key 或 client token 的服务复验同身份不同参数, 记录服务对参数规范化, 忽略字段, TTL 与作用域的实际合同

构造参数语义相同但序列化不同, 默认值变化, 字段顺序变化, 服务端补全字段, 幂等记录过期后复用和并发复用相同 token 的反例

比较全参数摘要, 语义字段摘要和服务端规范化请求身份三种绑定方式的误拒绝, 漏拒绝, 操作数量与验证后有效耗时

## 事实分层

### 已验证事实

- 弱路径错配恢复返回 `already_complete` 且新增写入为 0, 但最终 value 仍为 20, 没有实现新目标 30
- 强路径错配恢复返回 `intent_conflict` 且新增写入为 0, 没有覆盖已有基线状态
- 新 token `task-43` 首次调用写入一次并达到 value 30
- `task-43` 再次经过同一强生产入口返回 `already_complete`, 新增写入为 0
- 独立验证进程三次都重新计算摘要并通过五项机制检查
- 三次正式实验临时目录都在运行结束后清理

### 基于证据的推断

- 幂等完成记录需要回答的是同一意图是否已经完成, 只回答同一身份是否出现过不足以支持完成判断
- 零新增写入既可能表示安全重放, 也可能表示错误跳过, 必须与当前意图和后置条件一起验证
- 同身份不同意图显式冲突比静默返回旧成功更有利于恢复路径重新同步和重新决策

### 未验证事项

- 真实服务如何定义参数相同, 是否包含默认值, 区域, 可选字段和服务端补全字段
- 幂等记录 TTL 到期后身份复用的安全边界
- 并发请求在完成记录尚未持久化时是否可能同时执行
- 业务副作用与幂等记录无法原子提交时的恢复语义
- 完整 `ballast/tools/check.py` 在最终远端树上的结果
