## 研究摘要

本轮研究 DynamoDB TransactWriteItems ClientRequestToken 的十分钟有效期、事务内原子性与事务外 effect A+B 的完成证明边界, 不把同一 publisher 的两份文档或本地合成模型当作线上实证
本轮原始事件来自实际执行的 in-process simulator, 不是 AWS 或外部 effect sink

## 研究问题

首次事务已提交但 ACK 丢失, 相同 token 在 200 秒与 601 秒重放是否有相同去重效果, DynamoDB transaction commit 能否证明外部 A+B 的历史发生、effect-time 授权与当前受保护完成

## 来源依据

- [AWS TransactWriteItems API](https://docs.aws.amazon.com/amazondynamodb/latest/APIReference/API_TransactWriteItems.html), 2026-11-01 核验, token 自首次请求完成后十分钟有效, 过期后同 token 视为新请求, 窗口内不同参数触发 IdempotentParameterMismatch, 原子事务限制在同账户同 Region DynamoDB items
- [AWS DynamoDB transactions](https://docs.aws.amazon.com/amazondynamodb/latest/developerguide/transaction-apis.html), 2026-11-01 核验, transaction 是 all-or-nothing, 重复 token 调用可不新增写入但响应可能不同
- [Google Cloud Spanner transactions](https://docs.cloud.google.com/spanner/docs/transactions), 2026-11-01 核验, 另一 publisher 对事务重试和事务外副作用的类比风险, 不构成 DynamoDB 行为的第二份独立证明
600 秒整点的归属是本模型的边界假设, 不能由本轮文档精确推断服务端计时实现

## 可证伪假设

H1 token response proxy 在外部 effect 缺失或 token 过期重放时仍可能假 COMPLETE
H2 transaction commit proxy 不能证明外部 effect-set、历史授权或当前 membership
H3 full_reference 仅在 exact txn commit、A+B receipts、历史 grant、query coverage、UID/revision 与 protected commit 同时成立时 COMPLETE
H4 unknown 非幂等效果不能盲重试, covered MISS 还需 current permission、完整 attempts、fence 与 sink dedup
若 negative adversarial probe 被参考路径接受为 COMPLETE 或 RETRY_ALLOWED 则推翻 H3/H4

## 路径比较

Token proxy 只看到有限保留期内的请求响应, txn proxy 只看到数据库事务提交, 均未证明事务外效果、历史授权与当前目标谓词
