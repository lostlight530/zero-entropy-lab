## 研究问题

当 effect sink 已提交副作用, 但独立 receipt authority 尚未看到该提交时, receipt service 自己的最新 MISS 是否足以作为 authoritative miss 并允许 production replay

本轮攻击窗口为 `SINK_EFFECT_COMMIT -> receipt relay lag -> RECEIPT_MISS -> recovery decision -> replay`, 并比较仅看 receipt 结果、固定等待、带 applied-through coverage 的 reconciliation 与直接 sink identity 查询

关键问题不是 receipt 查询是否成功, 而是该查询的可见范围是否已经覆盖旧 attempt 可能成功提交的时间或序列边界

## 可证伪假设

- H1: receipt authority 返回 MISS 且查询本身成功时, 可以直接把 prior effect 记为 authoritative miss
- H2: 在 receipt MISS 后固定等待一次再查询, 如果仍为 MISS 就可以安全重试
- H3: receipt MISS 只有在其 applied-through watermark 已覆盖旧 attempt sequence 时才能证明该 attempt 未留下 receipt, 未覆盖时应保持 unknown
- H4: 如果 effect sink 提供 exact effect identity 的权威历史查询, 可以绕过 receipt relay lag 直接解析 prior occurrence
- H5: current permission invalid 只阻止新的 sink attempt, 不阻止只读 prior-effect reconciliation
- H6: completed replay 从 production entry 重入时保持零新增 effect 与零 sink call

H1 的反证条件是 delayed-hit-valid 中 effect 已经存在, receipt service 第一次返回 MISS 但 applied-through 只有 9, 旧 attempt sequence 为 11, weak replay 再产生一次 effect

H2 的反证条件是第二次 receipt query 仍只 applied-through 10, 固定等待路径随后重试产生 duplicate, 而第三次 query 会得到 HIT

H3 的反证条件是 watermark-reconcile 在 coverage 未达到 11 时仍把 MISS 当成 authoritative miss, 或 coverage 达到 11 后仍不能解析真实 MISS

H4 的反证条件是 direct sink exact identity query 在 historical effect 已存在时仍返回 MISS

- effect identity 固定为 `op-99`
- old attempt sequence 固定为 11

## 强反例

第一强反例攻击 receipt service 的 latest MISS 等于 end-to-end authoritative miss

delayed-hit-valid 中 receipt authority 对自身状态的读取是最新的, 但它只 applied-through 9, 而 effect 已由 attempt 11 提交. receipt-only 仍把 MISS 用作重试依据并产生 duplicate

第二强反例攻击固定等待即可获得安全 freshness

fixed-wait-receipt 多等待一次并增加一次 query, applied-through 仍只有 10, 路径仍错误重试. 第三次 receipt 才达到 12 并返回 HIT, 因而等待次数本身不是证明

第三强反例攻击保守 UNKNOWN 会永久阻止必要工作

covered-miss-valid 的 receipt MISS 已 applied-through 12, 明确覆盖旧 attempt 11, watermark-reconcile 随后在 current permission valid 下执行一次必要 effect. uncovered-then-covered-miss 也在第二次 coverage 到 12 后恢复执行

第四强反例使用 direct sink exact identity

当 sink 自身允许权威查询 `op-99` 历史 identity 时, delayed-hit-valid 第一次 direct query 即得到 HIT, 比等待 receipt relay 更少操作且证据更强. 因而 watermark 不是唯一正确实现, 它只是 receipt-only 场景下建立 coverage 的一种方式

## 路径比较

- receipt-only 操作最少, 但跨服务 visibility lag 下会把本地最新 MISS 错当 end-to-end miss, 产生 duplicate effect
- fixed-wait-receipt 增加一次 entry 与 query, 仍没有 coverage proof, 操作更多但结果质量不提高
- watermark-reconcile 在 delayed HIT 中需要 3 次 entry 与 3 次 receipt query 才得到 HIT, 但保留历史正确性; covered MISS 时 1 次 query 即允许必要 effect
- direct-sink-reconcile 如果 exact historical identity query 可用, delayed HIT 中只需 1 次 direct query 且零 replay, 但很多外部 sink 不提供这种能力
- persistent lag 时 watermark path 宁可保持 UNKNOWN 也不把未覆盖旧 attempt 的 MISS 升级为 absence
- current permission invalid 只阻止新的 sink effect, 不阻止只读 receipt reconciliation
- 本地 Python 耗时不外推真实系统性能, 有效成本使用 entries、receipt_queries、direct_queries、sink_calls 与最终证据质量比较

## 暂时结论

证据状态为观察

本轮支持: authority source 自身的 latest read 不等于对另一个系统历史的完整覆盖. 当 receipt authority 与 effect sink 没有共享原子提交或等价可见性边界时, negative receipt evidence 需要额外证明它已经覆盖旧 attempt 可能成功提交的窗口

receipt MISS + applied-through behind attempt 应保持 UNKNOWN, 而不是 authoritative miss

固定 sleep、固定 retry 次数或查询成功都不能替代 coverage proof

如果 sink 提供 exact historical effect identity 的权威查询, 直接 sink reconciliation 可以比 receipt relay 更强; 如果没有, receipt watermark、outbox sequence、commit witness 或等价 coverage boundary 才能把 negative evidence 升级为可执行依据
