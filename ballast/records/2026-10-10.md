## 研究摘要

One bounded deterministic experiment tests CronJob schedule observation, Job presence and Job terminal status against exact external effect completion. Eighteen scenarios and four paths produce 72 decisions. A separately structured verifier checks all 72 decisions. No live Kubernetes, external sink or non-idempotent action was executed.

## 研究问题

Can lastScheduleTime, an existing Job or a terminal Job prove that a particular scheduled occurrence produced the exact authorized external effects on the correct target incarnation and that the task predicate is currently satisfied.

## 来源依据

Checked on 2026-10-10 Asia/Shanghai: [Kubernetes CronJob documentation](https://kubernetes.io/docs/concepts/workloads/controllers/cron-jobs/) and [CronJob API reference](https://kubernetes.io/docs/reference/kubernetes-api/batch/cron-job-v1/).

The official docs describe approximate Job creation, possible duplicate or missing Jobs, the scheduled-timestamp annotation for Kubernetes 1.32+, Forbid/Replace concurrency policies, missed schedules and configurable Job history limits. The API reference separately defines lastScheduleTime and lastSuccessfulTime. These are one publisher lineage and do not prove any external effect or local cluster execution.

## 可证伪假设

H1 lastScheduleTime proves task completion. H2 Job existence proves completion. H3 Job Complete proves completion. H4 exact schedule identity, prior-effect coverage, historical authorization, target incarnation, effect membership, current permission and postcondition checks reject modeled false completion.

H1 fails if schedule is observed but no effect exists. H2 fails if a Job exists without effects. H3 fails if a completed Job has unknown external effects. H4 fails if the bounded reference oracle accepts any modeled invalid completion.

## 实验设计

Compare last-schedule-only, job-presence-only, job-terminal-only and full-integrity on the same primitive fields. Full-integrity is the modeled task-contract reference, checking exact schedule and UID binding, receipt coverage, historical authorization, duplicate occurrence, required effect membership, current permission only when new effects remain, and current postcondition. Unknown non-idempotent effects are never retried.

The producer and separately structured verifier executed in the JavaScript V8 tool runtime. The verifier reconstructs expected labels from primitive fields without calling the producer decision function. Both scripts are Node-compatible but standalone Node CLI execution was NOT_EXECUTED.
