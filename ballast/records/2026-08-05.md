# Ballast 日记录 2026-08-05

类型: 每日专题
主题: 验证后替换中的发布字节绑定

## 研究问题

候选产物通过独立验证后、最终发布前仍可被同名替换时, 只保存路径和验证成功状态能否证明最终发布内容正确, 摘要绑定发布如何影响安全停止、恢复与重放.

## 来源依据

查询日期为 2026-08-05.

- [MITRE CWE-367 Time-of-check Time-of-use Race Condition](https://cwe.mitre.org/data/definitions/367.html) 当前条目说明资源在检查与使用之间发生变化会使检查结果失效, 并建议缩短间隔、使用原子操作或在使用后复核实际结果.
- [SLSA Build Verifying artifacts](https://slsa.dev/spec/v1.2/verifying-artifacts) 当前批准页面要求验证声明的 subject 与实际产物摘要匹配, 用于确认来源声明确实适用于被消费的那个产物.
- [Python os.replace](https://docs.python.org/3/library/os.html#os.replace) 当前标准库文档说明成功替换在满足平台与同文件系统条件时是原子操作, 跨文件系统可能失败.

MITRE 描述检查与使用分离的失败机制, SLSA 提供产物摘要绑定原则, Python 文档提供受控实验的最终替换原语. 三者不证明所有文件系统、网络存储或发布服务具有相同原子性和持久性.

## 可证伪假设

- H1: 只要候选路径曾通过独立验证, 后续发布命令退出 0 且目标文件存在, 就可以确认发布完成.
- H2: 可变路径名不能承载验证身份. 发布器需要把验证结果绑定内容摘要与任务语义, 在使用前确认实际字节仍匹配, 用同一已验证字节完成最终替换, 再从目标回读验证.

如果候选被替换后按路径发布仍得到最初的有效字节, 摘要绑定路径无法在写入前拒绝变化, 或恢复后不能保持最终摘要和零写入重放, H2 被推翻.

## 控制条件

- 有效候选是 UTF-8 JSON, 状态为 complete, 包含必需身份 A 与值 1.
- 替换候选也是有效 JSON 且状态为 complete, 但 items 为空.
- 候选路径和最终目标路径保持不变, 只改变候选路径映射的字节.
- 初始有效字节的 SHA-256 摘要为 ee59aa5d7079c11192e806cc83b3f000ad258514f19fd40f24ad98487bbf676a.
- 独立验证器检查摘要、JSON 结构、状态、必需身份与重复身份, 不导入发布器实现.
- 正式实验使用 Python 标准库与系统临时目录, 替换和最终提交均使用 os.replace.

## 实验设计

1. 写入有效候选, 从独立进程验证摘要、状态和必需身份 A.
2. 验证退出 0 后, 用原子替换把候选路径指向不含 A 的新字节.
3. 弱路径按候选路径重新打开并复制到最终位置, 记录发布退出状态与目标存在性.
4. 独立验证器从弱路径目标重新计算摘要和语义结果.
5. 摘要绑定路径在发布前读取当前候选字节, 摘要不匹配时不创建目标.
6. 恢复有效候选后, 从同一次读取获得待发布字节, 校验摘要并以临时阶段文件原子替换目标.
7. 从最终目标重新验证, 再重放同一任务并检查新增写入与临时清理.

故障注入位于初始验证完成和按路径重新打开之间, 恢复点位于摘要不匹配的安全停止之后.

## 独立验证

验证器在独立 Python 进程中从目标文件重新读取原始字节, 计算 SHA-256, 解析 JSON 并检查 status、必需身份 A 与重复身份.

验证器不读取发布器的成功布尔值、写入计数或断言, 也不导入发布函数. 它仍与生产器共享 Python JSON 语义、字段合同、摘要算法和同一文件系统, 因此不能代表跨实现或跨存储独立性.

## 强反例

候选路径初始验证退出 0, 后续复制发布也退出 0, 最终文件存在且仍是合法 JSON, status 仍为 complete.

这些弱证据全部成立时, 最终字节已经不是被验证的字节, 摘要改变且必需身份 A 消失. 单独绑定路径、成功状态、文件存在或表层状态都会把错误产物报告为完成.

## 路径比较

| 路径 | 绑定实际字节 | 替换后安全停止 | 有效完成 | 结果质量 |
| --- | --- | --- | --- | --- |
| 验证路径后重新打开 | 否 | 否 | 否 | 发布合法但错误的 JSON |
| 摘要绑定但未恢复 | 是 | 是 | 否 | 正确拒绝且无目标污染 |
| 摘要绑定加原子发布 | 是 | 是 | 是 | 发布预期摘要与必需身份 |
| 完成后先回读再重放 | 是 | 是 | 是 | 零新增写入 |

强路径增加一次发布前摘要比较和一次发布后回读, 有效完成来自验证身份与实际字节一致, 不是更少操作. 单机耗时不用于推断真实发布系统性能.

## 暂时结论

状态为观察.

在本次受控实验中, 验证成功只能证明检查时读到的字节符合条件. 如果发布阶段按可变路径重新打开, 验证与使用可能指向不同内容. 内容摘要与任务语义需要随验证结果传递到发布点, 发布后仍从目标重新确认.

本次为 NOTES.md 的两个既有发现增加验证后替换证据, 但摘要绑定发布机制本身只出现一次, 不升级为新的候选或发现.

## 复验条件

在真实对象存储、制品仓库或网络文件系统中复验, 改变对象版本、条件写入、跨文件系统移动、缓存和读取一致性.

注入发布响应丢失、目标替换竞争、摘要算法配置变化和验证策略更新, 检查恢复器能否区分已生效、未生效与内容冲突. 验证原子可见不等于断电持久的边界.

## 事实分层

### 已验证事实

- 初始候选验证退出 0, 替换后按路径发布仍退出 0 且目标存在.
- 弱路径目标摘要改变并缺少 A, 独立验证退出 1.
- 摘要绑定路径在替换状态下拒绝发布, 写入 0 且目标不存在.
- 恢复路径发布预期摘要和必需身份 A, 完成后重放写入 0.
- 四项机制断言为真, 五个独立验证进程完成, 临时清理通过.

### 基于证据的推断

- 验证记录应携带内容身份, 不能只携带路径、时间或成功标记.
- 发布器应消费被验证的同一字节或不可变对象版本, 并从最终目标重新验证完成条件.

### 未验证事项

- 网络存储、对象版本和缓存层能否提供等价的内容身份与条件提交.
- 原子替换在断电、跨文件系统或多节点观察下的持久性和可见性.
- 摘要算法迁移、策略变更和大文件读取对有效耗时的影响.
