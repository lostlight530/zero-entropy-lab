## 研究问题

Parent Workflow COMPLETED 或 ChildWorkflowExecutionStarted 已记录，能否证明两个非幂等 external effects 均发生、在 effect-time 合法授权且满足当前 A+B task predicate

ABANDON、REQUEST_CANCEL 和 TERMINATE 三种 Parent Close Policy 是否允许以 lifecycle 信号替代 exact child run、effect identity、historical authorization、current completion 和 prior-effect query

## 来源依据

官方文档核验日期为 2026-10-25，外部合同只支持各自有限语义，不是本地实验或真实事故记录

- [Temporal Child Workflows](https://docs.temporal.io/child-workflows) 说明 parent 必须等待 child spawn，parent closed 时依据 child Parent Close Policy 传播取消或终止，parent Continue-As-New 不继承 ongoing children
- [Temporal Go SDK child workflows](https://github.com/temporalio/documentation/blob/main/docs/develop/go/workflows/child-workflows.mdx) 区分 StartChildWorkflowExecutionInitiated 与 ChildWorkflowExecutionStarted，异步 child 必须在 parent 结束前确认 started event，默认 close policy 为 TERMINATE
- [Temporal cancellation and termination](https://github.com/temporalio/documentation/blob/main/docs/encyclopedia/workflow/cancellation-and-termination.mdx) 区分 cancellation request 与 termination，不能由请求推断外部 cleanup 完成
- [AWS Step Functions service integration](https://docs.aws.amazon.com/step-functions/latest/dg/connect-to-resource.html) 作为独立 publisher 的不同产品类比，.sync task abort 时下游 cancellation 为 best effort，不是 Temporal 具体实现的独立佐证

前三条为 Temporal 同一 publisher，AWS 仅支持跨产品控制平面与外部 effect 分离的动机

## 可证伪假设

H1 parent terminal 即 COMPLETE，若 parent closed 而 child 未 started 或 effect 未发生则被证伪

H2 child started 数量等于 required member 数量即 COMPLETE，若 A+B started 但 effect journal 为空或 A+A 冒充 A+B 则被证伪

H3 full_reference 仅在 exact child/run/effect identity、historical authorization、当前唯一成员集合、protected guard 和时序同时满足时才报告 COMPLETE

H4 未知非幂等效果只有在 authoritative MISS 覆盖 exact prior attempt、当前 permission 有效且 protected current guard 成立时才可 RETRY_ALLOWED

任何 duplicate、extra effect、错误授权、MISS conflict 或 TOCTOU 仍被 full_reference 接受为 COMPLETE 都推翻 H3 的模型正确性

## Action-integrity state

- Current permission 仅决定新的 effect，不能追溯否定已获合法授权的历史 effect
- Historical occurrence 使用 synthetic effect journal，parent terminal 和 child started 不是 external receipt
- Historical effect-time authorization 独立验证 approval scope、revocation 与 effect timestamp
- Prior-effect HIT、authoritative MISS 与 UNKNOWN 分开，MISS 还需精确身份、scope、水位、retention 与 lifecycle
- Current completion 要求 current exact A+B、revision、incarnation、member states 与 protected commit
- Temporal order 分开 child start、parent close、effect、read 和 commit
- Verifier independence 仅有实现分离，缺乏独立 authority 和 semantic contract

## 暂时结论

PARTIAL / BOUNDED_SUPPORTED_WITH_LIMITS

Temporal 文档将 parent close、child started 与 child lifecycle 分开，本地模型进一步展示这些 control-plane signals 不能替代 exact historically authorized effect 和 protected current completion

ABANDON 可以保留 child lifecycle，REQUEST_CANCEL 只代表请求，模型中观察到的 post-close effect 不代表已经在真实 Temporal server 上复现

Reference 仍依赖 synthetic journal、approval、query 和 guard，不能晋升为真实系统结论
