# Ballast 日记录 2026-08-02

类型: 每日专题
主题: 缓存读取中的写入代际验证

## 研究问题

云端对象写入完成后, 验证读取经过仍保存旧表示的缓存时, 普通读取、请求侧绕缓存指令与绑定写入代际的读取能否正确判断当前结果.

## 来源依据

查询日期为 2026-08-02.

- [RFC 9111 HTTP Caching](https://www.rfc-editor.org/rfc/rfc9111.html) 发布于 2022-06, 规定新鲜缓存响应可以直接复用, no-cache 请求指令表示客户端偏好在复用前成功验证源站, 并定义了缓存验证与旧响应处理边界.
- [Cloud Storage consistency](https://docs.cloud.google.com/storage/docs/consistency) 更新于 2026-07-22, 说明对象直接读后写具有强一致性, 但公开可缓存对象可能在缓存寿命内返回旧版本, 且请求侧用于避开缓存的 Cache-Control 会被忽略. 文档建议用代际前置条件锁定正确对象版本.
- [Amazon S3 data consistency model](https://docs.aws.amazon.com/AmazonS3/latest/userguide/Welcome.html#ConsistencyModel) 查询时未显示独立更新日期, 说明直接对象 PUT 和 DELETE 后的读取具有强一致性, 单键更新原子可见.

RFC 给出通用 HTTP 缓存语义, Google Cloud 给出缓存层削弱端到端可见性的供应商边界, AWS 给出直接对象路径的对照. 三者不支持把所有云端读取统一视为最终一致或统一视为强一致.

## 可证伪假设

- H1: 写入后只要读取返回成功且载荷符合期望, 就足以证明本次写入代际已经可见.
- H2: 验证必须识别读取路径并绑定预期写入代际. 普通缓存读取或仅发送请求侧绕缓存指令可能返回旧表示, 相同载荷也不能替代代际与意图核对.

如果请求侧指令总能取得当前表示, 或只比较载荷不会接受错误代际, H2 被推翻.

## 控制条件

- 权威对象从代际 1 更新到代际 2, 缓存仍保存代际 1.
- 普通读取和请求侧 no-cache 路径都由同一旧缓存表示响应, 代际绑定路径读取权威代际 2.
- 内容反例让代际 1 与代际 2 使用相同载荷, 但操作意图不同.
- 独立验证器只读取观测对象、期望对象和验证模式, 不读取缓存实现、生产器断言或路径标签.
- 实验使用 Python 标准库, 文本显式使用 UTF-8.

## 实验设计

1. 普通缓存路径读取代际 1, 使用任务、意图、载荷与代际约束验证.
2. 请求携带 no-cache, 模拟服务忽略请求侧绕缓存指令, 再读取相同旧表示.
3. 读取明确绑定的代际 2, 使用相同完整约束验证.
4. 强反例让旧代际和当前代际载荷相同, 分别使用只比内容与绑定代际的验证器.
5. 在独立 Python 子进程中执行五次验证, 最后检查临时目录清理.

故障注入位于写入完成后的验证读取路径, 不改变权威对象本身.

## 原始观测

| 路径 | 读到代际 | 验证模式 | 退出状态 | 判断 |
| --- | ---: | --- | ---: | --- |
| 普通缓存读取 | 1 | 任务、意图、载荷、代际 | 1 | 拒绝旧表示 |
| 请求侧 no-cache 被忽略 | 1 | 任务、意图、载荷、代际 | 1 | 拒绝旧表示 |
| 绑定代际读取 | 2 | 任务、意图、载荷、代际 | 0 | 有效完成 |
| 同载荷旧代际 | 1 | 只比任务与载荷 | 0 | 错误接受 |
| 同载荷旧代际 | 1 | 任务、意图、载荷、代际 | 1 | 拒绝错误代际 |

五项机制断言全部为真, 验证读取 5 次, 验证后有效耗时 421.173 毫秒, 临时目录清理通过.

首次环境尝试因默认系统临时根在当前沙盒中不可写而失败, 没有产生实验观测. 正式重验在显式预置的系统临时目录中完成, 本日报只采用重验结果.

## 独立验证

独立 Python 进程从磁盘重新读取观测对象与期望对象. 完整模式核对任务标识、意图、载荷和代际, 内容模式只核对任务与载荷以构造反例.

验证器不读取生产器的缓存命中标志、请求头处理结果、路径成功布尔值或预期退出码. 它仍与生产路径共享 JSON 字段合同和 Python 运行时.

## 强反例

代际 1 与代际 2 的载荷都为 same-result, 但意图分别为 old-same 与 current-same. 只比较内容的验证器退出 0 并报告有效, 实际读取仍停留在旧代际.

请求已经携带 no-cache 也不能推翻该反例, 因为具体服务可能忽略请求侧避缓存指令. 成功响应与正确载荷仍不足以证明目标写入已经可见.

## 路径比较

| 路径 | 防旧缓存 | 绑定写入代际 | 有效完成 | 验证读 | 结果质量 |
| --- | --- | --- | --- | ---: | --- |
| 普通缓存读取 | 否 | 是 | 否 | 1 | 正确拒绝, 但无法确认完成 |
| 请求侧绕缓存指令 | 不保证 | 是 | 否 | 1 | 服务忽略指令时仍读旧值 |
| 只比较载荷 | 否 | 否 | 否 | 1 | 同载荷旧代际产生假成功 |
| 绑定代际的权威读取 | 是 | 是 | 是 | 1 | 确认当前写入 |

绑定代际路径没有减少读取次数, 改进来自更强的读取位置和验证合同. 单机耗时不用于推断真实云端延迟.

## 暂时结论

状态为观察.

本次受控实验中, 端到端验证强度由最弱读取层决定. 直接存储的强读后写保证不能自动跨越公开缓存, 请求侧绕缓存指令也不是通用完成证明. 验证读取需要定位权威路径并绑定预期代际与意图.

该观察与 8 月 1 日的远端回读相连, 但改变了故障位置和验证方式. 它扩展适用边界, 不单独升级候选或长期发现.

## 复验条件

使用真实对象存储与 CDN 组合复验, 分别测试成功写入响应、响应丢失、缓存过期、缓存重验证、版本化读取和权限变化.

构造源站代际已推进但版本化读取不可用、多个缓存节点新旧交错、代际元数据与正文来自不同请求的反例. 比较等待重试、源站读取与版本绑定读取的质量和有效耗时.

## 事实分层

### 已验证事实

- 普通缓存与被忽略请求指令路径都返回代际 1, 完整验证拒绝.
- 绑定代际路径返回代际 2, 完整验证接受.
- 同载荷旧代际通过内容验证, 但被意图与代际验证拒绝.
- 五项机制断言为真, 五次独立验证完成, 临时目录清理通过.

### 基于证据的推断

- 完成验证应记录所读层级和对象代际, 不能只记录读取成功或载荷摘要.
- 供应商宣称的强一致性需要按具体 API 与缓存边界解释, 不能自动推广到所有访问 URL.

### 未验证事项

- 真实 CDN 的刷新、重验证与多节点可见顺序.
- 版本标识不可用时等待和重复读取能否提供足够强的替代证据.
- 真实对象服务中响应丢失与缓存旧读同时发生时的有效耗时.

## 指标

- 有效完成: 绑定代际的权威读取为是, 其他三种完成判定为否.
- 重放一致与幂等通过: 本实验只读验证没有新增写入, 同一最终状态重复验证结果一致.
- 中断恢复: 不适用, 故障位于写后验证读取.
- 假成功: 内容相同但代际错误路径 1 次.
- 无效操作: 正式机制实验写入 0, 验证读取 5.
- 重试次数: 正式机制实验 0.
- 人工介入: 正式机制实验 0, 环境准备失败与重验分开记录.
- 结果质量差异: 内容验证接受旧代际, 完整验证拒绝旧代际并接受当前代际.
- 验证后的有效耗时: 421.173 毫秒.
