# Ballast 日记录 2026-08-07

类型: 每日专题
主题: 生产入口重放中的代际围栏

## 研究问题

任务读取旧代际后被中断, 当前状态由另一操作推进, 迟到任务恢复并重放时, 无条件生产入口与绑定当前代际和完成记录的生产入口能否避免旧结果覆盖与重复副作用.

## 来源依据

查询日期为 2026-08-07.

- [RFC 9110 HTTP Semantics](https://www.rfc-editor.org/rfc/rfc9110.html) 发布于 2022-06, 规定 `If-Match` 等前置条件可用于状态变更请求以防止并行客户端造成丢失更新, 条件失败时不得执行原方法, 除非能够确认相同变更已经生效.
- [Google Cloud Storage Request preconditions](https://docs.cloud.google.com/storage/docs/request-preconditions) 访问于 2026-08-07, 说明 generation-match 前置条件只允许目标资源仍处于预期代际时执行修改, 用于防止重复请求和独立进程之间的竞态与数据损坏.
- [Azure Blob Storage Manage concurrency](https://learn.microsoft.com/en-us/azure/storage/blobs/concurrency-manage) 访问于 2026-08-07, 说明对象写入会更新 ETag, 客户端使用原 ETag 和 `If-Match` 执行乐观并发控制, 当前 ETag 已变化时返回 412 并要求重新读取当前对象.

RFC 给出通用条件请求语义, Google Cloud 与 Azure 给出两个独立对象存储实现. 三者支持在提交点核对当前代际, 但不证明所有系统都提供可持久查询的完成记录或相同的响应丢失语义.

## 可证伪假设

- H1: 迟到任务只要生产入口返回成功且最终状态文件合法, 就可以认为恢复和重放安全.
- H2: 生产入口必须在每次提交前核对当前代际, 并把完成记录绑定操作身份、意图摘要和结果代际. 旧代际任务应被拒绝, 已完成的同输入重放应由同一生产入口识别并零写入跳过.

如果无条件路径不会覆盖当前结果或产生重复副作用, 或强路径无法拒绝旧任务和保持有效任务重放零写入, H2 被推翻.

## 控制条件

- 初始状态为 generation 1, value 10.
- 当前操作 `op-current` 基于 generation 1 写入 value 20, 推进到 generation 2.
- 迟到操作 `op-stale` 仍绑定 generation 1, 目标 value 11.
- 有效操作 `op-valid` 绑定 generation 2, 目标 value 21.
- 三个操作的意图摘要由独立控制夹具中的操作身份、预期代际和值计算.
- 独立验证器从控制夹具、弱路径观测和强路径观测重新计算结构、身份集合、计数与 SHA-256 意图摘要.
- 正式实验只使用 Python 标准库和系统临时目录, 所有文本显式使用 UTF-8.

## 实验设计

1. 初始化两份独立状态, 分别供弱生产入口与强生产入口使用.
2. 两条路径都先让 `op-current` 通过各自生产入口把状态推进到 generation 2 和 value 20.
3. 模拟 `op-stale` 在读取 generation 1 后中断, 当前操作完成后再恢复.
4. 弱路径让迟到操作和其同输入重放都重新经过无条件生产入口.
5. 强路径让迟到操作和其同输入重放都重新经过代际条件生产入口.
6. 强路径再执行 `op-valid`, 随后让同一操作重新经过同一生产入口.
7. 独立 Python 进程回读控制夹具和两条最终状态, 核对内容、结构、身份集合、摘要、写入计数和重复副作用.
8. 记录验证后有效耗时并确认临时目录自动清理.

故障注入位于旧任务读取基准之后和提交之前, 重放不是重复调用只读验证器, 而是重新调用原生产入口.

## 原始观测

| 路径 | 迟到操作首次 | 迟到操作重放 | 有效操作首次 | 有效操作重放 | 最终代际 | 最终值 | 副作用写入 |
| --- | --- | --- | --- | --- | ---: | ---: | ---: |
| 无条件生产入口 | applied | applied | 未执行 | 未执行 | 4 | 11 | 3 |
| 代际条件生产入口 | stale_precondition | stale_precondition | applied | already_complete | 3 | 21 | 2 |

弱路径中的 `op-stale` 两次都返回 applied, 最终状态文件结构合法, 但当前值从 20 回退到旧值 11, `op-stale` 在副作用日志中出现两次.

强路径两次拒绝旧代际操作, 迟到重放新增写入为 0. 有效操作首次写入 1 次, 同输入再次经过同一生产入口时返回 already_complete, 新增写入为 0.

五项机制断言在三次完整运行中均为真, 独立验证进程每次 1 个, 验证后有效耗时分别为 548.303 毫秒、572.445 毫秒和 598.125 毫秒, 系统临时目录均已清理.

## 独立验证

验证器独立读取控制夹具、弱路径观测和强路径观测, 不导入生产入口实现, 不读取生产器断言或成功布尔值.

验证器重新计算三个操作的 SHA-256 意图摘要, 检查弱路径重复身份计数, 检查强路径最终内容、代际、唯一操作身份集合和每个身份恰好一次.

验证器仍与生产路径共享 JSON 字段合同、Python 运行时、SHA-256 定义和同一文件系统, 未覆盖真实网络并发、存储复制与不可逆副作用.

## 强反例

无条件生产入口对迟到操作首次和重放都返回 applied, 两次调用均正常结束, 最终状态文件存在且可解析.

这些表面成功条件全部成立时, value 20 已被旧值 11 覆盖, generation 从 2 推进到 4, 同一 `op-stale` 产生两条副作用记录.

因此生产入口成功、文件存在和脚本结束不能证明恢复安全, 只读验证器重复读取不产生写入也不能替代真实生产入口重放.

## 路径比较

| 路径 | 提交前核对当前代际 | 完成记录绑定意图 | 迟到覆盖 | 重复副作用 | 有效完成 |
| --- | --- | --- | --- | --- | --- |
| 无条件生产入口 | 否 | 否 | 是 | 是 | 否 |
| 只重复只读验证 | 不适用 | 不适用 | 未攻击 | 未攻击 | 不能证明 |
| 代际条件入口拒绝旧任务 | 是 | 是 | 否 | 否 | 旧任务安全停止 |
| 同一入口完成后重放 | 是 | 是 | 否 | 否 | 是, 新增写入 0 |

强路径增加当前代际读取、完成记录核对和最终独立验证, 改进来自阻止错误提交与重复写入, 不是减少首次操作数量.

## 暂时结论

状态为观察.

本次受控实验中, 迟到任务重新经过无条件生产入口会覆盖当前状态并在重放时复制副作用. 在同一生产入口中绑定当前代际、操作身份、意图摘要和结果代际, 可以拒绝旧任务, 并让已完成的有效操作同输入重放保持零写入.

该观察为现有当前状态绑定发现增加真实生产入口重放证据, 同时纠正 2026-08-06 仅重复调用验证器所能支持的证据边界. 本机制只在本日受控模型中出现一次, 不建立新的候选或发现.

## 复验条件

使用真实支持比较交换、ETag、对象 generation 或条件引用更新的服务复验, 注入响应丢失、并行写入、延迟读和权限变化.

构造当前代际相同但意图不同、完成记录存在但目标已被后续合法写入推进、操作身份重复使用和完成记录丢失的强反例.

比较严格拒绝、重新同步后重算和确认已生效三种恢复路径的结果质量、写入数量与验证后有效耗时.

## 事实分层

### 已验证事实

- 弱生产入口两次接受旧代际操作, 最终值回退到 11, 同一操作产生两条副作用记录.
- 强生产入口两次拒绝旧代际操作, 迟到重放新增写入为 0.
- 有效操作首次通过强生产入口写入 1 次, 同输入重放返回 already_complete 且新增写入为 0.
- 独立验证器重新计算摘要并确认强路径最终身份集合为 `op-current` 和 `op-valid`, 每项恰好一次.
- 五项机制断言为真, 独立验证完成, 临时目录已清理.

### 基于证据的推断

- 重放证据需要覆盖生产提交边界, 只读验证器重复运行只能证明验证本身无副作用.
- 代际前置条件负责阻止旧任务提交, 完成记录负责识别相同意图已经完成, 两者不能互相替代.
- 完成记录只有在仍绑定当前结果代际和内容时才能支持跳过, 后续状态推进后应重新评估.

### 未验证事项

- 真实远端服务中条件写入、完成记录和业务副作用能否共享原子可见边界.
- 完成记录查询延迟、过期或丢失时的安全恢复策略.
- 多个生产者并发使用相同操作身份时的冲突处理.
- 不可逆外部副作用中的真实重复成本与补偿边界.

## 指标

- 有效完成: 强路径有效操作为是, 弱路径和旧任务强路径为否.
- 重放一致与幂等通过: 有效操作重新经过同一强生产入口后新增写入 0.
- 中断恢复: 旧任务在读取 generation 1 后中断, generation 2 已生效后恢复并被拒绝.
- 假成功: 弱路径 2 次 applied, 最终覆盖当前结果并重复副作用.
- 无效操作: 弱路径 2 次旧任务写入, 强路径 0 次旧任务写入.
- 重试次数: 迟到任务重放 1 次, 有效任务重放 1 次.
- 人工介入: 正式机制实验 0.
- 结果质量差异: 弱路径最终值 11 且重复 `op-stale`, 强路径最终值 21 且操作身份各一次.
- 验证后的有效耗时: 首次 548.303 毫秒, 两次同条件复验分别为 572.445 毫秒和 598.125 毫秒.
