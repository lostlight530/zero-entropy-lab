## 研究问题

当 producer 与 verifier 共用同一 approval relevant projection 时, 如果该 projection 漏掉真实授权依赖, 两者是否会共同 PASS 并把 stale unauthorized effect 误记为有效完成

关键窗口为 `APPROVE action+uid+policy+environment -> environment changes -> producer compares action+uid+policy -> EFFECT -> verifier repeats the same incomplete projection`

## 来源依据

查询日期为 2026-09-05

- [NIST SP 800-162](https://csrc.nist.gov/pubs/sp/800/162/upd2/final) 说明授权可以依赖 subject、object、requested operation 与 environment conditions, 属性管理还需要 validation、integrity、provenance 与 change history. 本轮只采用有限命题: environment 可以是真实授权依赖, 漏掉它的 projection 不能证明批准仍适用
- [NASA Software Assurance and Software Safety Standard](https://standards.nasa.gov/standard/nasa/nasa-std-87398) 说明 Software Assurance 与 Independent Verification and Validation 采用系统化方法贯穿生命周期. 本轮只采用有限命题: verification independence 用于降低开发与验证共享假设导致的共同遗漏风险

两个来源来自不同权威体系. 外部资料不证明本轮 effect 数量或具体 PASS 结果

## 可证伪假设

- H1: producer 与 verifier 对同一 projection 结果一致即可证明有效完成
- H2: action、UID 与 policy 已足够, environment 变化不会改变 approval applicability
- H3: verifier 从 raw authority state 独立重建完整合同能识别共享漏字段导致的共同失效
- H4: complete projection 拒绝真实依赖变化, 但不因无关 metadata 单独停止
- H5: whole-global revision 保守安全但会 over-fence 无关 metadata
- H6: completed replay 不能替代 omitted-dependency production replay

## 控制条件

- approval contract 固定为 action=`mark`, uid=`uid-A1`, policy=`standard`, environment=`normal`
- 初始 authority 为 uid-A1、standard、normal、note n0、revision 10
- environment-risk-high 只改变 environment 并推进 revision 11
- policy-restricted 只改变 policy 并推进 revision 11
- irrelevant-metadata 只改变 note 并推进 revision 11
- incomplete-projection 比较 action、UID、policy, 明确省略 environment
- complete-projection 比较 action、UID、policy、environment
- global-revision 比较 whole-global revision
- shared verifier 复用 incomplete projection, 不读取 environment
- raw verifier 不导入 producer, 从 raw uid、policy、environment 重建 approval applicability
- completed replay 从已持久化 completion 重新进入 production entry
- 夹具只使用 Python 标准库与系统 awk

## 实验设计

1. 三条 production 路径运行 normal
2. 只改变 environment, 攻击漏字段 projection
3. 只改变 policy, 作为 included dependency 控制
4. 只改变无关 note metadata, 检查 global over-fencing
5. completed replay 检查新增 effect 为 0
6. producer 保存 raw authority fields、projection match、effect、unauthorized 与 event order
7. producer 完整运行三次并比较 TSV SHA-256
8. shared verifier 复用 incomplete projection
9. raw verifier 从 raw authority fields 重建合同
10. awk 第二验证复核关键反例
11. 三个 Python 文件执行 `py_compile`

shared verifier 三次均返回 `SHARED_VERIFIER_PASS 15`, 但它明确共享漏字段 schema, 因而该 PASS 是被攻击对象而不是有效完成证据

## 独立验证

shared verifier 与 producer 没有语义独立性, 因为它复用同一三字段 projection

raw verifier 与 producer 为独立文件, 不读取 producer 保存的 projection_match 或 success boolean 作为授权真值, 而从 raw uid、policy、environment 重建批准合同

raw verifier 独立确认 15 个组合唯一完整、omitted environment 产生 unauthorized effect、complete projection 阻止 environment 与 policy drift、global revision over-fence 无关 metadata、normal 结果正确、completed replay 零新增 effect

三次 raw verifier 均 PASS, awk 三次 PASS, producer、shared verifier、raw verifier 均 py_compile PASS

raw verifier 仍共享 scenario vocabulary、TSV 字段约定与同一运行环境, 不构成完全外部 IV&V

## 强反例

批准时 environment=normal, 恢复前只把 environment 改为 high-risk. UID 与 policy 均保持批准值, incomplete producer 真实 match 并产生 1 次 unauthorized effect, shared verifier 因复用同一 projection 仍 PASS

反方向反例只改变 note metadata. complete projection 的真实依赖均未变化并安全执行, global revision 却额外停止

policy-restricted 控制中 incomplete projection 正确停止, 证明失败来自 environment omission, 不是该路径无条件执行

## 路径比较

- incomplete-projection 字段更少但会在漏依赖时产生 stale unauthorized effect
- shared verifier 增加验证步骤却没有增加独立语义覆盖
- raw verifier 能阻止把共同失效报告为有效完成, 但不能撤销已发生的 stale effect
- complete projection 在 effect 前阻止相关 drift, 优于仅靠事后 verifier 发现错误
- global revision 在相关 drift 中安全, 但无关 metadata 下额外 conflict

## 暂时结论

证据状态为观察

relevant projection completeness 不能由 producer 与 verifier 对同一 projection 的一致结果证明. 两者共享错误依赖集合时可以共同失效

verifier independence 至少需要一个不依赖 producer 投影结果的 raw fact 路径, 从 task semantics 与 authority state 重建关键约束. 但事后 verifier 不能替代 effect 前 dependency-complete protected authorization boundary

现行 METHOD 已覆盖 raw fact verification、共享假设披露与 relevant projection completeness, 本轮不修改 METHOD

## 事实分层

### 已验证事实

- omitted environment 场景中 incomplete projection match 并产生 1 次 unauthorized effect
- shared verifier 复用同一漏字段 projection 后仍 PASS
- raw verifier 从 raw authority state 能识别上述共同失效
- complete projection 阻止 environment 与 policy 两类相关 drift
- irrelevant metadata 中 complete projection 正常执行, global revision 额外停止
- completed replay 三条路径均零新增 effect
- 三次 trace SHA 一致, shared verifier 3/3 PASS, raw verifier 3/3 PASS, awk 3/3 PASS, py_compile PASS

### 基于证据的推断

- producer 与 verifier 一致不能证明 dependency set 完整
- 文件分离不等于语义独立, verifier 仍可能共享同一 contract omission
- raw authority verification 能提高 common-mode omission 的发现能力但不能撤销 stale effect

### 未验证事项

- 尚未在真实 ABAC、HITL 或 policy engine 复现
- 尚未验证 credential、time、location 等其他 dependency omission
- 尚未验证不同实现但共享错误规范时的发现率
- 尚未建立跨服务 authorization authority 与 effect sink 的原子 compare-and-effect
