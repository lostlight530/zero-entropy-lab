## 研究摘要

以受控合成 CDC 状态机研究 PostgreSQL logical slot 在 crash 后可能重放已发送变更时, replication LSN checkpoint 与 delivery signal 能否证明下游 A+B 不可逆效果及当前完成, 不宣称真实 PostgreSQL 或 Debezium 实验

## 研究问题

slot checkpoint 已达到 commit LSN, 或 CDC event 已送达, 是否足以证明同一 slot incarnation、事务身份与下游 effect A+B 的历史发生、effect-time authorization、权威 prior 查询及当前受保护完成

## 来源依据

- [PostgreSQL 18 Logical Decoding Concepts](https://www.postgresql.org/docs/18/logicaldecoding-explanation.html), 2026-11-03 核验, slot state checkpoint 持久化边界使 crash 后可能再次发送部分变更, client 必须容忍 duplicate
- [PostgreSQL 18 Streaming Replication Protocol](https://www.postgresql.org/docs/18/protocol-replication.html), 2026-11-03 核验, logical START_REPLICATION 与 confirmed_flush_lsn 的起点关系, 不承诺外部 sink effect
- [Debezium PostgreSQL connector source documentation](https://github.com/debezium/debezium/blob/main/documentation/modules/ROOT/pages/connectors/postgresql.adoc), 2026-11-03 核验, 异常恢复可能重新发出 change events, 这是独立 publisher 的 connector 合同而非本轮实测
- [Debezium JDBC sink documentation](https://github.com/debezium/debezium/blob/main/documentation/modules/ROOT/pages/connectors/jdbc.adoc), 2026-11-03 核验, at-least-once sink 应显式使用幂等 upsert, 不能推广到所有非幂等外部效果

## 强反例

- checkpoint 已达到 LSN 120 但 sink A+B receipts 均不存在, checkpoint_proxy COMPLETE, full_reference STOP_UNKNOWN
- crash 后已记录 A 而 B 缺失, checkpoint/delivery proxies COMPLETE, full_reference RECONCILE
- 同名 slot 不同 generation 或同 LSN 不同 XID, 弱路径仍 COMPLETE, reference RECONCILE
- A+B 被 A+C 同数替换、额外 C 或 duplicate A, 弱路径仍 COMPLETE, reference RECONCILE
- positive sink receipt 与 covered MISS 同时存在, reference EVIDENCE_CONFLICT
- future watermark、uncovered attempt 3、expired retention、non-atomic guard、numeric string revision, reference STOP_UNKNOWN 或 RECONCILE, 不因字段存在而完成
- 当前 permission 撤销不追溯否定此前合法且已满足完成谓词的历史 effect, 但禁止无权限的新 retry

## 路径比较

checkpoint_proxy 仅检查 LSN progress, delivery_proxy 仅检查事件送达, 两者都缺乏 downstream effect provenance、historical grant、exact A+B membership 和 protected completion
full_reference 使用更多合成 witness 才给出 COMPLETE, 依赖 authored query/guard authority, 并未证明真正跨数据库和 sink 的 atomicity 或独立事实
