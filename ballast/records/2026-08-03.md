# Ballast 日记录 2026-08-03

类型: 每日专题
主题: 集合变化中的跨页快照完整性

## 研究问题

远端集合在多页读取之间发生插入或排序键变化时, 偏移分页、普通游标与绑定初始快照的页令牌能否保持结果完整, 只比较最终数量是否会产生假成功.

## 来源依据

查询日期为 2026-08-03.

- [GitHub Using pagination in the REST API](https://docs.github.com/en/rest/using-the-rest-api/using-pagination-in-the-rest-api) 当前页面说明分页响应只返回集合子集, 客户端应沿 Link 关系请求后续页面, 端点可能使用 page、before、after 或 since. 文档给出继续读取方式, 但没有给出跨页共享快照的通用保证.
- [Google AIP-158 Pagination](https://google.aip.dev/158) 创建于 2019-02-18, 最近可见变更为 2025-07-08. 它要求页令牌不透明、后续请求除页大小外保持参数一致, 并允许单页返回少于请求数量的结果. 令牌被限定为继续位置, 规范没有要求所有实现绑定集合快照.
- [PostgreSQL 18 Transaction Isolation](https://www.postgresql.org/docs/current/transaction-iso.html) 查询时为当前稳定文档. 它说明 Read Committed 下连续查询可以看到不同快照, Repeatable Read 才让连续查询共享首个语句建立的稳定视图, 同时仍保留重试和更高层业务一致性边界.

GitHub 文档提供现实分页接口, AIP-158 提供 API 设计合同, PostgreSQL 文档提供跨读取快照的独立对照. 三者共同支持区分页位置与快照身份, 但不证明任意 API 都能提供可导出的稳定快照.

## 可证伪假设

- H1: 只要客户端跟随下一页链接或游标并最终取得预期数量, 聚合结果就完整.
- H2: 页位置不能单独证明跨页集合一致. 偏移可能因前置插入产生重复和遗漏, 普通游标可能因未读项目排序键跨过游标而遗漏, 绑定初始快照并验证身份集合可以保持本次读取完整.

如果偏移结果数量正确时身份也完整, 普通游标在排序键变化后仍返回基线全集, 或快照路径不能重放同一身份序列, H2 被推翻.

## 控制条件

- 初始集合按 rank 降序为 A、B、C、D, 页大小为 2.
- 基线身份序列由读取开始时的稳定集合生成, 不从生产器最终聚合结果推导.
- 偏移路径在第一页后插入排名最高的 X.
- 游标路径在第一页后把未读 C 的 rank 从 20 改为 35, 使其移动到游标 B 之前.
- 快照路径的两页都读取初始集合, 并与相同基线身份序列比较.
- 独立验证器只读取观测身份、基线身份和验证模式, 不读取分页实现或生产器断言.

## 实验设计

1. 读取偏移第一页 A、B, 插入 X 后按 offset 2 读取第二页 B、C, 聚合为 A、B、B、C.
2. 分别用只比较数量和检查任务、数量、唯一身份、缺失身份及顺序的验证器判断偏移结果.
3. 读取游标第一页 A、B, 将 C 的排序键移到 B 之前, 从当前 B 之后继续得到 D.
4. 保存初始快照并从同一快照读取两页, 聚合 A、B、C、D.
5. 对快照结果执行同状态重放, 检查验证结果与额外写入.

故障注入分别是第一页后的前置插入和未读项目排序键跨越游标.

## 原始观测

| 路径 | 聚合身份 | 数量验证 | 身份验证 | 任务级判断 |
| --- | --- | --- | --- | --- |
| 偏移加前置插入 | A、B、B、C | 通过 | 拒绝 | 数量正确但重复 B、遗漏 D |
| 普通游标加排序键前移 | A、B、D | 未使用 | 拒绝 | 遗漏跨过游标的 C |
| 绑定初始快照 | A、B、C、D | 未使用 | 通过 | 有效完成 |

偏移计数验证退出 0, 身份验证退出 1. 游标身份验证退出 1. 快照身份验证和同状态重放均退出 0, 重放写入为 0.

四项机制断言全部为真, 独立验证进程 5 个, 验证后有效耗时 470.415 毫秒, 临时目录清理通过.

## 独立验证

独立 Python 进程从 UTF-8 JSON 文件重新读取任务标识、观测身份序列与基线身份序列.

计数模式只核对任务和数量, 用于构造假成功. 身份模式额外检查重复、缺失、意外身份及顺序. 验证器不读取 offset、cursor、snapshot 标志或生产器成功布尔值, 但仍与生产路径共享 JSON 字段合同和 Python 运行时.

## 强反例

偏移路径最终恰好得到 4 个元素, 与初始基线数量完全相同, 因而计数验证返回成功. 实际结果 A、B、B、C 同时包含重复 B 和遗漏 D.

普通游标也不能单独推翻 H2. 未读项目 C 的排序键在两页之间移动到游标 B 之前后, 从 B 继续只能读取 D, 聚合结果仍遗漏 C.

## 路径比较

| 路径 | 跨页状态绑定 | 识别重复和遗漏 | 有效完成 | 验证进程 | 结果质量 |
| --- | --- | --- | --- | ---: | --- |
| 偏移加计数验证 | 否 | 否 | 否 | 1 | 假成功 |
| 偏移加身份验证 | 否 | 是 | 否 | 1 | 识别损坏但需重同步 |
| 普通游标加身份验证 | 只绑定位置 | 是 | 否 | 1 | 排序键变化时遗漏 |
| 快照绑定加身份验证 | 是 | 是 | 是 | 2 | 基线全集且重放一致 |

快照路径没有减少页数, 额外成本来自保存或引用稳定视图与完整身份验证. 单机耗时不用于推断真实远端分页性能.

## 暂时结论

状态为观察.

本次受控实验中, 跟随分页协议只能证明客户端继续请求, 不能单独证明所有页面属于同一集合视图. 结果数量也不能识别等量重复与遗漏. 页令牌需要绑定稳定快照或等价集合代际, 最终验证需要核对唯一身份集合与预期边界.

该实验为 NOTES 中既有发现增加分页集合反例, 但快照绑定分页机制只出现一次, 不升级为新的候选或长期发现.

## 复验条件

使用真实支持游标或版本化列表的 API 复验, 在页间注入插入、删除、排序键更新、权限变化和令牌过期.

测试无法提供稳定快照的服务是否能通过上界水位、去重、缺失检测和受控重同步获得等价结果. 比较全量重启、局部续读与快照读取的调用数量、质量和验证后有效耗时.

## 事实分层

### 已验证事实

- 偏移聚合数量为 4, 计数验证通过, 身份验证发现重复 B 和遗漏 D.
- 普通游标在未读 C 的排序键跨过游标后遗漏 C.
- 快照绑定结果与初始身份序列一致, 同状态重放验证一致且写入为 0.
- 四项机制断言为真, 五个独立验证进程完成, 临时目录清理通过.

### 基于证据的推断

- 多页任务的完成合同应记录集合视图身份, 不能只记录下一页位置、页数或最终数量.
- 普通游标减少偏移漂移但不能自动抵抗可变排序键, 稳定排序键或快照语义需要由服务合同明确提供.

### 未验证事项

- 真实 API 的游标是否隐式绑定快照及其保留窗口.
- 删除、权限变化和令牌过期同时发生时的安全恢复边界.
- 无快照 API 中上界水位与重同步能否避免遗漏且保持可接受速度.
