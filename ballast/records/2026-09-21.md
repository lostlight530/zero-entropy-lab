## 研究摘要

本轮从 09-20 request-time replay freshness转向 conditional state-changing recovery. 核心问题是响应丢失后 retry遇到 stale If-Match或 412 时, precondition failure究竟证明了什么.

RFC 9110明确把 If-Match定义为当前 selected representation的执行前置条件, 并允许 origin server在能够判断同一 state-changing request已经成功时返回 2xx. 因此 precondition failure本身不是 historical non-occurrence proof.

## 研究问题

当一次 unsafe state-changing request的响应丢失, 随后 conditional retry因 stale ETag失败时, recovery能否把 412直接降级为 original attempt未执行, 或把当前 representation已经满足 intent直接升级为 historical occurrence proof.

## 来源依据

查询日期 2026-09-21.

- RFC 9110 Section 13定义 conditional requests. If-Match使用 strong comparison并在执行 method之前由 origin server判断, 主要用于防止 lost update.
- RFC 9110 Section 13.1.1规定 If-Match为 false时不得执行该 request method, 通常返回 412; 对 state-changing request, 如果 server能够判断请求的 change已经成功, 也可以返回 2xx. 这直接说明当前 precondition result与 historical application不是同一事实.
- RFC 9110 Section 9.2.2规定 idempotent method可在通信失败后自动 retry, 但 non-idempotent request不应自动 retry, 除非客户端知道其 semantics实际幂等或能够判断原 request从未应用.

外部 RFC只支持 HTTP contract, 不证明本地 fixture结果, 也不证明任意 API的 ETag覆盖完整业务 intent.

## 可证伪假设

- H1 stale If-Match或 412足以证明 original unknown attempt没有产生 effect.
- H2 current representation满足 intent足以证明 original unknown attempt历史上产生了 effect.
- H3 conditional precondition可以保护新的 write boundary, 但 historical occurrence仍需要独立 hit / authoritative miss / unknown evidence.
- H4 current permission invalid只阻止新 effect, 不阻止只读 reconciliation.
- H5 prior HIT与 prior UNKNOWN不会因当前 If-Match结果被重新分类.

## 强反例

stale-same-intent中 original validator已经失效而 current representation恰好等于 goal-X. conditional-only只得到 precondition failure. readback看到 current goal满足.

但 current-goal-satisfied-by-other-writer具有相同 current readback, 历史却由另一个 writer造成. 因而 current goal satisfied不能证明 original attempt HIT, 推翻 H2.

反向地, prior-HIT-stale中 historical evidence已证明 original effect发生, 当前 If-Match仍可能 stale. 因而 stale precondition不能证明 original effect MISS, 推翻 H1.

## 路径比较

unconditional retry在 stale target或 revoked permission下可能产生不受保护的新 effect.

conditional-only保护当前 target generation, 但只能给出当前 write是否允许执行, 不重建历史.

conditional-readback改善 current completion判断, 能区分 current goal satisfied与 current conflict, 但 provenance仍不足以证明谁造成当前状态.

evidence-separated同时保留 historical occurrence三态, current permission, target validator与 current completion readback, 因而不把 412, HIT, UNKNOWN或 already-satisfied相互替代.

## 暂时结论

状态为观察. H1与 H2被强反例推翻. H3, H4, H5在 modeled boundary内得到支持.

HTTP conditional write是 current effect fence, 不是 historical receipt authority. Post-failure readback可以建立 current completion evidence, 但如果任务需要证明 original occurrence identity, 仍需 receipt, operation identity, audit log或等价 historical authority.

因此 `412 != authoritative miss`, `current goal satisfied != historical hit`, `historical hit != current permission`.

## AGI-scale action-integrity relevance

长期自主 Agent跨 API恢复 unsafe action时, conditional request可以保护 stale target, 但不能承担全部 recovery semantics. Agent必须分别保存 historical effect evidence, current permission, target generation与 current task completion, 否则会在响应丢失后把 current state误解释成 historical provenance.
