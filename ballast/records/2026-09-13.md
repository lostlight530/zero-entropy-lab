## 研究问题

旧 attempt 可能在 approval 有效期内已经成功但 completion 未持久化, recovery 发生在 approval 过期后时, current approval expiry 是否可以直接停止并跳过 historical reconciliation

反方向问题是 authoritative receipt HIT 是否足以恢复 completion, 即使该 historical effect 实际发生在 approval valid_until 之后

本轮把三个事实分开: historical occurrence, historical effect-time authorization, current permission for any new effect

## 来源依据

查询日期为 2026-09-13

- [RFC 9110 HTTP Semantics](https://www.rfc-editor.org/rfc/rfc9110.html) 的 9.2.2 说明通信失败后, 非幂等请求不应自动重试, 除非客户端能够证明请求语义实际幂等或能够检测原请求从未被应用. 本轮只采用有限命题: response 或 completion 缺失不能单独证明原 effect 未发生
- [RFC 7519 JSON Web Token](https://www.rfc-editor.org/rfc/rfc7519.html) 的 4.1.4 说明 `exp` 到达或超过 expiration time 后 JWT 不应继续被接受. 本轮只采用有限命题: temporal authorization evidence 在实际使用时需要满足时间边界, 不把 JWT 直接等同于人工 approval
- [Amazon ECS idempotency](https://docs.aws.amazon.com/AmazonECS/latest/developerguide/ECS_Idempotency.html) 说明相同 client token 与相同参数的成功重试返回原结果而不执行额外动作. 本轮只采用有限命题: historical result identity 与 retry suppression 可以独立于当前重试时点存在, 不把 ECS token 当作 Ballast approval

来源共同支持两个独立设计前提: historical occurrence 需要独立证据, temporal authorization 需要按相关时点判断. 外部来源不证明本地 effect_total、valid_completion 或 PASS

## 可证伪假设

- H1: recovery 时 current approval 已过期即可直接安全停止, 不需要查询 historical effect occurrence
- H2: authoritative receipt HIT 足以恢复 valid completion, 不需要验证 historical effect 发生时 approval 是否仍有效
- H3: current approval 是否允许新 effect, historical effect 是否发生, historical effect 当时是否获授权是三个不可互相替代的事实
- H4: 对 prior HIT 应使用 historical effect time 与 approval_until 重建旧 effect 的授权有效性; 对 authoritative MISS 才转入 current approval 门决定是否允许新 effect
- H5: completed replay 必须从 production entry 重入并保持零新增 effect

H1 的反证条件是 authorized-hit-expired: old effect 在 t=95 合法发生, recovery 到 t=105 时 current approval 已过期, approval-first path 在 prior query 前停止导致 reconciled=0

H2 的反证条件是 unauthorized-hit-expired: receipt 确认 effect 已发生, 但 effect_time=101 已越过 approval_until=100, receipt-hit-complete 仍把它标成 valid completion

## 控制条件

- approval action identity 固定为 `action-43`, approval_until 固定为逻辑时刻 100
- effect identity 固定为 `op-113`
- authorized-hit-expired: prior=HIT, historical effect_time=95, recovery_time=105
- unauthorized-hit-expired: prior=HIT, historical effect_time=101, recovery_time=105
- miss-expired: prior=MISS, recovery_time=105
- miss-valid: prior=MISS, recovery_time=99
- unknown-expired: prior=UNKNOWN, recovery_time=105
- completed-replay 已有持久化 completion, 从相同 production entry 重入
- approval-first-stop 先看 current approval, 过期即在 prior query 前停止
- receipt-hit-complete 对 HIT 直接恢复 completion, 不检查 historical authorization
- current-gated-reconcile 查询 prior 后仍用 recovery 时 current approval 判断 HIT 是否可完成
- historical-boundary-reconcile 对 HIT 验证 historical effect-time authorization, 对 MISS 才检查 current approval 并决定是否进入 protected new effect
- fixture 只使用 Python 标准库与系统 awk

## 强反例

第一强反例攻击 current approval expired 即可停止全部恢复

authorized-hit-expired 的 old effect 在 t=95 合法发生, recovery 到 t=105 时批准已过期. approval-first-stop 虽零新增 effect, 但 prior_reconciled=0; current-gated-reconcile 查询到 HIT 后仍因为 current expiry 拒绝合法历史 completion

第二强反例攻击 receipt HIT 即 valid completion

unauthorized-hit-expired 的 effect 确实存在, 但发生在 t=101, 已晚于 approval_until=100. receipt-hit-complete 仍直接完成, 说明 occurrence evidence 不能替代 historical authorization evidence

反方向强反例是 miss-valid

prior effect 确认未发生且 recovery_time=99 仍在批准窗口内时, historical-boundary-reconcile 应允许一次必要 effect, 不能因为强调 reconciliation 而永久零写入

## 路径比较

- approval-first-stop 操作最少且能阻止 expired recovery 的新 effect, 但丢失 historical occurrence reconciliation
- receipt-hit-complete 能快速恢复 authorized HIT, 但同样接受 unauthorized historical HIT, 形成 false completion
- current-gated-reconcile 能查询 historical occurrence, 但把 current approval validity 错用作 historical completion validity, 对 authorized-hit-expired 产生 false negative
- historical-boundary-reconcile 对 HIT 使用 historical authorization boundary, 对 MISS 使用 current approval boundary, 在两个时间轴之间保持语义分离
- stronger path 在 HIT 场景多一次 historical-time validation, 但避免 false positive 与 false negative, 结果质量优先于少一次操作
- 本地逻辑时钟与 Python 进程耗时不外推真实审批或远端系统性能

## 暂时结论

证据状态为观察

本轮支持 H3、H4、H5, 推翻 H1、H2

current approval expiry 只决定 recovery 之后是否允许新的 effect, 不能抹除更早已经合法发生的 historical effect

receipt HIT 只证明 occurrence, 不能单独证明 historical effect 在当时获得有效 approval

对 HIT 的 completion recovery 需要绑定 historical effect identity 与 effect-time authorization evidence; 对 MISS 才转入 current approval 门决定新的 protected effect

## 事实分层

### 已验证事实

- authorized-hit-expired 中 historical effect_time=95、approval_until=100、recovery_time=105
- approval-first-stop 在该场景 prior reconciliation=0; historical-boundary-reconcile 恢复 valid completion 且 new_effect=0
- unauthorized-hit-expired 中 effect_time=101 已越过 approval_until=100, receipt-hit-complete 仍 valid_completion=1, historical-boundary-reconcile valid_completion=0
- miss-expired 中 historical-boundary-reconcile effect_total=0, miss-valid 中只新增一次必要 effect
- unknown-expired 保持 zero-write reconciliation
- completed replay 四条路径均零新增 effect
- 三次 producer trace SHA-256 完全一致, Python verifier 3/3 PASS, awk 3/3 PASS, producer/verifier py_compile PASS

### 基于证据的推断

- historical occurrence、historical authorization 与 current new-effect authorization 是三个不同证明义务
- current expiry 不应反向否定过去在有效窗口内合法发生的 effect
- authoritative HIT 也不应洗白过去发生在授权窗口之外的 stale effect
- historical-boundary reconstruction 在受控模型中同时避免上述 false negative 与 false positive

### 未验证事项

- historical effect time 与 approval validity 尚未来自两个真实独立 authority channel
- 尚未覆盖 receipt visibility lag 与 approval expiry 同时发生
- 尚未验证可信时间源、clock skew、issuer generation 与服务端 effect-time enforcement
- 尚未在真实外部 API 或 HITL 系统复验
