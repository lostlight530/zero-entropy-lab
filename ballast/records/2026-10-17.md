## 研究问题

补偿动作的首次响应丢失且 idempotency key 保留期过后, 旧 key、取消终态、补偿收据数量或补偿队列状态能否证明不应重复退款及当前任务已完成, 哪些证据才允许一次新的非幂等补偿

## 来源依据

2026-10-17 实际访问并核验, 三个不同发布者, 不视为真实系统故障样本

- [Stripe API generation 1 idempotent requests](https://docs.stripe.com/api/idempotent_requests): API generation 1 可在至少 24 小时后清理 key, 清理后复用可触发新请求, 且保存的首个响应可能是错误, 不能把相同 key 当成无限期去重证明, 此语义不自动推广至 API generation 2 或所有 refund endpoint
- [Temporal Saga Pattern](https://github.com/temporalio/documentation/blob/main/docs/design-patterns/saga-pattern.mdx): compensation 需要幂等且可能因 retry 多次运行, 注册补偿与完成外部 effect 不是同一证据
- [AWS durable execution idempotency and retries](https://github.com/aws/aws-durable-execution-docs/blob/main/docs/patterns/best-practices/idempotency.md): at-most-once 是 per retry attempt, 不保证整个 workflow exactly-once, 需外部副作用去重与独立恢复合同

这些文档只支持各自的 API 或设计合同, 本轮 retention=10 与 refund sink 均为受控模型参数, 不是 Stripe 真实测试
