## 研究摘要

本轮把 delegated multi-agent authority frontier 推进成最小受控实验, 比较 subject-only, actor-aware 与 actor+audience+sender 三条 current-permission path, 同时保留 HIT 与 UNKNOWN 的 prior-effect 分界

## 研究问题

subject 正确时, 只验证 subject 是否足以证明新的 delegated effect 仍由正确 actor 在正确 resource 与 sender context 下执行

## 来源依据

查询日期 2026-09-18

- RFC 8693 https://www.rfc-editor.org/rfc/rfc8693.html 支持 delegation 中 subject 与 actor 身份分离, JWT `act` 可表达 current actor 与 delegation history
- RFC 9700 https://www.rfc-editor.org/rfc/rfc9700.html 支持 access-token privilege restriction, audience restriction 与 sender-constrained applicability
- RFC 8707 https://www.rfc-editor.org/rfc/rfc8707.html 支持 resource restriction 防止 token 在错误 resource 上使用

外部标准不证明本地 fixture PASS 或真实 OAuth deployment behavior

## 可证伪假设

- H1 subject 正确且 current state active 时, subject-only 足以授权 delegated effect
- H2 actor identity 可拒绝 actor substitution, 但不能独立拒绝 wrong audience 或 sender mismatch
- H3 actor + audience + sender projection 可拒绝本轮三类 delegation-context drift
- H4 prior HIT 即使 current actor 已失效仍进入只读 historical reconciliation
- H5 prior UNKNOWN 即使 current permission 看似有效也不能直接产生新的非幂等 effect

## 暂时结论

状态为观察

H1 被推翻, H2/H3/H4/H5 在本地边界内得到支持

Delegated current permission 不能只绑定最终 subject, current actor identity 与 token applicability 是不同 permission dependency

Historical occurrence classification 继续独立于 current delegated permission

## AGI-scale action-integrity relevance

长期自主 Agent 可能形成 planner -> approver -> executor -> sub-agent -> tool/resource delegation chain

如果只保留最终 subject, executor replacement, resource drift 或 token replay context 可能被误认为仍属于原授权
