## 研究摘要

本轮把 Ballast 的 delegated multi-agent authority frontier 推进成一个最小受控实验

研究 subject identity 正确时, 只检查 subject 是否会把错误 actor, 错误 audience 或错误 sender 继续放行, 并比较 subject-only, actor-aware 与 actor+audience+sender 三条 permission path

同时保留 prior HIT 与 UNKNOWN 的恢复语义, 防止 delegated permission 研究把 historical occurrence 偷换成 current permission

## 研究问题

当 planner/subject 将部分权限委托给 executor/actor 时, verifier 只验证 subject 和 scope 是否足以证明新的 effect 仍由正确 actor 在正确 resource 和正确 sender context 下执行

## 来源依据

查询日期为 2026-09-18

- RFC 8693 OAuth 2.0 Token Exchange: https://www.rfc-editor.org/rfc/rfc8693.html
  - delegation 与 impersonation 不同
  - delegation 保留 subject 与 actor 的不同身份
  - JWT `act` 可以表达当前 actor 和 delegation history
  - access-control policy 对 nested `act` history 的处理具有明确边界
- RFC 9700 OAuth 2.0 Security Best Current Practice: https://www.rfc-editor.org/rfc/rfc9700.html
  - access token 应限制到所需 privilege
  - resource server 应验证 audience restriction
  - sender-constrained token 用于把 token applicability 绑定到特定 sender
- RFC 8707 Resource Indicators for OAuth 2.0: https://www.rfc-editor.org/rfc/rfc8707.html
  - resource/audience restriction 用于限制 token 在错误 resource 上被重放

外部标准只支持 delegation identity 与 token applicability 的有限语义, 不证明本地 fixture PASS 或真实 OAuth deployment behavior

## 可证伪假设

- H1: subject 正确且 current state active 时, subject-only permission 足以授权 delegated effect
- H2: 加入 current actor identity 可以拒绝 actor substitution, 但不能独立拒绝 wrong audience 或 sender mismatch
- H3: actor + audience + sender binding 的 relevant projection 能拒绝本轮三类 delegation-context drift
- H4: prior HIT 即使 current actor 已失效, 仍应进入只读 historical reconciliation, 不能因为 current permission invalid 把 occurrence 改写成 MISS
- H5: prior UNKNOWN 即使 current actor/current permission 看似有效, 也不能直接产生新的非幂等 effect

## 独立验证

外部语义验证来自三个 IETF/RFC authority surface

RFC 8693 支持 subject 与 actor 在 delegation 中不能被坍缩

RFC 9700 与 RFC 8707 支持 audience restriction 与 sender-constrained applicability 是与 subject identity 不同的 token-use constraint

本地第二验证从场景字段重新计算 expected permission predicate, 未使用 producer-internal success flag

但本地 producer/verification 仍共享 scenario vocabulary, intended actor/audience/sender 常量与同一 Python runtime, 因而只记 PARTIAL semantic independence, 不记 external IV&V

## 强反例

actor-swapped 证明 subject 正确不代表 current actor 正确

wrong-audience 证明 actor 正确不代表 token 对当前 resource 适用

sender-mismatch 证明 subject + actor + audience 正确仍不代表当前 sender 满足 sender binding

prior-hit-actor-now-invalid 反向证明 current permission invalid 不能抹掉已知 historical occurrence

prior-unknown 证明 current permission valid 也不能把 unknown historical occurrence 自动升级成 safe retry

## 路径比较

subject-only 最便宜, 但三类 delegated-context drift 全部 false accept

actor-aware 消除 actor substitution, 仍 false accept wrong audience 与 sender mismatch

actor-aud-sender 在本轮 relevant projection 内拒绝三类 drift, baseline 保持可执行

stronger projection 不是全局完整授权证明, 因为本轮没有覆盖 scope narrowing, delegation depth, issuer/key lifecycle, revocation, approval validity 或 effect-set drift

## 暂时结论

状态为观察

H1 被推翻, H2/H3/H4/H5 在本地受控边界内得到支持

Delegated authority 不能只绑定最终 subject

对新的 effect, current actor identity 与 token applicability constraints 至少是不同的 permission dependency

同时 historical occurrence classification 继续独立于 current delegated permission

本轮不足以证明 `actor + audience + sender` 是完整 delegation policy, 只能证明它比 subject-only 和 actor-only 更强且仍存在未建模依赖

## AGI-scale action-integrity relevance

长期自主 Agent 可能形成 planner -> approver -> executor -> sub-agent -> tool/resource 的 delegation chain

如果系统只保留最终 subject 或 broad scope, executor replacement, resource drift 或 token replay context 可以被误认为仍属于原授权

Ballast 因而需要把 delegated actor identity 与 token applicability 纳入 current execution permission, 但不能把 delegation history 本身误当作 historical occurrence 或 current completion proof
