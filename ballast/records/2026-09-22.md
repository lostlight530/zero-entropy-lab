## 研究摘要

本轮直接攻击 09-21 conditional-write strongest path的 target identity假设. Strong ETag能够保护 selected representation的变化, 但它是否足以证明当前逻辑 URL仍指向原 concrete incarnation.

RFC 9110把 ETag定义为 selected representation的 opaque validator. Kubernetes则明确区分可删除后复用的 Name与用于区分历史相似实体的 UID. 因而本轮构造 delete/recreate same-name + same-content-validator alias, 检查只绑定 ETag是否会把新 incarnation误当旧 target.

## 研究问题

当任务授权和语义明确绑定 concrete target incarnation时, strong representation validator匹配是否足以替代 incarnation identity与 current revision, 尤其在同名资源删除重建且 representation bytes相同时.

## 来源依据

查询日期 2026-09-22.

- RFC 9110 Section 8.8与 8.8.3定义 validator为 selected representation的当前 metadata, ETag是区分同一 resource多个 representations的 opaque validator. Strong validator在 representation data发生可观察变化时必须变化, 适合 conditional request与 lost-update avoidance.
- RFC 9110没有把 ETag定义为跨 delete/recreate lifecycle的 resource-incarnation identifier. ETag生成机制可由内部 revision, content hash, file attributes或 timestamp实现.
- Kubernetes Object Names and IDs文档明确说明 Name在对象删除后可以再次用于新对象, 而 UID在 cluster lifetime内区分历史上相似实体的不同 occurrence.
- Kubernetes ObjectMeta文档把 resourceVersion定义为用于 change detection和 optimistic concurrency的 opaque internal version, 把 UID定义为 time-and-space unique object identity.

外部来源只支持 validator与 object identity的语义边界. Kubernetes UID/resourceVersion不是通用 HTTP强制模型, 本地 fixture也不证明任意 HTTP server实际复用 ETag.

## 可证伪假设

- H1 logical name足以绑定 concrete target.
- H2 strong ETag匹配足以证明 concrete target incarnation未变化.
- H3 UID匹配足以保护 concrete target, 无需 current revision.
- H4 concrete UID + current revision + current permission能够在本轮 modeled boundary拒绝 same-name recreation, same-incarnation stale state与 revoked permission.
- H5 prior HIT与 UNKNOWN不因 target reincarnation而被重分类.
- H6 新 incarnation恰好满足 goal只能证明 current representation predicate, 不能证明原 concrete-target task完成.

## 实验设计

执行 8 scenarios × 4 paths共 32 个 modeled decisions.

关键 fault injection是将 u1删除后创建同名 u2, 并让 u2具有与旧 representation相同的 modeled content-derived ETag=A. 这不声称所有 HTTP server都会这样生成 ETag, 只测试 RFC允许的 validator role是否足以承担额外 incarnation contract.

另注入同一 u1 revision从 r10推进到 r11, 以及 current permission revoked.

producer连续执行三次. 第二套 verifier从 prior-effect class, permission, UID, revision与 ETag字段重建 expected transition.

## 强反例

`recreated-same-content-etag`中 logical name与 ETag都与旧观察一致, 但 concrete UID已从 u1变为 u2. etag-only仍产生 new-effect, 推翻 H2.

`same-incarnation-changed`中 UID仍为 u1但 revision已从 r10推进到 r11. uid-only仍产生 new-effect, 推翻 H3.

`recreated-goal-satisfied`进一步说明新 u2即使当前 bytes满足 goal, 对明确绑定 u1的 concrete-instance task也不能自动声明原 target完成, 支持 H6的有限边界.

## 路径比较

name-only既不能识别 same-name reincarnation, 也不能识别同 incarnation revision drift或 permission revocation.

etag-only能识别 representation data变化, 但 modeled content-equivalent recreation形成 incarnation alias, 且不承担 current permission.

uid-only识别 reincarnation, 但同一 incarnation内部 revision drift仍可能让旧 decision失效, 且本弱路径不承担 current permission.

uid-revision把 concrete identity与 current state generation分别绑定, 再独立检查 current permission. 在本轮 modeled concrete-target contract内 0 false accept / 0 false reject.

## 暂时结论

状态为观察. H1, H2, H3被反例推翻. H4, H5, H6在本轮 modeled boundary内得到支持.

Representation validator回答 representation是否仍匹配, incarnation identifier回答是否仍是同一个 concrete object, revision回答该 object的 current generation是否仍匹配. 三者职责不能机械坍缩.

因此 `strong ETag match != concrete incarnation identity`, `UID match != current revision`, `current goal on replacement != completion of an incarnation-bound task`.

## AGI-scale action-integrity relevance

长期自主 Agent可能跨数小时或数日恢复对同一 logical name的操作. 如果对象在中间被删除重建, 只保存 URL、名称或 content validator可能把 replacement entity误当原授权对象. Concrete target identity与 current generation需要成为可验证 action state, 而不是从内容相似性推断.
