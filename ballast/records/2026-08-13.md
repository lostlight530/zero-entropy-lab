# Ballast 日记录 2026-08-13

类型: 每日专题
主题: 任务取消后仍有效凭据造成的迟到副作用

## 研究问题

Agent 任务已经被显式取消后, 如果旧执行者持有的 bearer credential 仍处于技术有效期内, 仅验证 token 到期时间或仅查询 token active 状态是否足以阻止迟到副作用, 还是必须在副作用接受边界同时核对当前任务状态.

本题不同于 2026-08-12 的任务有效期研究. 8 月 12 日攻击的是时间自然越过 `valid_until`, 今天攻击的是控制面已经显式把任务从 RUNNING 转换为 CANCELLED, 但 credential 生命周期尚未同步变化的窗口.

## 来源依据

查询日期为 2026-08-13.

- [RFC 7662 OAuth 2.0 Token Introspection](https://www.rfc-editor.org/rfc/rfc7662.html) 发布于 2015-10. 标准定义受保护资源可以查询 token 当前 `active` 状态, 一般用于表示 token 已签发, 未撤销, 且仍在有效时间窗口内. 标准同时允许资源把额外授权上下文带入 introspection 决策. 适用边界是 OAuth token 状态, 不等价于任意 Agent 任务的业务状态.
- [RFC 7009 OAuth 2.0 Token Revocation](https://www.rfc-editor.org/rfc/rfc7009.html) 发布于 2013-08. 标准定义客户端可以通知授权服务器某个 token 已不再需要, revocation 用于使相应 token 失效. 适用边界是 credential 生命周期管理, 标准不要求任意业务任务取消一定自动触发 token revocation.
- [Kubernetes Service Accounts](https://kubernetes.io/docs/concepts/security/service-accounts/) 访问于 2026-08-13. Kubernetes 推荐自有服务使用 TokenReview 验证 ServiceAccount credential, 因为绑定对象被删除后 TokenReview 会立即失败. 文档同时指出仅做 OIDC 离线校验时, 客户端可能继续把 token 视为有效直到其到期. 适用边界是 Kubernetes 绑定 ServiceAccount token, 本轮没有运行真实 Kubernetes 集群.

三个来源共同支持把静态凭据有效期, 动态 credential 状态和更上层授权上下文分开. 它们不直接证明本轮 Agent 任务取消实验的结果.

## 可证伪假设

- H1: 只要 bearer credential 的签名, scope 与过期时间仍有效, 旧任务在被取消后继续提交也可以视为授权有效.
- H2: 每次副作用前查询 token introspection, 只要返回 `active=true`, 就足以代表当前 Agent 任务仍可继续.
- H3: 副作用入口必须同时核对当前任务状态与 credential 状态. 任务已经 CANCELLED 时, 即使 credential 仍 ACTIVE 也应拒绝旧任务提交.

如果显式取消后离线 token 路径不产生写入, H1 的风险解释被削弱.

如果 token 尚未被撤销且 introspection 仍为 ACTIVE 时, introspection-only 路径能够拒绝取消后的提交, H2 的风险解释被削弱.

如果 task-bound 路径在任务状态已经是 CANCELLED 时仍接受提交, H3 被推翻.

## 控制条件

- 初始任务状态固定为 RUNNING.
- credential 初始状态固定为 ACTIVE, 代表签名, scope 与时间窗口均有效.
- 正常基线中不发生任务取消或 credential 撤销.
- 第一类故障注入只把任务状态切换为 CANCELLED, 保持 credential 为 ACTIVE.
- 第二类故障注入先取消任务, 再显式把 credential 状态切换为 INACTIVE.
- 离线 token 路径只依赖本地静态 credential 有效性, 不读取任务状态或动态撤销状态.
- introspection-only 路径读取当前 credential ACTIVE 或 INACTIVE, 不读取任务状态.
- task-bound 路径同时读取当前任务状态与 credential 状态.
- 三条路径都使用相同 `intent_id` 完成记录, 用于单独验证完成后同输入生产入口重放.
- 实验只使用 Python 标准库, 系统已有 awk 与本轮系统临时目录.

## 实验设计

1. 正常基线保持任务 RUNNING, credential ACTIVE, 让三条路径提交 `job-a -> value 20`.
2. 第一类故障注入把任务切换为 CANCELLED, credential 保持 ACTIVE, 再让旧执行者经三条生产入口提交同一意图.
3. 第二类故障注入在取消任务后再撤销 credential, 比较离线校验, introspection-only 和 task-bound 三条路径.
4. 记录每个场景的任务状态, credential 状态, 提交结果, 最终 value 与写入计数.
5. 正常完成后让同一 `job-a` 再次经过相同生产提交入口, 检查是否产生第二次写入.
6. 生产夹具输出固定十列 UTF-8 TSV 事件轨迹, 不把验证器应得到的成功布尔值写入轨迹.
7. 独立 Python 进程从 `TASK_CANCEL`, `TOKEN_REVOKE`, `SUBMIT` 与 `FINAL` 事件重建任务和 credential 状态, 独立计算取消后被接受的副作用数量.
8. 再使用 awk 独立解析同一 TSV, 重新计算第一类故障中的取消后接受数量和完成后写入计数.
9. 完整生产夹具运行三次, 比较事件轨迹摘要与独立验证结果.

## 原始观测

三次完整生产轨迹均包含 48 个事件行, SHA-256 均为 `fa081e6b0626143ada6dcf58135cd8baa7280a3cc68cf429af17855b4ac0e7a7`.

三次生产夹具本体耗时分别为 0.392 毫秒, 0.459 毫秒和 0.356 毫秒. 这些数字只记录本轮确定性内存模型成本, 不用于推断真实授权服务性能.

| 场景 | 路径 | 提交结果 | 最终任务 | 最终 credential | 最终 value | 写入次数 |
| --- | --- | --- | --- | --- | ---: | ---: |
| 正常基线 | 离线 token | applied | RUNNING | ACTIVE | 20 | 1 |
| 正常基线 | introspection-only | applied | RUNNING | ACTIVE | 20 | 1 |
| 正常基线 | task-bound | applied | RUNNING | ACTIVE | 20 | 1 |
| 取消但未撤销 credential | 离线 token | applied | CANCELLED | ACTIVE | 20 | 1 |
| 取消但未撤销 credential | introspection-only | applied | CANCELLED | ACTIVE | 20 | 1 |
| 取消但未撤销 credential | task-bound | task_cancelled | CANCELLED | ACTIVE | 0 | 0 |
| 取消后撤销 credential | 离线 token | applied | CANCELLED | INACTIVE | 20 | 1 |
| 取消后撤销 credential | introspection-only | token_inactive | CANCELLED | INACTIVE | 0 | 0 |
| 取消后撤销 credential | task-bound | task_cancelled | CANCELLED | INACTIVE | 0 | 0 |

第一类故障中, 任务已经显式变为 CANCELLED, 但 credential 仍为 ACTIVE. 离线 token 路径和 introspection-only 路径各接受 1 次旧任务副作用, task-bound 路径以 0 写入停止.

第二类故障中, credential 随后被撤销. introspection-only 路径此时能够拒绝提交, 但离线 token 路径因为不观察动态撤销状态仍产生 1 次写入.

三条路径在正常完成后使用同一 `job-a` 再次经过各自生产提交入口, 第二次都返回 `already_applied`, 总写入仍为 1.

## 独立验证

独立 Python 验证器运行在与生产夹具分离的进程中, 只消费 UTF-8 TSV 事件轨迹.

验证器不读取生产器内部的 `allowed` 判定, 而是按事件顺序自行维护任务状态与 credential 状态. 当 `SUBMIT` 返回 `applied` 且当前任务状态已经不是 RUNNING 时, 独立计为一次取消后副作用.

三次独立 Python 验证均通过, 第一类故障重新得到:

- 离线 token 取消后接受数为 1.
- introspection-only 取消后接受数为 1.
- task-bound 取消后接受数为 0.
- 三条完成后重放路径总写入均为 1, 没有第二次副作用.

第二验证器使用 awk 独立解析同一事件轨迹, 不复用 Python 对象模型与解析器, 对第一类故障得到相同分类并通过.

独立 Python 验证三次进程级墙钟耗时分别约为 0.70 秒, 0.61 秒和 0.62 秒, 主要包含本轮沙箱 Python 启动成本, 不用于真实服务性能比较.

生产器和两个验证器仍共享同一事件字段语义, 且实验没有调用真实 OAuth 或 Kubernetes 服务, 因此独立性不是完全的外部系统独立验证.

## 强反例

强反例是 `TASK_CANCEL -> credential 仍 ACTIVE -> 迟到提交`.

在这个窗口中, introspection-only 路径获得的是一个技术上合理的 `ACTIVE` credential 状态. 它没有发生 token 过期, 也没有伪造 credential, 但仍对已经取消的任务执行了 1 次副作用.

因此 `active credential + 请求成功 + 单次写入` 不能证明 Agent 任务当前仍有执行授权.

随后显式撤销 credential 可以让 introspection-only 路径停止, 但这不推翻强反例. 它只说明 credential revocation 能在被正确传播后缩小窗口, 不能证明任意任务取消都已经与 credential 生命周期原子绑定.

Kubernetes 文档中的 TokenReview 与离线 OIDC 差异提供一个现实边界例子: 动态对象状态可以让在线校验立即失效, 而离线校验可能继续接受到 token 到期. 本轮只借用这个状态分层思想, 不把 Pod 删除等同于 Agent 任务取消.

## 路径比较

| 路径 | 依赖状态 | 取消但 credential ACTIVE 时写入 | credential 撤销后写入 | 完成后重放新增写入 | 结果质量 |
| --- | --- | ---: | ---: | ---: | --- |
| 离线 token | 静态签名, scope, exp | 1 | 1 | 0 | 无法识别任务取消或动态撤销 |
| introspection-only | 动态 credential 状态 | 1 | 0 | 0 | 能识别撤销, 但任务取消未传播时仍误写 |
| task-bound | 当前任务状态 + credential 状态 | 0 | 0 | 0 | 取消窗口中拒绝旧任务副作用 |

离线 token 路径操作数最少, 但对动态撤销和任务取消都失明.

introspection-only 增加一次动态 credential 查询, 在 token 已撤销后提高质量, 但不能自动推导更上层任务状态.

task-bound 再增加一次当前任务状态读取, 本轮故障中少执行 1 次取消后的副作用. 在结果质量优先前提下, 不能为了减少一次状态检查把 ACTIVE credential 当成完整任务授权.

## 暂时结论

状态为观察.

在本轮受控模型中, credential 有效性与 Agent 任务执行授权是两个不同状态维度.

任务取消后 credential 仍 ACTIVE 时, 静态 token 校验与 token introspection 都可能给出自身层面正确的结果, 但仍允许已经取消的任务产生副作用.

当前证据支持把任务状态检查保留到最终副作用接受边界, 或让任务取消与 credential revocation 或等价 capability 失效共享可验证的同步边界. 单次实验不足以升级为候选或发现.

## 事实分层

### 已验证事实

- 第一类故障中任务状态已经是 CANCELLED, credential 仍为 ACTIVE.
- 离线 token 和 introspection-only 各接受 1 次取消后的副作用.
- task-bound 在相同输入上写入为 0.
- credential 被撤销后 introspection-only 写入为 0, 离线 token 仍写入 1 次.
- 三次生产轨迹摘要一致, Python 独立验证三次通过, awk 第二实现通过.
- 完成后的同输入生产入口重放没有新增第二次写入.

### 基于证据的推断

- 认证或 credential active 状态不能自动替代当前任务授权状态.
- 如果任务取消和 capability 失效不是同一可验证边界, 资源服务仍需要额外任务状态或等价授权上下文.
- 离线 token 校验减少远端查询成本, 但在需要即时撤销或任务级取消的场景中可能扩大迟到副作用窗口.

### 未验证事项

- 真实授权服务器撤销传播时延与缓存行为.
- 真实 Kubernetes TokenReview 和离线 OIDC 的并发时序.
- 多资源服务缓存 introspection 结果时的窗口大小.
- 任务状态服务自身发生旧读时 task-bound 路径是否仍安全.
- 不可逆外部副作用需要怎样的取消确认协议.
