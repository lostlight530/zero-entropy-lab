# Ballast 日记录 2026-08-06

类型: 每日专题
主题: 异步接受回执与终态产物验证

## 研究问题

HTTP 202 或状态资源 Succeeded 是否足以证明异步任务完成, 操作身份、意图摘要与最终产物的绑定验证能否阻止假成功并支持零副作用重放.

## 来源依据

查询日期为 2026-08-06.

- [RFC 9110 202 Accepted](https://www.rfc-editor.org/rfc/rfc9110.html#name-202-accepted) 说明 202 只表示请求已接受处理, 处理尚未完成且最终可能不执行.
- [Azure Asynchronous Request-Reply pattern](https://learn.microsoft.com/en-us/azure/architecture/patterns/asynchronous-request-reply) 要求状态端点区分非终态与终态, 完成后再定位结果资源.
- [Amazon EC2 API idempotency](https://docs.aws.amazon.com/ec2/latest/devguide/ec2-api-idempotency.html) 说明变更请求可能在异步工作完成前返回, 客户端令牌用于避免不确定结果下的重复操作.

RFC 定义接受语义, Azure 给出状态监视与结果定位模式, AWS 给出异步返回和重试风险. 来源不保证状态与业务产物原子一致, 该缺口由实验攻击.

## 可证伪假设

- H1: 202 或 Succeeded 足以让客户端记录完成.
- H2: 接受、终态与完成是三个断言, 完成必须回读状态和产物, 绑定同一操作与意图并检查任务级内容.

若 Succeeded 永远与产物原子一致, 或绑定验证无法拒绝缺失产物和保持零副作用重放, H2 被推翻.

## 控制条件

- 输入为 A、B 两个项目, 操作标识 op-async-001.
- 意图摘要为 a0bc4630e960cabc36e493fb8171f68e927e523c70f9b286fec7a3880b62e11c.
- 接受端返回 202 与状态位置, 首次入队计数为 1.
- 独立验证器检查状态终态、状态与产物的操作标识和意图摘要、产物存在、项目数与内容摘要.
- 使用 Python 标准库和受控临时目录.

## 实验设计

1. 写 Pending 状态但不生成产物, 验证 202 路径.
2. 注入状态先写故障, 把状态写成 Succeeded 后中断, 仍不生成产物.
3. 恢复同一操作, 生成绑定 A、B 的产物.
4. 独立进程回读状态和产物并执行最终验证.
5. 重放同一任务, 先验证已完成结果, 检查新增入队和写入.

故障点位于终态写入与产物提交之间.

## 原始观测

| 路径 | 表面信号 | 独立验证 | 入队 | 写入 |
| --- | --- | --- | ---: | ---: |
| 只看接受 | HTTP 202 | 拒绝, missing_artifact 与 nonterminal_status | 1 | 0 |
| 只看终态 | Succeeded | 拒绝, missing_artifact | 1 | 0 |
| 绑定恢复 | Succeeded 且产物存在 | 通过 | 1 | 1 |
| 完成后重放 | 已验证完成 | 通过 | +0 | +0 |

四项机制断言为真, 独立验证进程 4 个, 验证后有效耗时 268.32 毫秒, 临时目录已清理.

## 独立验证

验证器在独立 Python 进程重新读取状态和产物, 不读取接受布尔值、恢复分支、写入计数或生产器断言.

验证器仍与生产器共享 JSON 语义、SHA-256、字段合同和文件系统, 未覆盖真实队列可见性与复制延迟.

## 强反例

状态含正确操作标识和意图摘要, state 为 Succeeded, 状态文件合法可读, 但最终产物不存在. 只轮询终态会报告完成, 独立产物验证以 missing_artifact 拒绝.

## 路径比较

| 路径 | 区分接受与完成 | 验证产物 | 有效完成 | 结果质量 |
| --- | --- | --- | --- | --- |
| 只看 202 | 否 | 否 | 否 | 未执行也可完成 |
| 只看 Succeeded | 是 | 否 | 否 | 终态与产物分裂 |
| 状态加产物绑定 | 是 | 是 | 是 | 身份、意图、数量与内容一致 |
| 验证后重放 | 是 | 是 | 是 | 新增入队和写入为 0 |

强路径增加状态与产物回读, 有效速度来自避免错误完成和重复操作, 不是减少首次请求.

## 暂时结论

状态为观察.

本次实验中, 202 只能证明接受, Succeeded 只能证明状态资源声明终止. 任务完成还要验证最终产物绑定同一操作和意图且满足任务级条件.

本次为 NOTES.md 两个既有发现增加异步终态分裂证据, 该机制只出现一次, 不建立新候选或发现.

## 事实分层

### 已验证事实

- 202 加 Pending 且无产物被拒绝.
- Succeeded 且身份与意图正确但无产物仍被拒绝.
- 恢复绑定产物后全部验证通过.
- 完成后重放新增入队 0, 新增写入 0.
- 四项断言为真, 四个独立进程完成, 临时目录已清理.

### 基于证据的推断

- 接受确认、执行终态和任务级完成应分开记录.
- 终态只应触发最终验证, 不能替代产物验证.
- 重放跳过需要绑定当前操作、意图和产物.

### 未验证事项

- 真实状态服务与结果存储的一致性和保留期.
- 回调丢失、重定向、取消与迟到完成组合.
- 轮询退避和最终回读对有效耗时的影响.

## 指标

- 有效完成: 绑定恢复为是, 接受和只看终态为否.
- 重放一致与幂等通过: 是, 新增入队和写入均为 0.
- 中断恢复: 状态先写后恢复产物并通过.
- 假成功: 弱路径 2 次.
- 无效操作: 强路径 0.
- 重试次数: 0, 恢复前先检查状态.
