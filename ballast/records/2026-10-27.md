## 研究问题

SQS FIFO DeleteMessage 返回 HTTP 200、发送时 deduplication token 仍在五分钟窗口内，能否证明指定 message 的最新 delivery epoch 已完成删除、下游 A+B effect 均在 effect-time 获授权且当前任务完成

当旧 handle、同 dedup ID、A+A 重复、A+C 替换、covered negative MISS、grant revocation 与 current guard TOCTOU 注入时，弱代理与完整模型能否被可复算地推翻

## 来源依据

2026-10-27 实际访问并核对当前权威文档

- [Amazon SQS DeleteMessage API](https://docs.aws.amazon.com/AWSSimpleQueueService/latest/APIReference/API_DeleteMessage.html) 明确每次 ReceiveMessage 返回不同 ReceiptHandle，旧 handle 的 DeleteMessage 请求可能成功但消息未删除，standard queue 还可能发生再次投递
- [Amazon SQS FIFO MessageDeduplicationId](https://docs.aws.amazon.com/AWSSimpleQueueService/latest/SQSDeveloperGuide/using-messagededuplicationid-property.html) 规定五分钟去重窗口，重复发送可被接受但不交付，窗口并非永久外部 effect ledger
- [Google Cloud Pub/Sub exactly-once delivery](https://docs.cloud.google.com/pubsub/docs/exactly-once-delivery) 作为不同 publisher 和不同产品的比较，说明过期 acknowledgment ID 失效与 region-scoped exactly-once 语义，不能独立证明 AWS 的 DeleteMessage 实际行为

前两个 URL 均属于 AWS 一个 publisher，Google 是独立 publisher 但只提供跨产品对照，所有文档均不证明本地模型 fixture 为真实云端事故

## 可证伪假设

H1 http_status_proxy 将 DeleteMessage HTTP 200 当 COMPLETE，在 stale handle 或未发生 effect 时产生 false COMPLETE

H2 fifo_dedup_proxy 将 HTTP 200 加 dedupAgeSec <= 300 当 COMPLETE，在 token 抑制投递却无下游 effect 时仍产生 false COMPLETE，并可能对已完成但超窗的历史 effect 给出 false negative

H3 full_reference 要求 exact message/delivery epoch/最新 handle 的 synthetic deletion journal、A+B 不重复且无额外 receipt、effect-time grant、正确 run/attempt/target incarnation 与受保护 current witness，才在模型内 COMPLETE

H4 covered authoritative sink MISS、当前 permission 与 guarded recovery witness 缺一不可，否则未知非幂等 outcome 不允许盲重试，covered MISS 与正面 receipt 冲突必须 EVIDENCE_CONFLICT

任何 duplicate、extra effect、same-count member swap、stale handle、grant drift 或 guard drift 被 full_reference 判 COMPLETE 即推翻 H3 的本轮实现

## Action-integrity state

- Current permission 只约束未来 effect 的重试，不能倒推已发生 effect 的历史授权
- Historical occurrence 来自 synthetic exact receipt，DeleteMessage success 与 dedup token 不充当 effect receipt
- Historical effect-time authorization 按每个 effect 的 grant identity、区间及 revokedAt 单独验证
- Prior-effect evidence 区分 hit、authoritative miss、unknown，MISS 必须覆盖 exact task/run/attempt/target/incarnation/effect set、水位、retention 与 lifecycle
- Current completion 要求 exact A+B UID、current target incarnation、guarded revision 和 commit witness
- Temporal ordering 在本轮仅为合成整数 ticks，不能证明真实云端时钟或跨系统 happens-before
- Verifier independence 仅有分离实现，fixture、语义合同与 authority 均不独立

## 强反例

旧 handle 的 DeleteMessage 可能返回 HTTP 200 而没有删除，弱 HTTP proxy COMPLETE，full_reference 因缺少精确 deletion proof 返回 STOP_UNKNOWN

dedupAgeSec <= 300 与 HTTP 200 同时成立但下游 effect journal 为空，两个 weak proxies 仍 COMPLETE，reference STOP_UNKNOWN

A+A 重复收据替代 A+B、额外 effect C、当前 A+C 同数量替换，两个 weak proxies COMPLETE，reference RECONCILE

covered authoritative MISS 与正面 A/B receipt 同时存在，reference EVIDENCE_CONFLICT，不把 negative evidence 偷换为 retry permit

完整历史 effect 和 queue proof 在 dedup 五分钟窗后仍可完成，或当前 permission 后续 revoked 仍可证明过去授权，reference COMPLETE，说明 dedup window 与 current permission 不能倒推历史 truth
