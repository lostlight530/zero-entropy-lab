## 研究摘要

本轮针对 Azure Blob `Copy Blob` 的异步完成语义，研究 HTTP 202、`x-ms-copy-status`、`x-ms-copy-id`、source ETag 与 destination metadata 能否证明 exact downstream effect-set 已合法发生且当前任务完成

实际执行 GitHub 已提交源码的 producer 与单独编写的 primitive verifier，46 个 reset-per-scenario 合成场景、三条路径、138 条决策，44/44 非 COMPLETE 对抗控制、46/46 exact probes、138/138 行复算一致

这不是 Azure Storage 线上实验，全部 copy status、receipts、grant、prior MISS、current witness 均为 authored synthetic facts，真实 Azure 调用与真实外部 effects 为 0

## 研究问题

Azure Copy Blob 返回 HTTP 202 或目的 blob 带有 copy metadata 时，是否足以证明指定 source version 的异步复制已成功、其 copyId 与目标 incarnation 未漂移、后续 A+B 两个非幂等 effects 发生时合法授权且当前受保护 completion predicate 仍成立

当 Copy 仍 pending、abort 后 metadata 存在但目标长度为零、源 ETag 改变、copyId 或目标 identity 漂移、A+A 重复、A+C 替换、历史收据与负向 MISS 冲突或 guard TOCTOU 时，弱路径是否会错误晋升 COMPLETE

## 来源依据

以下文档于 2026-10-28 访问，外部文档只证明各自 API 合同，不证明本轮合成模型或真实云服务故障

- [Microsoft Azure Copy Blob REST API](https://learn.microsoft.com/en-us/rest/api/storageservices/copy-blob) 明确异步复制可以返回 HTTP 202 且 `x-ms-copy-status: pending`，复制可延迟完成，copy ID 用于查询或取消，源 ETag 在复制过程中改变会使复制失败，状态成功与请求接受必须区分
- [Microsoft Abort Copy Blob REST API](https://learn.microsoft.com/en-us/rest/api/storageservices/abort-copy-blob) 说明取消 pending copy 后可留下零长度且保留 metadata 的目的 blob，metadata presence 不是复制完成证明
- [Google Cloud Storage Objects rewrite](https://docs.cloud.google.com/storage/docs/json_api/v1/objects/rewrite) 是独立 publisher 的不同产品对照，其 `done=false` 和 `rewriteToken` 明确区分中间进度与复制完成，但不能作为 Azure 行为的独立实证

Microsoft 两份页面属于同一 publisher，Google 文档仅提供跨产品控制面阶段语义对照

## 可证伪假设

H1 `http_proxy` 仅凭 HTTP 202 判 COMPLETE，在 pending、abort、缺失下游 effects 时产生 model-relative false completion

H2 `copy_status_proxy` 仅凭 copy status success 判 COMPLETE，在 A+A、A+C、错误 copyId、错误历史授权、目的 incarnation 替换或当前 guard drift 时仍产生 false completion

H3 `full_reference` 只有 exact source/target/incarnation/copyId、copy success 与 status proof、source ETag、destination ETag/size/digest、A+B exact receipts、effect-time grants、covered prior HIT 和 protected current membership 全部成立才判 COMPLETE

H4 仅在 covered authoritative MISS、copy authoritative failed、无历史 downstream effect、当前 permission 仍允许且 protected retry boundary 完整时给出 RETRY_ALLOWED，未知结果不能盲重试

只要任何上述缺失、重复、额外 effect、冲突或 TOCTOU 在 full_reference 中被判 COMPLETE，就推翻 H3 的当前实现

## Action-integrity state

- Current permission 仅约束新的 copy/effect retry，不能追溯否定已发生且当时获授权的 effects
- Historical occurrence 由 synthetic exact A+B receipts 表示，HTTP 202、copy status、metadata 和目标文件存在均不替代 downstream receipt
- Historical authorization 由每个 receipt 对应的 synthetic grant identity、有效时间区间和 revocation tick 表示
- Prior-effect evidence 区分 hit、authoritative miss、unknown，合成 MISS 绑定 task/run/attempt/target/incarnation/copyId/effect set、水位和 retention，Azure Copy Blob API 本身不提供这种下游 authoritative journal
- Current completion 需要目的 ETag、size、digest、target incarnation、A+B UID membership、read/guard/commit revision 一致
- Temporal evidence 为单一合成整数 tick 域，不是可信跨服务时钟或真实 happens-before
- Verifier 使用另一套函数重建同一 authored schema，implementation PARTIAL、data source NONE、semantic contract SHARED、authority NONE

## 强反例

- HTTP 202 且 copy status pending，无任何 downstream receipt，HTTP proxy 错误 COMPLETE
- Abort 后 metadata 仍存在而 blob length 为 0，不能把 metadata presence 当作完整复制
- Copy status success，但 receipts 为 A+A、A+C 或额外 C，copy-status proxy 仍错误 COMPLETE
- Copy status success 且目标名称不变，但 source、destination 或 incarnation 发生身份漂移，原始 reference 漏判在同日被实际反例推翻并修复
- 受控 positive receipts 与 covered negative MISS 同时出现，reference 给 EVIDENCE_CONFLICT 而非 COMPLETE
- 历史 effects 已合法完成后 current permission revoked，reference 仍可 COMPLETE；无 receipt 的重试若 current permission revoked 则 BLOCKED
- 完整 source/copy/receipt 正向证据下 current membership same-count swap 或 guard revision drift 仍不能 COMPLETE

## 路径比较

HTTP proxy 只观察传输接受，copy-status proxy 只观察复制阶段，两者均不证明 downstream effect-set 与当前受保护任务谓词

Reference 在共享合成合同内显著减少 model-relative false completion，但多字段验证增加证据需求与人工 reconciliation，不能将 44/46、38/46 分歧解释为真实 Azure 准确率、真实重复率或独立验证强度

三条路径的真实 sink calls、真实 retry 次数与 validated elapsed 均 NOT_APPLICABLE 或 NOT_MEASURED，模型内 RETRY_ALLOWED 不代表真实 Azure 允许无条件重新发起复制

## 暂时结论

状态为 OBSERVATION / PASS_WITH_LIMITS / BOUNDED_MODEL_ONLY

Azure 异步 Copy Blob 的请求接受、复制状态与下游 effect-set completion 是不同的证明命题；受控模型展示弱代理可在身份、授权、成员完整性及受保护 current predicate 缺失时产生 false completion

该结论只在 authored fixture 和已实现 reference 合同内成立，不晋升 CASE 或 NOTES 长期发现，不宣称发现 Azure 服务故障或安全漏洞
