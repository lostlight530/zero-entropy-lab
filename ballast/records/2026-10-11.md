## 研究摘要

One bounded deterministic synthetic experiment compares Actions cancellation and run-attempt metadata with an external effect contract. Twenty scenarios and four paths now yield 80 decisions after same-day strengthening. A Python producer and separately structured Node.js verifier executed locally: 18/18 scenario labels and 72/72 rows agreed. No real workflow, external sink or irreversible effect was executed.

## 研究问题

Can cancellation, a newer attempt or matching receipt count establish exact historically authorized external effects on the correct incarnation and current task completion after cancellation races or incomplete receipt visibility.

## 来源依据

Checked 2026-10-11 Asia/Shanghai.

- [GitHub concurrency](https://docs.github.com/en/actions/how-tos/write-workflows/choose-when-workflows-run/control-workflow-concurrency) documents cancel-in-progress, default pending replacement and optional queue behavior as scheduling controls, not external effect receipts.
- [GitHub cancellation reference](https://docs.github.com/en/actions/reference/workflows-and-actions/workflow-cancellation) describes job condition reevaluation, runner signaling and termination delays, without claiming external effect rollback.
- [GitHub Actions variables](https://docs.github.com/en/actions/reference/workflows-and-actions/variables) defines GITHUB_RUN_ID as stable across reruns and GITHUB_RUN_ATTEMPT as incrementing on rerun. Neither is an external task-effect identity.
- [Stripe idempotent requests](https://docs.stripe.com/api/idempotent_requests) illustrates a distinct external API replay contract and provider-specific retention. Stripe semantics are not assumed for arbitrary Actions sinks.

The three GitHub documents share one publisher lineage. Stripe is a second publisher but supports only the general external-sink boundary, not a GitHub-specific cancellation guarantee.

## 实验设计

Compare cancellation-only, attempt-advanced-only, receipt-count-only and full-integrity paths on identical primitives. The full path is an internal task-contract reference, not an external oracle. It checks incarnation, membership, receipt binding, prior-effect coverage, duplicate and unexpected receipts, effect-time authorization, temporal evidence, missing effects, current permission before new effects and present postcondition. Unknown non-idempotent outcomes are safe-stopped, never retried.

Strong counterexamples include canceled-after-effect versus canceled-before-effect with identical cancellation status, permission revoked after completed effects versus before unfinished effects, and two same-count receipts that duplicate an effect identity. The separately structured verifier shares scenario vocabulary and is not fully semantically independent.

## 暂时结论

BOUNDED_MODEL_SUPPORTED: cancellation state, run identity, attempt identity, historical effect occurrence, historical authorization, current permission, target incarnation, effect-set membership, temporal ordering and current completion are separate. The synthetic reference rejects modeled false completions accepted by weaker metadata-only paths. No GitHub Actions bug, exactly-once guarantee or live recovery guarantee is claimed.

## AGI-scale action-integrity relevance

Long-horizon agents may delegate irreversible actions to CI workers and resume after cancellation, rerun or ownership transfer. A newer attempt is not proof that an earlier effect was absent or authorized. Recovery requires stable external effect identity and independent current-state proof before non-idempotent replay.
