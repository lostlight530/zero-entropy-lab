## 研究摘要

本轮研究的是 Azure Service Bus **发送侧去重被接受但丢弃** 与 **接收侧 PeekLock settlement** 两条独立 transport 状态链是否能够共同证明 downstream A+B 不可逆 effects 的历史发生、effect-time authorization 和当前受保护完成

与 10-27 SQS stale receipt handle、10-29 Cloud Tasks deadline、10-30 Pub/Sub ACK 不同, 本轮专门攻击 Azure Service Bus 的 scheduled/non-scheduled MessageId collision、partition/session dedup identity 和 lock settlement generation, 仅在合成合同内推演, 不冒充 Azure 实际服务调用

## 研究问题

同一个 MessageId 的发送操作返回 accepted, 但因去重窗口内重复而被丢弃, 或者消息 PeekLock settlement 发生 lock loss、旧 generation 回执, 是否可以将 transport signal 当成 downstream exact A+B completion

当旧 attempt 可能存在未纳入查询范围的 attempt 3、query watermark 在 queryAt 之后、receipt 集合相同计数但成员替换、current permission 撤销或 guarded completion 发生 TOCTOU 时, 何时应 COMPLETE、RECONCILE、STOP_UNKNOWN、BLOCKED 或 EVIDENCE_CONFLICT

## 来源依据

2026-10-31 Asia/Shanghai 实际核验的公开来源

- [Microsoft Azure Service Bus duplicate detection](https://learn.microsoft.com/en-us/azure/service-bus-messaging/duplicate-detection) 规定窗口内重复 MessageId 的发送可能返回 accepted 但消息被丢弃, partitioned 实体使用 MessageId+PartitionKey, session 与 partition key 要匹配, scheduled messages 同样参与去重, 默认窗口 10 分钟且可配置

- [Microsoft preventing loss and duplicates](https://learn.microsoft.com/en-us/azure/service-bus-messaging/service-bus-message-loss-and-duplicates) 明确发送侧 duplicate detection 不替代接收侧幂等处理, PeekLock 属于至少一次交付

## 可证伪假设

H1 `send_proxy` 将 accepted 直接视为 COMPLETE, 会在 accepted-but-dropped、无 downstream receipt、partition drift 或过期窗口新 delivery 时产生 model-relative false completion

H2 `settlement_proxy` 将锁已 SETTLED 视为 COMPLETE, 会在 A/B receipt 缺失、effect-time grant 不合法、same-count member replacement 和 protected guard 漂移时产生 model-relative false completion

H3 `full_reference` 仅在 exact task/run/intent/message/partition/session/UID、settlement generation、complete attempt-history、HIT query coverage、exact A+B receipt、effect-time grant、current membership 和 protected commit 同时成立时返回 COMPLETE

H4 有完整历史授权的已发生 effect 在 current permission 撤销后仍可作为历史事实, 但新 effect 的 covered-MISS retry 必须有 current permission、独立于 query 自述的完整 old-attempt coverage、old-worker fence 和幂等或受保护去重

任一已注入的负向边界返回 `COMPLETE` 或未经证明的 `RETRY_ALLOWED` 即推翻 H3/H4 的当前实现, 未建模真实 authority 不纳入已验证范围

## 强反例

- **Accepted-but-dropped scheduled duplicate**: 发送 accepted 不代表本次新消息进入消费, 无 exact effects 且 lock LOST 时 send_proxy 假 COMPLETE, reference RECONCILE
- **Partition/session identity**: 同 MessageId 但 partition 改变或 session 不匹配, send_proxy 和部分 lock proxy 仍 COMPLETE, reference RECONCILE
- **Effect-before-settlement-loss**: 已有 A+B 历史 receipts 但 lock generation 或 delivery settlement 失效, send_proxy 不能证明 delivery settlement
- **Same-count false proof**: A+A 两条 receipts 或 A+C 替代 A+B, 以及当前 membership A+C, 数量不变但 exact set 不满足, reference RECONCILE
- **Covered MISS vs positive receipt**: 查询声明完整 MISS 但仍有精确正向 receipt, reference EVIDENCE_CONFLICT, 不盲目 retry
- **Future watermark / unseen attempt 3**: query watermark 大于 queryAt, 或独立合成 history 声明 attempt 3 而 query 只覆盖 1/2, reference STOP_UNKNOWN
- **Historical authorization separation**: current permission 后撤销但 A+B 在授权有效期内发生仍可 COMPLETE, 授权过期的 B effect 则 BLOCKED
- **TOCTOU**: guard 仅做检查而没有 commit-bound protection, reference RECONCILE

### 同一研究窗口中的参考模型自我纠错

## 路径比较

Send accepted 只提供发送交互结果, broker dedup retention、scheduled collision 和 partition key 属于 transport identity 范围, 不提供 downstream A+B 的历史授权或当前谓词证明

PeekLock Complete/settlement 仅处理 delivery lifecycle, 即使其状态真实也不等价于外部 non-idempotent sink 与 protected task completion

Full reference 增加 identity、effect-time grant、complete historical attempt coverage、query watermark/retention、current member set 与 compare-at-commit, 能在 authored input domain 内安全停止, 但成本是更多 reconciliation 与 UNKNOWN, 也可能共享未建模语义错误

## 暂时结论

本轮只建立一个受控模型观察: Azure Service Bus send-side accepted/dedup 与 receive-side settlement 不能作为 task-level action integrity 的独立替代证据, 尤其不能跨越真实 external effect authority 和 protected current predicate

未验证 Azure 线上行为、真实副作用、跨系统原子性、跨时钟先后或语义独立性, 结论 `BOUNDED_MODEL_ONLY / PARTIAL`, 不升级 CASE 或 NOTES
