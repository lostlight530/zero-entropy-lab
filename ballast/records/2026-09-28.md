## 研究摘要

This Daily studies an occurrence-only action after ambiguous transport. It asks whether a lost response, duplicate event identity, or an occurrence receipt can be promoted into a complete recovery decision. The model keeps historical occurrence, historical effect-time authorization, current permission, target identity and occurrence-only completion separate. No real non-idempotent external effect is executed or blindly retried.

## 研究问题

Can ambiguous transport, duplicate event identity, or a receipt alone establish valid occurrence-only completion, and when is a new effect safe after recovery.

## 来源依据

Checked 2026-09-28.

RFC 9110 Section 9.2.2 states that a client should not automatically retry a request with a non-idempotent method unless it knows the request semantics are actually idempotent or can detect that the original request was never applied.

The CloudEvents specification defines `source + id` as unique for each distinct event and allows a duplicate re-send to retain the same id. That supports duplicate-event identity, but does not by itself prove downstream effect occurrence, historical authorization, current permission, or completion.

The external contracts support only these field and retry semantics. They do not prove the local fixture or a real event-delivery runtime.

## 可证伪假设

H1 transport ambiguity alone is sufficient occurrence evidence.

H2 duplicate event identity alone is sufficient downstream occurrence evidence.

H3 an occurrence receipt alone is sufficient valid completion evidence.

H4 a full-axis recovery contract that keeps prior-effect class, historical authorization, current permission, target identity and occurrence-only completion separate rejects the modeled unsafe retries and false completions.

## 强反例

A lost response leaves prior occurrence UNKNOWN unless stronger evidence covers the original attempt.

The same CloudEvents `source + id` can identify a duplicate event without proving that a downstream non-idempotent effect occurred exactly once.

A receipt HIT can prove an occurrence while historical effect-time authorization remains unproved.

An authoritative historical MISS does not grant current permission for a new effect.

These cases defeat H1-H3 without converting UNKNOWN into MISS or HIT.

## 路径比较

transport-only collapses communication outcome into occurrence evidence and can retry after an unknown result.

event-id-only strengthens duplicate identity but still does not prove downstream occurrence or authorization.

receipt-bound improves historical occurrence classification but can still overclaim valid completion when authorization, target identity or current permission is missing.

full-axis has zero disagreement inside this bounded model because it preserves each decision axis instead of borrowing proof laterally.

## 暂时结论

Observation.

Transport ambiguity is not authoritative occurrence evidence.

Duplicate event identity is not downstream occurrence proof.

Historical occurrence is not historical authorization.

Authoritative MISS is not current retry permission.

Occurrence-only completion needs an occurrence-specific contract; inventing a persistent-state predicate would misrepresent the task semantics.

H4 is supported only inside this controlled model and is not a real distributed-runtime result.

## AGI-scale action-integrity relevance

Long-running autonomous agents can issue irreversible or occurrence-only actions such as send, publish, notify or external dispatch. Recovery after ambiguous transport needs durable effect identity and evidence without converting missing evidence into safe retry. This is an action-integrity requirement, not an AGI capability claim.
