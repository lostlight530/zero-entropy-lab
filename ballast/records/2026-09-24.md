## 研究摘要

本轮继续 09-21 至 09-22 的 recovery chain, 将 authority 从单一 target state扩展到 asynchronous acceptance, exact effect ledger, current completion store 与 current permission四个分离 surface.

RFC 9110明确 202 Accepted只表示 request已被接受处理, processing尚未完成且最终可能不会执行. 因而 receipt acceptance不能被提升为 historical effect HIT或 valid completion.

## 研究问题

在 approval authority, asynchronous receipt authority, effect ledger 与 completion store没有共享事务时, 202 Accepted加 current goal state是否足以判断旧 effect occurrence, current completion与是否允许 retry.

## 来源依据

查询日期 2026-09-24.

- [RFC 9110 Section 15.3.3](https://www.rfc-editor.org/rfc/rfc9110.html#section-15.3.3) 定义 202 Accepted为 accepted for processing, processing尚未完成, request最终可能执行也可能不执行.
- RFC 9110同时说明 202 response intentionally noncommittal, representation应描述当前状态并指向 status monitor.
- 该 HTTP contract只支持 acceptance与completion不能坍缩的语义边界, 不证明本地 modeled effect ledger, completion store或 permission authority对应任何特定生产系统.

## 可证伪假设

- H1: receipt-only路径可把 202 Accepted直接视为 historical HIT与 complete.
- H2: completion-only路径看到 current goal satisfied即可证明原 attempt产生 effect.
- H3: effect-ledger-only路径足以决定完整 recovery, 无需 current completion与 current permission.
- H4: 分离 prior-effect class, current completion与 current permission后, full-axis路径能在本轮模型中避免 blind retry与 false provenance completion.
- H5: current goal由其他 actor满足时, authoritative historical MISS仍保持 MISS, 不能升级为原 attempt HIT.

## 控制条件

固定 receipt为 HTTP 202 accepted, exact operation identity保持不变.

八个场景只改变 prior-effect evidence, current completion predicate与 current retry permission.

规范 recovery decision固定为:

- HIT + completion true -> complete.
- HIT + completion false -> reconcile, 不 blind retry.
- authoritative MISS + completion false + permission true -> retry.
- authoritative MISS + completion false + permission false -> permission-stop.
- authoritative MISS + completion true -> current-goal-only, 不把原 attempt升级为 HIT.
- UNKNOWN + completion false -> safe-stop-unknown.
- UNKNOWN + completion true -> current-goal-only, provenance仍 unknown.

## 强反例

`accepted-pending`中 receipt-only把 202直接判 complete, 但 prior effect仍 UNKNOWN且 current completion false. 这直接推翻 H1.

`accepted-miss-complete-other`中 authoritative ledger明确原 operation MISS, 但 current goal已由其他 actor满足. completion-only把 current state当成原 attempt provenance, 推翻 H2并支持 H5.

`accepted-hit-incomplete`中 exact effect HIT但 current goal未完成. effect-only判 complete, 说明 historical occurrence不能替代 current completion.

`accepted-miss-revoked`中 effect MISS但 current permission已失效. effect-only仍 retry, 说明 occurrence authority不能替代 current execution permission.

## 路径比较

receipt-only把 asynchronous acceptance误当完成与 occurrence, false provenance最严重.

completion-only能看到当前目标, 但不能证明谁产生 effect, 且 completion false时会在 UNKNOWN或 revoked permission下错误 retry.

effect-only能保持 UNKNOWN不重试, 但 HIT不等于 current completion, MISS也不等于 current permission.

full-axis分别读取 prior-effect, current completion与 current permission, 在本轮 modeled contract内 0 disagreement, 同时不把 current-goal-only升级为 historical HIT.

## 暂时结论

状态为观察.

H1, H2, H3被强反例推翻. H4与H5在本轮 modeled boundary内得到支持.

202 Accepted是 receipt/acceptance evidence, 不是 historical effect occurrence proof, 也不是 current completion proof. Current goal satisfied可以支持 current-state判断, 但不能单独重建 original actor provenance. Authoritative MISS只解决旧 effect occurrence, 新 retry仍需要 current permission.

## AGI-scale action-integrity relevance

长期自主 Agent常跨 queue, worker, receipt service, effect sink与 completion store恢复任务. 如果把任一单点 success surface当成全局 truth, 会把 accepted, occurred, authorized, complete与retryable错误坍缩. Cross-service recovery需要显式保留这些 authority axes.
