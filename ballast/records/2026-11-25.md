## 研究摘要

本日研究 S3 Object Lock 的授权组合边界，重点区分 Governance retention bypass、Compliance retention、Legal Hold、精确版本删除权限与历史效果证据

研究没有重复 2026-11-24 的 ETag/current-version 条件删除问题，而是将对象版本级 WORM 锁、双条件 Governance bypass 和独立 Legal Hold 纳入一个可证伪的授权决策模型

实际执行了一个 Node.js CLI synthetic producer 和一个单独编写的 primitive-field verifier，保留 24 个场景、15 个 tamper probes、原始输入、判定结果和运行摘要

## 研究问题

Can an autonomous agent safely decide whether to retry or declare completion for an exact S3 object-version deletion when Governance bypass, Compliance retention, Legal Hold, IAM action permission, prior-effect evidence, historical authorization and current lock revision can diverge

## 来源依据

- [AWS S3 Object Lock](https://docs.aws.amazon.com/AmazonS3/latest/userguide/object-lock.html) accessed 2026-11-25, retention and Legal Hold apply to individual object versions; Legal Hold is independent from retention; protected versions may still receive a new version or delete marker; Compliance mode cannot be bypassed during retention
- [AWS Object Lock considerations](https://docs.aws.amazon.com/AmazonS3/latest/userguide/object-lock-managing.html) accessed 2026-11-25, Governance bypass requires `s3:BypassGovernanceRetention` and an explicit `x-amz-bypass-governance-retention:true` request header; bypass does not remove Legal Hold
- [AWS S3 required permissions](https://docs.aws.amazon.com/AmazonS3/latest/userguide/using-with-s3-policy-actions.html) accessed 2026-11-25, exact version deletion requires `s3:DeleteObjectVersion`; Governance-protected version deletion conditionally requires `s3:BypassGovernanceRetention`
- [MinIO AIStor Object Locking and Immutability](https://docs.min.io/aistor/administration/object-locking-and-immutability/) accessed 2026-11-25, documents per-version WORM lock, delete-marker creation for unversioned delete and specific-version delete refusal under active lock; this is a second publisher and a product-specific contract, not live AWS evidence

AWS's three pages are one publisher identity, not three independent sources; MinIO is a second publisher identity, and its behavior is not treated as proof of AWS runtime behavior

## 可证伪假设

H1 a bypass-permission-only path accepts active Governance deletion without the explicit request header, and may also accept a still-active Legal Hold or Compliance retention

H2 a response-only path can classify a simple delete marker or an identity-mismatched 2xx response as exact-version completion

H3 an authored reference that checks exact version identity, base DeleteObjectVersion permission, both Governance bypass conditions, Legal Hold, Compliance expiry, exact prior-effect scope, historical grant and completion revision will reject those weak inferences while remaining vulnerable to unsupported issuer and atomicity booleans

Falsifier: a provider contract or live controlled request contradicts the documented permission/header/retention distinctions, or a reference decision accepts a malformed exact identity under its declared synthetic contract

## Action-integrity state

Current permission governs a new delete effect only and is not used to invalidate a previously authorized historical effect

Historical occurrence is represented by exact task/run/operation/effect/bucket/key/version/request identity, not by response status alone

Historical effect-time authorization is a separate authored grant interval and actor binding; current IAM permission is not used as historical proof

Prior-effect evidence distinguishes HIT, exact scoped MISS and UNKNOWN; an uncovered watermark, missing version scope or positive/negative conflict does not become an authoritative absence

Current completion requires the exact target version to be absent and the authored read/commit revision to match; a delete marker or same-key later version is not the exact version deletion witness

Legal Hold, Governance retention and Compliance retention are separate lock predicates, while verifier independence remains limited to implementation separation

## 强反例

- Governance bypass permission without the explicit request header is denied by the reference, while the permission-only weak path allows
- Explicit header without Governance bypass permission is denied
- Legal Hold remains blocking even when Governance bypass permission and header are both present
- Active Compliance retention is not bypassed by Governance permission or header
- An unversioned simple DELETE may create a delete marker, but it does not prove permanent deletion of the exact protected version
- A request or receipt bound to another version cannot establish the task's exact target deletion
- An exact negative query without version scope or sufficient applied-through watermark remains STOP_UNKNOWN
- A positive receipt conflicting with an asserted authoritative MISS remains EVIDENCE_CONFLICT
- Current task permission revoked before a new delete prevents retry, while later permission revocation does not retroactively erase a valid historical HIT
- Completion revision drift prevents current completion
- Self-attack: an authored issuer boolean and an authored protected/atomic boolean can still fool the reference, so neither MODEL_COMPLETE nor verifier agreement is a full-integrity proof

## 暂时结论

PARTIAL / EVIDENCE_INSUFFICIENT

Governance bypass is not a single permission bit: the documented request requires both the bypass permission and explicit request marker, and Legal Hold remains an independent blocker; Compliance retention is a separate non-bypassable mode during its active period

A delete marker, 2xx response, same key, receipt count or authored authority boolean cannot be promoted automatically into exact historical version deletion, effect-time authorization or protected current completion proof

The result is a bounded model of documented contract distinctions, not a live provider experiment or a new durable finding

## AGI-scale action-integrity relevance

A long-running agent may hold a stale permission snapshot while an object version's retention or Legal Hold changes, or may confuse hiding an object key with deleting a specific version

The agent needs action-specific permission, lock-mode and Legal Hold state, exact version identity, historical effect proof and current completion evidence as separate contract inputs
