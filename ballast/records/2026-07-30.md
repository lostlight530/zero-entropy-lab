# Ballast 日记录 2026-07-30

类型: 每日专题
主题: 副作用与去重收据之间的双写中断

## 研究问题

非幂等任务需要同时保存真实副作用和去重收据时, 副作用先写、收据先写与单一原子状态提交在中断恢复和同输入重放中会产生什么结果差异.

## 来源依据

查询日期为 2026-07-30.

- [AWS Builders' Library: Making retries safe with idempotent APIs](https://aws.amazon.com/builders-library/making-retries-safe-with-idempotent-APIs/) 为官方工程资料, 明确要求去重标识与相关变更形成 ACID 的全有或全无操作, 否则会出现已记录标识但资源未创建, 或资源已创建但标识未记录. 页面没有显示稳定更新日期.
- [Microsoft Azure Architecture Center: Implement the Transactional Outbox pattern by using Azure Cosmos DB](https://learn.microsoft.com/en-us/azure/architecture/databases/guide/transactional-out-box-cosmos) 为官方架构资料, 描述业务状态提交与事件发布之间发生故障会丢失事件, 并使用事务批次把需要一致可见的状态放入同一提交边界. 页面当前可读取正文但同时显示授权提示, 因而只使用可核对的公开段落.
- [PostgreSQL 16 Transactions](https://www.postgresql.org/docs/16/tutorial-transactions.html) 为官方数据库文档, 将事务定义为由多个步骤组成的全有或全无操作. 该文档只支撑原子提交语义, 不证明跨远端系统的原子性.

AWS 与 Microsoft 独立支持双写间隙的风险和同一提交边界的设计方向, PostgreSQL 补充一般事务语义. 外部资料不证明本地文件替换具备数据库事务或断电持久性.

## 可证伪假设

路径 A 先保存资源, 在保存收据前中断, 恢复器只查收据后重试. 预计产生两个资源, 即使最终存在收据也会被独立验证拒绝.

路径 B 先保存收据, 在创建资源前中断, 恢复器命中收据后返回缓存成功. 预计没有资源, 但浅层完成判断仍为真, 独立验证应将其拒绝.

路径 C 把资源和收据构造成同一状态候选, 在替换前注入中断, 恢复后再一次性替换权威快照. 预计中断前状态不可见, 恢复后恰好一个资源和一个匹配收据, 同输入重放写入 0.

如果路径 A 没有重复资源, 路径 B 没有幽灵成功, 或路径 C 暴露部分状态、无法恢复、验证失败或重放新增写入, 对应假设被推翻.

## 控制条件

- 三条路径使用同一请求标识与同一当前意图.
- 资源记录同时绑定请求标识与当前意图摘要.
- 路径 A 与 B 分别使用隔离的资源文件和收据文件.
- 路径 C 使用单一 JSON 快照, 候选只在完整构造后通过同卷 `os.replace` 变为权威状态.
- 独立验证器运行在另一 Python 进程, 从当前意图重新计算摘要并直接回读最终资源与收据.
- 全部样本位于系统临时目录, 使用 UTF-8 并在退出前清理.

## 实验设计

1. 路径 A 写入第一个资源后注入中断, 不写收据, 再让恢复器因收据缺失执行第二次创建并保存收据.
2. 路径 B 写入指向预期资源的收据后注入中断, 不写资源, 再让恢复器命中收据并返回缓存成功.
3. 路径 C 构造同时包含资源和收据的候选, 在权威替换前注入中断并删除候选, 检查原状态未变.
4. 路径 C 恢复时重新构造候选并一次性替换权威快照, 再执行同输入重放.
5. 独立验证三条最终状态, 要求当前请求恰好一个资源、一个收据、意图摘要一致且收据结果指向该资源.
6. 检查六项机制断言、完整耗时和临时目录清理.

## 原始观测

- 路径 A 首次写入资源后在收据前中断, 恢复时再次创建, 最终调用 2 次、写入 3 次、资源 2 个、收据 1 个.
- 路径 A 的生产路径因收据存在报告完成, 独立验证以 `exact_resource_count_mismatch` 拒绝, 退出状态为 1.
- 路径 B 先写收据后在资源前中断, 恢复器命中缓存成功, 最终调用 1 次、写入 1 次、资源 0 个、收据 1 个.
- 路径 B 的生产路径报告完成, 独立验证以 `exact_resource_count_mismatch` 拒绝, 退出状态为 1.
- 路径 C 第一次候选在替换前中断并清理, 权威状态保持空资源和空收据.
- 路径 C 第二次提交只产生 1 次权威替换, 最终资源 1 个、收据 1 个, 独立验证通过, 退出状态为 0.
- 路径 C 同输入重放写入 0, 权威快照字节不变, 候选残留为 0.
- 六项机制断言全部通过, 有效完成为真, 系统临时目录清理通过.
- 正式实验验证后的有效耗时为 305.212 毫秒.
- 提交前两次复验及重放到最新 `main` 后的复验保持相同资源计数、验证判断、零写入重放与清理结果, 验证后有效耗时分别为 264.321、220.08 和 273.933 毫秒.

首次非提权执行在默认系统临时根创建目录后受到 ACL 拒绝, 未进入机制实验. 该精确残留被清理, 环境失败不计入路径证据.

## 独立验证

`verify_dual_write_atomicity.py` 在独立进程中直接读取分离文件或原子快照, 读取调用时当前意图并重新计算 SHA-256. 它要求相同请求标识恰好对应一个当前意图资源, 收据存在、意图匹配且结果标识指向该唯一资源.

验证器不读取生产器的完成布尔值、中断标签、写入计数或预期验证结果. 独立性限制是生产器与验证器共享 JSON 字段合同、SHA-256 和本地文件事实源.

## 强反例

路径 B 已经存在格式正确且意图摘要匹配的收据, 恢复器无需重试即可返回缓存成功, 操作数量也是三条路径中最低. 但最终资源数量为 0.

这个状态推翻了持久去重收据存在就足以证明任务完成的解释. 收据只有与真实副作用在同一可验证提交边界内一致可见, 或恢复时通过权威结果协调, 才能支持跳过重试.

## 暂时结论

状态为观察.

本次受控实验同时复现了双写间隙的两种对称失败: 副作用可见而收据缺失导致重复创建, 收据可见而副作用缺失导致幽灵成功. 将两者放入单一原子可见状态后, 替换前中断不污染权威状态, 恢复后有效完成且同输入重放零写入.

该结果为当前状态绑定发现增加原子提交边界证据, 但单文件替换机制只出现一次, 不新建候选或长期发现.

## 复验条件

使用真实事务存储、事务 outbox 或支持条件写入的远端服务复验. 分别注入提交确认丢失、进程崩溃、并发恢复者、候选损坏、磁盘写满和断电边界.

当副作用与收据无法共享事务时, 比较可查询副作用协调、outbox、状态机补偿和安全停止. 使用不同实现的验证器攻击共享 JSON 合同与摘要假设.

## 事实分层

### 已验证事实

- 副作用先写路径在收据缺失后的恢复中创建了第二个资源.
- 收据先写路径在资源缺失时仍由生产路径报告缓存成功.
- 独立验证器拒绝两个分离写入反例, 接受一个资源与一个匹配收据的原子快照.
- 原子快照路径在替换前中断后保持旧状态, 恢复后重放写入 0 且没有候选残留.

### 基于证据的推断

- 去重收据不是独立完成证明, 它需要与副作用保持同一一致性边界或在恢复时接受权威协调.
- 较少调用与写入只有在资源和收据关系通过独立验证时才代表有效速度改进.

### 未验证事项

- `os.replace` 在断电、磁盘写缓存、跨卷和网络文件系统中的持久性与原子边界.
- 真实数据库事务、消息 outbox 和跨服务补偿在相同故障位置的表现.
- 多个并发恢复者争用同一请求标识时的隔离行为.

## 指标

- 有效完成: 路径 C 为是, 路径 A 与 B 为否.
- 重放一致与幂等通过: 路径 C 为是, 同输入重放写入 0 且快照不变.
- 中断恢复: 路径 C 在提交前中断后恢复, 路径 A 与 B 恢复错误.
- 假成功: 路径 A 与 B 各 1 次, 独立验证均拦截.
- 重复副作用: 路径 A 多 1 个资源.
- 无效操作: 正式协议内 0.
- 重试次数: 路径 A 1 次, 路径 B 0 次, 路径 C 恢复提交 1 次.
- 人工介入: 正式机制实验内 0.
- 结果质量差异: 路径 A 资源过多, 路径 B 资源缺失, 路径 C 资源与收据一一对应.
- 验证后的有效耗时: 305.212 毫秒.
