# Ballast 日记录 2026-07-31

类型: 每日专题
主题: 超时重试后的旧尝试迟到提交

## 研究问题

第一尝试超过客户端截止后, 第二尝试已经提交当前结果, 第一尝试随后迟到完成时, 无条件提交、只发送取消信号与提交代际围栏会产生什么结果差异.

## 来源依据

查询日期为 2026-07-31.

- [gRPC Deadlines](https://grpc.io/docs/guides/deadlines/) 为官方协议工程文档, 说明客户端超过截止会停止等待并得到 `DEADLINE_EXCEEDED`, 但服务端应用负责停止已经派生的活动. 页面标记最后修改日期为 2025-07-07.
- [gRPC Cancellation](https://grpc.io/docs/guides/cancellation/) 进一步说明库通常不能直接中断应用提供的处理器, 处理器需要协调并周期检查取消. 页面标记最后修改日期为 2024-02-29. 这与 Deadlines 属于同一来源体系, 合并视为一项来源.
- [AWS Builders' Library: Timeouts, retries, and backoff with jitter](https://aws.amazon.com/builders-library/timeouts-retries-and-backoff-with-jitter/) 为官方工程资料, 说明超时或失败不代表副作用没有发生, 带副作用的调用需要幂等设计才能安全重试. 页面当前重定向到 AWS Builder Center, 未显示稳定更新日期.
- [Microsoft Azure Architecture Center: Retry pattern](https://learn.microsoft.com/en-us/azure/architecture/patterns/retry) 为官方架构资料, 说明非幂等操作可能在服务端已完成但响应失败后被再次执行, 并要求用不同故障条件测试重试逻辑与竞态. 页面正文可公开读取, 同时显示授权提示, 因而只使用可核对段落.

gRPC 支撑取消不等于应用处理已经停止, AWS 与 Microsoft 独立支撑超时后副作用状态未知和非幂等重试风险. 这些来源没有规定本实验使用的单调代际实现, 也不证明本地文件模拟等同于真实 RPC.

## 可证伪假设

路径 A 在第一尝试超时后启动第二尝试, 第二尝试先提交第二代结果, 第一尝试再无条件提交第一代结果. 预计客户端看到重试成功, 但最终状态倒退到第一代并被独立验证拒绝.

路径 B 在相同顺序中发送取消信号, 但应用处理器没有在提交点核对取消或所有权. 预计取消信号存在仍不能阻止第一代结果迟到覆盖, 构成强反例.

路径 C 为每次尝试分配单调代际, 第二代提交后第一代只能在代际不小于当前值时提交. 预计第一代迟到提交被拒绝, 最终保持第二代, 独立验证通过且同输入重放写入 0.

如果路径 A 或 B 最终仍为第二代, 或路径 C 接受旧代际、验证失败或重放新增写入, 对应假设被推翻.

## 控制条件

- 三条路径使用同一任务标识、第一代旧输入和第二代当前事实源.
- 事件顺序固定为第一尝试开始、客户端超时、事实源推进、第二尝试提交、第一尝试迟到提交.
- 路径 B 只增加取消信号, 不把信号伪装成处理器已经停止的证明.
- 路径 C 只增加提交点的单调尝试代际比较.
- 独立验证器运行在另一 Python 进程, 直接回读当前事实源与最终结果.
- 全部样本位于系统临时目录, 使用 UTF-8 并在退出前清理.

## 实验设计

1. 第一尝试捕获第一代输入, 注入客户端截止并把权威事实源推进到第二代.
2. 路径 A 先让第二尝试提交第二代结果, 再让第一尝试无条件覆盖.
3. 路径 B 记录取消信号已经发送, 保持应用处理器未在提交点核对的反例, 重复相同覆盖顺序.
4. 路径 C 先接受第二代尝试, 再以当前已接受代际拒绝第一代迟到提交.
5. 独立验证三条最终状态, 要求任务标识、当前代际、载荷和最新已接受尝试一致.
6. 对路径 C 执行同输入重放, 检查写入计数、最终字节与临时清理.

## 原始观测

- 路径 A 的第二尝试先成功, 第一尝试随后被接受, 最终有 2 次结果写入和 2 个已接受提交, 状态从第二代倒退到第一代.
- 路径 A 的客户端保留重试成功判断, 独立验证以 `stale_generation`、`payload_mismatch` 和 `result_not_latest_accepted_epoch` 拒绝, 退出状态为 1.
- 路径 B 已记录取消信号, 但处理器没有在提交点核对, 第一尝试仍覆盖第二代结果, 最终同样有 2 次结果写入并停留在第一代.
- 路径 B 的独立验证以相同三项原因拒绝, 退出状态为 1.
- 路径 C 接受第二代提交 1 次, 第一代迟到提交因代际较旧被拒绝, 最终保持第二代.
- 路径 C 独立验证通过, 退出状态为 0, 同输入重放写入 0 且状态字节不变.
- 五项机制断言全部通过, 有效完成为真, 系统临时目录清理通过.
- 正式实验验证后的有效耗时为 305.958 毫秒.
- 月末审计重放保持相同状态、验证判断与零写入重放, 验证后有效耗时为 214.317 毫秒.
- 同步最新 `main` 后的提交前复验仍保持相同结果, 验证后有效耗时为 262.062 毫秒.

默认临时根和工作副本临时根各发生一次 ACL 拒绝, 两次都在机制实验前停止. 两个精确残留目录完成清理, 环境失败不计入路径证据.

## 独立验证

`verify_late_attempt_fencing.py` 在独立进程中读取当前事实源和最终状态, 要求任务标识一致、结果代际与载荷等于当前事实源, 并要求最终结果的尝试代际等于已接受提交中的最大代际.

验证器不读取客户端重试成功、取消信号、故障标签、生产路径完成判断或预期验证结果. 独立性限制是实验编排器与验证器共享 JSON 字段合同、本地文件事实源和代际比较定义.

## 强反例

路径 B 已经向旧尝试发送取消信号, 第二尝试也已经成功提交当前结果. 如果只观察客户端和取消事件, 任务具有两个正向信号.

应用处理器没有在副作用提交点重新核对取消或所有权, 因而第一尝试仍把当前结果覆盖为旧结果. 取消是停止意图, 不是停止完成证明, 也不是提交权限.

## 路径比较

| 路径 | 客户端看到重试成功 | 取消信号 | 接受提交 | 结果写入 | 最终代际 | 独立验证 | 重放写入 |
| --- | --- | --- | ---: | ---: | ---: | --- | ---: |
| 无条件迟到提交 | 是 | 否 | 2 | 2 | 1 | 拒绝 | 未执行 |
| 只有取消信号 | 是 | 是 | 2 | 2 | 1 | 拒绝 | 未执行 |
| 提交代际围栏 | 是 | 可选 | 1 | 1 | 2 | 通过 | 0 |

路径 A 与 B 没有额外协调操作, 但都破坏当前结果. 路径 C 增加一次提交代际判断, 减少一次无效结果写入并保持结果质量. 本实验未分别计量三条路径的耗时, 不能比较绝对速度.

## 暂时结论

状态为观察.

本次受控事件交错中, 客户端超时和取消信号都不能证明旧尝试已经失去提交能力. 第二尝试成功后, 无条件接受旧尝试会让最终状态倒退, 而提交点的单调代际围栏拒绝迟到结果并保持零写入重放.

该结果为当前状态绑定发现增加超时后迟到提交证据, 但代际围栏只在确定性本地事件顺序中出现一次, 不新建候选或长期发现.

## 事实分层

### 已验证事实

- 两条无提交围栏路径都在第二代成功后接受第一代迟到提交, 最终状态倒退.
- 取消信号存在没有阻止忽略提交点检查的处理器写入旧结果.
- 独立验证器拒绝两条第一代最终状态, 接受被代际围栏保护的第二代状态.
- 围栏路径拒绝旧代际, 同输入重放写入 0 且临时目录完成清理.

### 基于证据的推断

- 客户端等待结束、取消已发送和执行副作用已经停止是三个不同状态, 不能相互替代.
- 重试接管需要在副作用提交点核对当前提交权限, 只在开始阶段检查不足以阻止迟到覆盖.

### 未验证事项

- 真实网络中的取消传播延迟、处理器终止和响应乱序.
- 并发线程、数据库条件更新与消息队列提交中的原子边界.
- 当前尝试失败而旧结果仍有业务价值时的安全接纳规则.

## 指标

- 有效完成: 路径 C 为是, 路径 A 与 B 为否.
- 重放一致与幂等通过: 路径 C 为是, 同输入重放写入 0.
- 中断恢复: 路径 C 在超时接管后保持当前结果.
- 假成功: 路径 A 与 B 各 1 次, 客户端重试成功但最终结果过期.
- 无效操作: 路径 A 与 B 各接受 1 次迟到旧写入, 路径 C 拒绝该写入.
- 重试次数: 三条路径各 1 次.
- 人工介入: 正式机制实验内 0.
- 结果质量差异: 路径 A 与 B 为第一代过期结果, 路径 C 为第二代当前结果.
- 验证后的有效耗时: 305.958 毫秒.
