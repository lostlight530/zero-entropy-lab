## 研究摘要

This Daily tests whether Kubernetes watch progress evidence can be promoted into proof of membership-complete current state when history can expire, bookmarks are discretionary, and a client may need to relist after 410 Gone.

The bounded fixture keeps watch progress, snapshot consistency, exact member incarnation, current permission, historical effect evidence and task completion separate.

No live Kubernetes mutation or non-idempotent external effect is executed.

## 研究问题

Can a resourceVersion, observed watch event or BOOKMARK prove a membership-complete current task state after history loss, relist, authority drift or target reincarnation.

## 来源依据

Checked 2026-10-08 against current Kubernetes API Concepts documentation.

[Kubernetes API Concepts](https://kubernetes.io/docs/reference/using-api/api-concepts/) states that list plus watch can track changes from a collection resourceVersion, that old resource versions can become unavailable with 410 Gone, and that clients must recover by rebuilding state from a fresh get or list before watching from the returned resourceVersion.

The same contract states that BOOKMARK marks progress through a resourceVersion but is not guaranteed to arrive at any particular interval, or at all when requested.

Chunked list continuation preserves a consistent collection snapshot across pages, while a resourceVersion on an individual object records that object's last update rather than proving how current the object was when served.

These source facts constrain API observation semantics only. They do not prove this bounded fixture or a live cluster result.

## 可证伪假设

H1 an observed BOOKMARK is sufficient to prove current membership-complete task state.

H2 a last-seen resourceVersion remains sufficient completion evidence after 410 Gone and local history loss.

H3 a successful fresh relist alone proves completion even if current permission, exact member incarnation or post-list changes are unresolved.

H4 separating snapshot completeness, watch continuity, exact incarnation, current permission, prior-effect evidence and task-defined completion rejects the modeled false completions.

## 暂时结论

Watch progress is evidence about observed API history, not a universal completion receipt.

A consistent relist repairs one evidence gap after history loss, but completion still requires coverage from that snapshot through the task-defined verification boundary.

H4 is supported only by this bounded model.

## AGI-scale action-integrity relevance

Long-running agents commonly maintain local mirrors, event cursors and resumable state across tools.

A cursor or progress marker can prove how far one observation channel advanced without proving that the task's current membership, authority and external effects are complete.

Durable runtimes should therefore distinguish observation continuity from protected completion.
