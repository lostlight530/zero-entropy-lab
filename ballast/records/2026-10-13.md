## 研究摘要

One bounded synthetic research window tested whether an OAuth token exchange, a positive preflight introspection response or an actor-chain claim proves delegated effect-time authorization and task-defined completion. Thirty distinct primitive scenarios, four decision paths and 120 recorded decisions were evaluated in a JavaScript isolate. A separate predicate reconstruction agreed with all 30 frozen scenario labels, and 12 metamorphic assertions passed. No real token, protected resource, external effect or non-idempotent retry was used.

## 研究问题

When a planner delegates an action to an executor through token exchange, can successful issuance, preflight token activity or a correctly shaped actor history establish that an exact effect was authorized at its commit boundary, occurred on the correct target incarnation and still satisfies current task semantics.

## 来源依据

Official sources inspected 2026-10-13 Asia/Shanghai:

- [IETF RFC 8693, sections 1.1 and 4.1/4.4](https://datatracker.ietf.org/doc/rfc8693/) distinguishes delegation from impersonation, expresses current actor identity through `act`, treats nested prior actors as informational for token-consumer access control, and describes `may_act` as a potential token-exchange authorization input. It does not specify this task's sink policy, receipt semantics or protected commit.
- [IETF RFC 7662, sections 2.2 and 4](https://www.rfc-editor.org/info/rfc7662/) defines token introspection and warns that cached activity can become stale after revocation. `active` is contextual, not an effect receipt.
- [IETF RFC 7009, section 2.2 and security considerations](https://datatracker.ietf.org/doc/rfc7009/) defines revocation and notes possible propagation delay. Revocation now does not independently establish what an earlier effect did.
- [Microsoft Entra Agent ID OBO documentation](https://learn.microsoft.com/en-us/entra/agent-id/agent-on-behalf-of-oauth-flow) describes a concrete agent identity and user-token on-behalf-of exchange with delegated permissions and consent. This is a separate publisher and implementation-specific example, not evidence that Microsoft OBO is identical to RFC 8693 or that a sink effect completed.

The three RFCs share the IETF publisher lineage. Microsoft provides a second independent publisher only for its documented OBO architecture. None of these sources supplies live Ballast runtime evidence.

## 实验设计

Four paths evaluate the same immutable primitives:

1. `exchange_only`: issued-exchange signal as a completion proxy.
2. `preflight_introspection_only`: cached/preflight active signal as a completion proxy.
3. `actor_trail_only`: actor-chain presence as a completion proxy.
4. `full_integrity`: bounded task-contract reference, with separate rules for existing historical effects and permission to produce unfinished new effects.

Fault injections include delegated authority revocation between preflight and effect, stale introspection, wrong current actor/subject/audience/scope, `may_act` without an issued exchange, changed informational prior actor, current revocation after historically valid effects, uncovered negative lookup, unknown old effect, conflicting receipt and MISS, wrong receipt actor, duplicate/extra effect, target reincarnation, incomplete membership, missing temporal witness and postcondition reversal. The model never executes a retry. An UNKNOWN non-idempotent effect remains safe-stopped.

## 强反例

The same positive preflight introspection and issued exchange appear in the valid baseline and in the revoked-before-new-effect case; only the latter lacks current effect-time authority. Conversely, a later revoked token and a changed current actor do not retroactively invalidate independently proven earlier authorized effects. An `act` history with a different nested prior actor must not automatically fail token-consumer access control under RFC 8693, whereas a receipt attributed to the wrong current effect actor violates this modeled task contract. A covered MISS with positive receipts is an evidence conflict, not permission to retry. A historical HIT with no member-level receipts remains UNKNOWN for exact task completion.

## AGI-scale action-integrity relevance

Delegated long-horizon agents may hand work across planner, executor, STS, resource server, effect sink and receipt authority. Token exchange and identity lineage answer who may act in a specified context, not whether an irreversible effect happened, was authorized at its actual boundary or remains task-complete. Recovery requires claim-specific evidence and must preserve UNKNOWN without blind replay.
