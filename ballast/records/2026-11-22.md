## 研究摘要

One falsifiable bounded synthetic study tests how GitHub Actions reruns preserve the run ID while increasing run attempt, separating orchestrator context identity and original actor authority from actual external effect occurrence, effect-time authorization and current completion

## 研究问题

Can an unchanged GitHub Actions workflow run ID, an increased run attempt, or job success justify skipping or replaying a task-defined non-idempotent external effect without exact prior effect evidence, current permission and protected completion evidence

## 来源依据

- [GitHub Actions context reference](https://docs.github.com/en/actions/reference/workflows-and-actions/contexts) accessed 2026-11-22, github.run_id does not change on re-run, github.run_attempt increases, github.actor and github.triggering_actor can differ
- [GitHub workflow re-run contract](https://docs.github.com/en/actions/how-tos/manage-workflow-runs/re-run-workflows-and-jobs) accessed 2026-11-22, re-runs use original actor privileges, original GITHUB_SHA and GITHUB_REF; selected job reruns may also rerun dependencies and reuse outputs of jobs not included in the rerun
- [AWS S3 conditional writes](https://docs.aws.amazon.com/AmazonS3/latest/userguide/conditional-writes.html) accessed 2026-11-22, If-None-Match and If-Match are scoped conditional object writes, including documented 412 and concurrent 409 boundaries, not external publish-and-notify effect-set proof
- GitHub and AWS are different publisher identities, but independent vendor contracts are not independent witnesses of authored fixtures or proof of actual cross-service effects

## 可证伪假设

H1 stable run-ID-only SKIP hides changed operation, target or membership, while attempt-number-only RETRY may duplicate an already occurring business effect
H2 modeled exact prior receipt or complete negative query, separate current permission and protected completion/fence reduce unsupported decisions within the authored contract
H3 current rerunner identity does not determine original GitHub workflow actor privilege, and neither actor proves a separately managed effect sink authorization
H4 verifier agreement under shared fixtures and assumed issuer/fence booleans cannot establish external effect truth
Falsifiers include a reference model accepting a stale member or a false MISS, reference/verifier disagreement under malformed primitive facts, or a live independent sink counterexample

## Action-integrity state

Current permission governs only prospective writes and includes current credential, approval, owner and modeled original-actor context
Historical occurrence is represented by individually scoped positive receipts, not by workflow/run status or job-success output
Historical effect-time authorization is per receipt, not deduced from current actor or current authorization
Prior-effect MISS is qualified only for exact business effect-set, all modeled known attempts, correct scope, applied-through watermark and retention
Current completion is a separate exact member, target and revision predicate, temporal ordering and verifier independence remain limited
The authored run attempt list and issuer bits do not constitute live authoritative history or signed evidence
