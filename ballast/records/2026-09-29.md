## 研究摘要

This Daily tests whether fresh reads, a stable snapshot, or merely selecting a Serializable mode can prove valid completion when current authority, target incarnation and dynamic membership may change concurrently.

The full-axis model treats successful protected commit as necessary but still requires the predicate projection itself to include every relevant authorization, target and membership dependency.

No real external non-idempotent effect is executed or blindly retried.

## 研究问题

Can reread freshness, stable snapshot, or a Serializable label alone prove current completion when authority and membership can drift before commit.

## 来源依据

Checked 2026-09-29.

PostgreSQL transaction-isolation documentation states that successive Read Committed statements can observe different committed states, Repeatable Read provides a stable transaction snapshot but can still permit serialization anomalies, and Serializable transactions can be aborted with serialization failure.

The PostgreSQL documentation also states that data read in a Serializable transaction generally must not be treated as valid if that transaction later aborts. This supports the boundary that selecting Serializable is not itself completion evidence; the relevant transaction must successfully commit.

Kubernetes API concepts state that list plus resourceVersion/watch can track collection changes without missing retained events, while an expired history can require 410 Gone recovery by relist. This supports membership-freshness semantics only and does not prove transaction atomicity or authorization validity.

These external contracts do not prove the local fixture or a real PostgreSQL/Kubernetes integration.

## 可证伪假设

H1 a fresh reread immediately before completion is sufficient.

H2 a stable snapshot alone is sufficient.

H3 declaring Serializable is sufficient even if the transaction aborts or the protected predicate omits a real authority dependency.

H4 a successful protected commit whose predicate covers current permission, relevant authority dependencies, target incarnation, membership witness and prior-effect class rejects the modeled false completions.

## 控制条件

Eight scenarios vary current permission, dynamic membership, target incarnation, authority-projection completeness, transaction commit outcome, prior-effect class and historical authorization.

Four recovery paths are reread-only, snapshot-only, serializable-label and protected-commit.

No path may convert prior UNKNOWN into authoritative MISS. Historical HIT remains separate from historical authorization. Current permission is checked only for a new effect or completion transition that requires current authority.

## 实验设计

## 路径比较

reread-only reduces the stale window but leaves authority, membership and commit TOCTOU.

snapshot-only gives coherent reads but does not make the snapshot current at a later completion boundary.

serializable-label catches modeled target and membership inconsistency, but still false-completes when permission changes, the authority projection is incomplete, or the transaction aborts and its result is nevertheless used.

protected-commit has zero disagreement inside this bounded model because completion is accepted only after the relevant predicate is complete and the protected transaction successfully commits.

## 暂时结论

Observation.

Freshness is not atomicity.

Stable snapshot is not protected completion.

Serializable mode is not successful commit.

Successful commit is not sufficient when the predicate projection omits a real authorization or semantic dependency.

Historical occurrence remains separate from historical authorization and current permission.

H4 is supported only inside this controlled model and is not a real database/controller runtime result.

## AGI-scale action-integrity relevance

Long-running autonomous agents can make decisions over dynamic target sets and delegated authority while state changes concurrently across services.

A strong completion signal therefore needs both a protected decision boundary and a dependency-complete predicate. Transaction machinery can protect the wrong contract perfectly if the contract itself omitted an authority or membership dependency.

This is an action-integrity requirement, not an AGI capability claim.
